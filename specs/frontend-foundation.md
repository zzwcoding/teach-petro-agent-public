# 前端底座设计（真实开发轨）

> 版本：v0.1（2026-09-29）· 性质：**工程裁决册**——前端真实化的横切设计，与 21 册 API 合同配套消费。
> 依据：ADR-0003（技术选型）/ 00 册 §3 错误包·§4 分页信封·§5 异步任务模式·§6 SSE 规范·§9 权限模型总纲 / prototype 现状（React18+antd5+Vite，22 页面组件，无路由库/无状态库/单文件构建）。
> Owner 裁决（2026-09-29）：**改现有原型、双树共存、边做边比**——不新建底座搬家，不全做完再重构。

## 1. 总决与理由

在现有 `prototype/app/` 工程上补底座：落地页占原 hash 路径（`#/A1`），原型页整体挪到 `#/proto/*`，同一份菜单并列、原型页带"原型"角标，点一下即对比 mock 与真 API 行为差异。

- **零搬迁**：22 个页面组件全部复用；
- **对比体验最好**：同一 shell/同一菜单，胜开两个服务两个端口；
- **重构摊销为零**：底座先行→逐页落地（切数据源）→阶段全做完原型树整体删除，不存在期末大重构；
- prototype 归真实开发轨（V2-page-spec 产品化批持续修改中），改它不违 ADR-0005 设计轨冻结。

## 2. 底座五件

### 2.1 请求层 `api/client`（不引 axios，fetch 封装）

- baseURL 按环境配置（dev 走 vite proxy → FastAPI，默认 :8000）；
- 请求拦截：注入 `X-Dev-User` 身份桩头（00 册 §2；生产 OAuth2.0 换 token 注入，切换时点未拍板）；
- 响应统一解包：错误包 `code/message/detail/trace_id`（00 册 §3）、分页计数信封（00 册 §4）、snake_case→camel 约定按各册 DTO 兑现；
- 状态语义集中处理：401/403 兜底跳提示、409 重入、422 业务拒绝话术；
- `useTaskPolling(taskId)` 通用 hook：202 受理→轮询→终态，承载 00 册 §5 的 11 处合同先例（产物任务/演练/试运行/扫库同构）。

### 2.2 SSE 客户端 `api/sse`

- 原生 EventSource 封装（不引库）：19 类事件帧分发（A1 会话域合同值，00 册 §6 不收编帧集）、`Last-Event-ID` 断线续传（00 册 §6 三收场）、澄清/审批 interrupt→resume 回流；
- 每页面只订自己关心的帧类型，信封与 `done/error/replay_truncated` 三帧语义全通道复用。

### 2.3 轻量全局态（zustand，新增唯一前端依赖）

- 三槽起步：当前角色（接 `roles.js` 唯一真源）、语义层当前版本徽标（`semantic.current`，D3 页头策略徽标同源）、会话列表缓存（A1 预留）；
- 页面内状态维持 `useState` 不动（303 处不迁移）。

### 2.4 全局组件库 `components/`

从各页抽取跨页同构件，**原型页与落地页共用**（对比时视觉一致，差异只来自数据真假）：

| 组件 | 合同形状来源 |
|---|---|
| Artifact 产物卡 | A1 端点 7/8（kind/四步/current_step/预签名直链） |
| Voucher 取货凭证卡 | A1/F1 句柄四字段（artifact_id/download_url/total_rows/expires_at） |
| 答案卡 + cN 引用展开回跳 | A1/B2（引用别名 fail-closed） |
| 解释链五要素 | A1/F13（血缘段五件套） |
| 四态徽标（过/拦下/不涉及/未跑） | C3 合同常量 |
| 审批抽屉（interrupt 同款） | A1/A3/C2 双入口单源 |

### 2.5 工程形态

- 去 `vite-plugin-singlefile`，恢复正常 dev/build + vite proxy；原型页面透明无感；
- 前端 eslint 进 CI，与后端四门禁并列（阶段 0 起）；
- **不迁 TS**（裁决）：jsx 存量 22 页迁移成本高、收益低，eslint 兜底；后续新写横切层（client/sse/store）用 JSDoc 注解。

## 3. 权限面

菜单级角色过滤沿用 `roles.js`；按钮级做 401/403 兜底（无权即禁），对齐 00 册 §9 权限模型总纲；不做前端硬编码权限矩阵（真源在服务端）。

## 4. 双树共存结构

```
落地树（真 API，#/A1 …）原型树（mock，#/proto/A1 …）
   └─ 全部走 api/client        └─ 数据自包含（现组件内 mock 不动）
菜单同列：落地页按阶段点亮；原型页常显带「原型」角标
对比：同 shell 同菜单，一键切树
退役：全部阶段验收后原型树整体删除
```

## 5. 阶段落位

| 阶段 | 前端干什么 |
|---|---|
| 0 地基 | 底座五件全建 + D1 页面落地（首个接真 API 的页面）+ eslint 进 CI |
| 1–4 | 每阶段落地页＝切数据源到 api/client + 按需抽组件进库；原型树保留作对照 |
| 收官 | 原型树删除，菜单收敛 |
