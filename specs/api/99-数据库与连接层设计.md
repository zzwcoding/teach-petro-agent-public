### 1.2 主键与标识（两族并存）

- **业务标识主键**（默认）：合同冻结 id 形态的表，`id text primary key` 直装单号族（`RT-20260929-01`/`QT-20260928-01`/`#PP-0394`）或机器短 id 族（`run-`/`task-`/`lib-`/`sess-`/`msg-`）。单号族前缀一经立册冻结不回收复用（00 §1.5）；id 列 UNIQUE 约束天然承载。
- **整数注册序主键例外**：语义台账四账（C1 合同 id 为整数注册序——terms 1–11/metrics 1–15/objects/relations/whitelist）按合同值落 `id int` 主键；行版本随 `sem_ledger_revision` 共享轴（§2.8）。
- **序列主键例外**（追加型/无业务标识表）：`id bigserial`——事件帧类追加表不适用（本设计 SSE 帧不落库，见 §1.5）；流转/审计/版本子表用**复合键**承载序（如 `proposal_flow_log(proposal_id, seq)`、`kb_fragment_version(fragment_id, v)`）——序即合同语义（v1 永存、流转追加）。
- **单号发生器**：`#PP-NNNN`/`RT-YYYYMMDD-NN` 等同日序/流水序由服务端发号（序列表或 `max+1` 于事务内行锁）——发号实现挂开放问题 7，表结构只落 UNIQUE 约束兜底。
- **序号不复用**：E1 考题 id `E1-NN`「服务端序列递增、删除后不复用」（E1 常量 17）——服务端发号器保证，非 DB 列约束。

### 1.3 时间与审计列

- 时间列一律 **`timestamp`（无时区）**，值由 `infra.clock` 产出东八区本地时间（B14 禁散用 `datetime.now()`）；不带时区后缀（00 §1.4 合同值）。**展示串时间不入库**：A3 `outcome.text`/E3 `finishedAt:"…（人工）"` 等含后缀的展示串按 R2 结构化拆列（机器列落库、后缀读侧拼装）——E3 拆 `finished_at`＋`trigger_way` 两列（见 §5 出入 3）。合同 DTO 的 `time` 列（A3 提出/E1 发起/E2 任务等）落**同名机器 timestamp 列**、读侧拼「YYYY-MM-DD HH:mm」展示串——列名照抄合同 DTO 保序列化零映射，非展示串入库。
- `expired`（C1 术语届满 flag）**不落列**：服务端按 `expires_at` 到日现算（F60 机器判；C1 mock 更正项⑧同款）——免每日刷新任务。
- 审计四族列形照抄不收编：A3 `when/who/agent/what`、B1 `time/who/action/target`、D3 `time/who/action/digest`、C2 `time/step/detail`——四种子表/列组各归各表（R10）。

### 1.4 枚举落表策略（裁决）

**裁决：合同冻结的枚举一律用列内 `CHECK (col IN (...))` 约束承载；不用 PG 原生 `enum` 类型，不为枚举建字典表。**

| 方案 | 处置 | 理由 |
|---|---|---|
| PG `enum` 类型 | **不用** | 迁移增删值需 `ALTER TYPE`（Alembic 处理繁琐）；金仓兼容模式的 enum 支持属方言差异区（F11 踩坑素材），设计演绎不踩；R4 状态族「各域枚举为合同值保留、不收编」——enum 类型把值域钉死在类型层，跨域对账更难 |
| 字典表 | **不用** | 合同枚举是**冻结常量**不是运营数据（「合同值不可改，变更走合同变更记录」）——字典表会诱导运营端改值，绕过合同演进纪律；且 20+ 枚举 × 字典表＝20+ 张无业务消费方的表 |
| **CHECK 约束** | **采用** | 值域进 DDL＝合同值进版本库；违约即数据库层报错，与「非法迁移 409 由领域层裁决」分工明确（DB 防非法值、领域防非法迁移）；变更＝一次 Alembic 迁移＋合同变更记录，两处留痕同构 |
| 开放值域不约束 | 状态机枚举外的开放值域（B5 节点 `type`＝按库 ExtractConfig 投影、D5 `type` 值域「随场景类型扩展不封闭」、citation `kind`、任务 `type`）**不落 CHECK**，只落列 | 合同明示不封闭的值域不冻结 |

### 1.5 JSONB 使用边界（逐处裁决）

**判据三问**（任一答「是」则拆子表/拆列，否则 JSONB）：①需要按其内部字段查询/索引/JOIN 吗？②子项需要独立寻址/独立约束/独立版本吗？③形状会按面/按目标变体到需要逐项校验吗？

### 1.6 软删除与版本化

- **不设统一软删除列（deleted_at）**——合同语义用状态承载：FAQ 停用三态（`serve/negative/disabled`）、变动单 `withdrawn`、API Key `revoked`、质检规则 `enabled=false`（「停用＝任务跳过不删」）、bans 下线备查资产照常可读。物理删除仅限合同明示处：E1 删题（「任务结果为快照不级联删除」）、FAQ 合并被并入条目删除、变体删除、判分设置无删除。
- **版本化三处半**：`kb_fragment_version`（v1 不可变＋乐观锁）、`sem_ledger_revision`（行版本轴＋`sem_version` 全量版本轴，**两轴显式分离**——C2 对账 8）、`retrieval_config_version`（生效指针）——以上 append-only 子表＋当前指针；**`wiki_page_version` 随 B4 v0.4 撤除**（Owner 2026-10-04 拍板"版本历史直接去掉"——覆盖当前版语义，`current_version`＝重建计数，详见 §2.7 留档行）。
- **审计只读追加、不可关闭**（00 §8.2）：留痕子表无 UPDATE/DELETE 通路（连接层只读会话守卫＋模块边界双保险）。

### 1.7 金仓兼容注意（PG 方言红线内）

1. 不用 PG 特有扩展：`pgcrypto`（SM4/SM3 由 `infra.crypto` 应用层实现，DB 只存密文/摘要列——与 D3「密文存储在服务端」同构）、物化视图（聚合刷新走 `infra.scheduler`）、全文检索扩展（BM25/关键词路落法已收口＝应用层 BM25——开放问题 5 于 G-07 收口，见 §6）。**向量索引例外＝pgvector 采用（ADR-0003 裁决 1）**：开发 PostgreSQL 直用；金仓生产侧以等价插件交付期验证（遗留验证项，不阻塞开发——§2.5 `kb_fragment.embedding`）。
2. JSONB、CHECK、部分索引、表达式索引（如 `lower(question_norm)`）、数组类型（`numeric[3]`/`smallint[4]`——E1 三维评分/E3 四维体检）、`bigserial`/`IDENTITY` 属金仓兼容面内可用集；**每个 Alembic 迁移在金仓基线上做近似验证**是实施批义务（initdb 期兼容模式固化——00 §11）。
3. 摘要列（`audit_log.digest`＝SM3、`api_key.fingerprint`）由应用层写入，不依赖 DB 函数——跨库一致。
4. 时区：列一律 `timestamp` 无时区；禁止 `timestamptz`（避免金仓/PG 时区规则差异进入设计演绎）。

### 1.8 任务表通用形态（不建统一任务总表）

00 §5 的 10 处异步任务先例落表为**各域任务表**（`kb_ingest_task`/`chat_artifact_task`/`faq_scan_task`/`quality_task`/`eval_run`/`checkup_run`/`pipeline_run`/`gateway_drill_run`/`sandbox_run`——原列 `retrieval_test_run` 随 D2 v0.2 检索试跑端点撤除移除，2026-10-01），共享列族：`id`（任务号族）、`status`（**域内枚举照抄 R4**：双态 `running|done`、B1 四态含 `failed/stuck`、产物五态）、`nodes jsonb`＋`current_step`/`stop_at`、`result/reason`、`started_at/finished_at`。**不建统一 task 总表**：①R4「新任务域默认双态、不收编」——统一表强制收编枚举违合同；②终态落痕归各域聚合（「任务历史累积保留」是各域合同义务），跨域写统一表即跨模块直写他模块表（违 §3 边界）。`infra.queue` 骨架只管受理 202/重入 409/stuck 巡检的执行语义，持久化在各域表。

## 4. 统一数据表连接层设计（infra.db）

### 4.1 定位与边界

- **全平台唯一 DB 出口**：边界规则 B3「禁止任何模块绕过 `infra.db` 直连数据库驱动」的结构化对应——psycopg/金仓驱动只在本模块 import；B16「infra 禁 import domains/api」——本模块只依赖 stdlib 与 SQLAlchemy——**ORM 已定型 SQLAlchemy 2.0（ADR-0003 裁决 3）**：接缝在 `ConnectionManager` 的引擎与会话工厂（测试替身/部署配置注入位，不再保留「替换持久化方案」悬置）。
- **多数据库角色路由**：`primary`（平台主库：开发 PostgreSQL／生产金仓——双库切换唯一缝）、`replica`（只读副本，**预留**——现回落 primary）、`midplatform`（中台源 8 表只读路由——映射卡取行/质检扫描专用，强制只读）。D5 健康四灯的库灯＝`primary` 探活（本环境主库——开发为 PostgreSQL、生产为金仓；演示页双库灯并列为部署全景照抄，另一库不经本进程连接）；Redis/MinIO 归各自 adapter，中台源连接是否入健康带挂开放问题 1。
- **事务语义**：`transaction()` 上下文管理器支持嵌套（内层 SAVEPOINT）——governance 批准事务七步①②⑥⑦ 同事务、③④⑤ 生效后副作用的形状直接可用。
- **行级权限注入点**：连接层不认识 security（不 import），只提供谓词装配执行点 `with_row_filter(stmt, predicates)`——`security.row_filter()` 产出谓词、调用方（wells/问数链/仓储基类）注入，mandatory filter「WHERE 由权限层拼接，不靠模型自觉」（00 §9.3）。
- **审计钩子的分工**：连接层只做**慢查询日志与 SQL 计时**（工程观测）；业务审计四元组一律走 `security.audit` 与各聚合内嵌留痕（B12）——连接层绝不自动写业务审计表，避免第三套审计通道。
- **测试替身策略**：一切消费方只依赖 `ConnectionManager` 的三个公开面（`session()/transaction()/readonly()`）＋`Repository` 基类；单测注入 `FakeConnectionManager`（内存 SQLite 或假会话），seam 收敛在一处构造函数。

```python
"""infra.db —— Petro-Agent 统一数据表连接层（全平台唯一 DB 出口）。

定位与边界（specs/api/98 §4/§6）：
- B3：任何模块禁止绕过本模块直连数据库驱动（psycopg/金仓驱动只在此 import）。
- B16：本模块禁止 import app.domains / app.api（依赖单向向下）。
- 双库：开发 PostgreSQL / 生产金仓（金仓 ≈ PostgreSQL 方言，00 §11）——
  驱动差异收敛在 DRIVER_REGISTRY 一处；金仓驱动落位批只改注册表。

  一律经 security.audit 与各聚合内嵌留痕（B12/R10），本层不写业务表。
- 测试替身：消费方只依赖 ConnectionManager 与 Repository 基类；
  单测以 FakeConnectionManager（内存库/假会话）注入构造函数。

ORM 声明：SQLAlchemy 2.0 定型（ADR-0003 裁决 3）——Mapped[]/select()/
begin_nested() 2.0 风格编写；接缝仍在 ConnectionManager（引擎/会话工厂，
供测试替身与部署配置注入）；领域层不得出现本模块之外的任何驱动符号。
"""
from __future__ import annotations

    Iterator,

# 双驱动适配 seam：金仓驱动名在驱动落位批补齐（占位不改结构）。
# 金仓兼容模式在 initdb 期一次性固化（00 §11）；方言近似验证是实施批义务。
DRIVER_REGISTRY: dict[str, str] = {
    "postgresql": "postgresql+psycopg",
    # placeholder —— 金仓 KingbaseES ≈ PostgreSQL 方言（00 §11）；
    # 官方驱动落位批只改本注册表（结构不动）。
    "kingbase": "kingbase+kb",

@dataclass(frozen=True)
class DatabaseSpec:
    """单个数据库角色的连接规格（config.yaml 装载，infra.config 供给）。"""

    name: str
    role: DatabaseRole
    driver: str                    # DRIVER_REGISTRY 的 key
    host: str
    port: int
    database: str
    user: str
    password: str                  # 部署配置注入；SM4 字段级加密见 EncryptedField
    pool_size: int = 10
    max_overflow: int = 5
    pool_recycle_seconds: int = 1800
    slow_query_ms: int = 800       # 慢查询阈值（工程日志，非业务审计）
    readonly: bool = False         # midplatform/replica 恒 True

    def url(self) -> URL:

        if prefix is None:
            raise ValueError(f"未登记的数据库驱动: {self.driver!r}")

            password=self.password,
            host=self.host,
            port=self.port,
            database=self.database,

class ReadOnlyViolation(RuntimeError):
    """只读角色上发生写意图（flush/execute 非查询）时抛出。"""


class ConnectionManager:
    """连接池与会话/事务的唯一出口（每数据库角色一个引擎）。

    用法（领域仓储内）：
        with db.session() as session:            # 自动提交/回滚的轻会话
            ...
        with db.transaction() as session:        # 显式事务；支持嵌套 SAVEPOINT
            with db.transaction(session) as sp:  # 内层＝SAVEPOINT
                ...
        with db.readonly() as session:           # replica/midplatform 只读
            ...
    """

    def __init__(self, specs: Sequence[DatabaseSpec]) -> None:
        self._engines: dict[DatabaseRole, Engine] = {}
        self._sessions: dict[DatabaseRole, sessionmaker[Session]] = {}
        self._specs: dict[DatabaseRole, DatabaseSpec] = {}
        for spec in specs:
            engine = create_engine(
                spec.url(),
                pool_size=spec.pool_size,
                max_overflow=spec.max_overflow,
                pool_recycle=spec.pool_recycle_seconds,
                pool_pre_ping=True,
                future=True,
            )
            self._attach_observers(engine, spec)
            self._attach_readonly_enforcement(engine, spec)
            self._engines[spec.role] = engine
            self._sessions[spec.role] = sessionmaker(
                bind=engine, expire_on_commit=False, future=True
            )
            self._specs[spec.role] = spec

    # ---------- 观测钩子（慢查询/计时；不写业务审计表） ----------

    def _attach_observers(self, engine: Engine, spec: DatabaseSpec) -> None:
        state: dict[Connection, float] = {}

        def before(conn: Connection, _cursor: Any, _stmt: Any, *_a: Any) -> None:
            state[conn] = time.monotonic()

        def after(conn: Connection, _cursor: Any, statement: Any, *_a: Any) -> None:
            started = state.pop(conn, None)
            if started is None:
                return
            elapsed_ms = (time.monotonic() - started) * 1000
            if elapsed_ms >= spec.slow_query_ms:
                LOGGER.warning(
                    "slow query on %s (%.0f ms): %s",
                    spec.role, elapsed_ms, str(statement)[:300],
                )

        def on_error(context: Any) -> None:
            # 失败语句不触发 after_cursor_execute——计时状态在此回收（防泄漏）。
            conn = getattr(context, "sqlalchemy_connection", None)
            if conn is not None:
                state.pop(conn, None)

        event.listen(engine, "before_cursor_execute", before)
        event.listen(engine, "after_cursor_execute", after)
        event.listen(engine, "handle_error", on_error)

    def _attach_readonly_enforcement(self, engine: Engine, spec: DatabaseSpec) -> None:
        """DB 级只读兜底（readonly 角色）：连接建立即置事务只读。

        ORM 层 before_flush 守卫（readonly() 内恒挂）拦 ORM 写；本钩子拦
        绕过 ORM 的 Core execute 写语句——「强制只读」双保险（PG/金仓近似）。
        """
        if not spec.readonly:
            return

        def set_read_only(dbapi_connection: Any, _record: Any) -> None:
            cursor = dbapi_connection.cursor()
            try:
                cursor.execute("SET default_transaction_read_only = on")
            finally:
                cursor.close()

        event.listen(engine, "connect", set_read_only)

    # ---------- 会话与事务 ----------

    def _assert_writable(self, role: DatabaseRole) -> None:
        if self._specs[role].readonly:
            raise ReadOnlyViolation(f"数据库角色 {role!r} 为只读，禁止写会话")

    @contextmanager
    def session(self, role: DatabaseRole = "primary") -> Iterator[Session]:
        """轻会话：块结束即 commit（异常回滚）。写角色前置只读校验。"""
        self._assert_writable(role)
        session = self._sessions[role]()
        try:
            yield session
            session.commit()
        except BaseException:
            session.rollback()
            raise
        finally:
            session.close()

    @contextmanager
    def transaction(
        self, role_or_session: DatabaseRole | Session = "primary"
    ) -> Iterator[Session]:
        """显式事务；传入已开启 Session 时降级为 SAVEPOINT（嵌套支持）。

        governance 批准事务（C2 端点 7：状态/版本/汇入/留痕/审计同事务、
        生效后副作用补偿）即以外层 transaction + 内层 SAVEPOINT 表达。
        """
        if isinstance(role_or_session, Session):
            outer = role_or_session
            nested = outer.begin_nested()  # SAVEPOINT
            try:
                yield outer
                nested.commit()
            except BaseException:
                nested.rollback()
                raise
            return
        role = role_or_session
        self._assert_writable(role)
        session = self._sessions[role]()
        try:
            with session.begin():
                yield session
        finally:
            session.close()

    @contextmanager
    def readonly(self, role: DatabaseRole = "primary") -> Iterator[Session]:
        """只读会话：路由到 replica（未配置回落 primary），恒挂只读守卫。

        守卫按**意图**挂（进入 readonly() 语境即拦 flush）——不按目标角色
        spec.readonly 判（primary 未配 replica 的回落情形同样要拦）；
        readonly 角色另有连接级 DB 只读兜底（_attach_readonly_enforcement）。
        """
        target: DatabaseRole = role
        if role == "primary" and "replica" in self._engines:
            target = "replica"
        session = self._sessions[target]()
        spec = self._specs[target]

        def guard(flush_context: Any, _instances: Any) -> None:
            raise ReadOnlyViolation(f"只读会话（{spec.role}）禁止 flush")

        event.listen(session, "before_flush", guard)
        try:
            yield session
        finally:
            session.close()

    def resolve_read_role(self, role: DatabaseRole = "primary") -> DatabaseRole:
        """读路由解析：primary 有 replica 配置时读走 replica（预留 seam）。"""
        if role == "primary" and "replica" in self._engines:
            return "replica"
        return role

    # ---------- 行级权限注入点（与 D3 row_filter 衔接） ----------

    @staticmethod
    def with_row_filter(
        stmt: Select, predicates: Sequence[Any]
    ) -> Select:
        """把 mandatory filter 谓词 AND 进查询装配（原样语句不可达执行器）。

        谓词由 security.row_filter() 产出、调用方注入——本层不 import
        security（B16），只提供装配执行点；「无权的数据查不出来，不是
        打码」的物理落点（00 §9.3）。
        """
        for predicate in predicates:
            stmt = stmt.where(predicate)
        return stmt

    # ---------- 健康检查（D5 四灯之库灯——本进程配置的引擎） ----------

    def check_health(self) -> dict[str, str]:
        lights: dict[str, str] = {}
        for role, engine in self._engines.items():
            try:
                with engine.connect() as conn:
                    conn.execute(text("SELECT 1"))
                lights[role] = "up"
            except Exception:  # noqa: BLE001 —— 探活失败降级为 down，不影响业务面
                LOGGER.exception("health check failed: %s", role)
                lights[role] = "down"
        return lights

    def dispose(self) -> None:
        for engine in self._engines.values():
            engine.dispose()


ModelT = TypeVar("ModelT")


class Repository(Generic[ModelT]):
    """领域仓储基类：读写通用（会话经 ConnectionManager 取得）。

    归属裁决（B16 优先于经典依赖倒置）：仓储接口与实现都放各模块包内
    （app/domains/<m>/store.py），仅依赖本基类与 ConnectionManager——
    infra 不反向 import 领域 Protocol（出入登记见本文档 §5 出入 12）。
    """

    model: type[ModelT]

    def __init__(self, db: ConnectionManager, role: DatabaseRole = "primary") -> None:
        self._db = db
        self._role = role

    def get(self, session: Session, id_: str) -> Optional[ModelT]:
        return session.get(self.model, id_)

    def add(self, session: Session, entity: ModelT) -> ModelT:
        session.add(entity)
        return entity

    def delete(self, session: Session, entity: ModelT) -> None:
        session.delete(entity)


class ReadOnlyRepository(Repository[ModelT]):
    """只读仓储基类：读路由解析（replica 预留）+ 分页助手（R3 信封语义）。

    会话由查询方法经 db.readonly(self._read_role) 按需开启——只读守卫
    在该会话上生效；写意图在本基类无出口（不暴露 add/delete 的会话编排）。
    """

    def __init__(self, db: ConnectionManager, role: DatabaseRole = "primary") -> None:
        super().__init__(db, role)
        self._read_role: DatabaseRole = db.resolve_read_role(role)

    def paginate(
        self,
        session: Session,
        stmt: Select,
        *,
        page: int = 1,
        page_size: int = 20,
    ) -> Page[ModelT]:
        """分页查询助手：total＝当前筛选条件下总数（R3 裁决值）。

        counts（全局计数）由调用方对同表另行 count 装配——信封形状
        归接口层公共件（98 §7.2 R3 接线责任落点）。
        """
        page = max(page, 1)
        page_size = max(page_size, 1)
        total = session.scalar(
            select(func.count()).select_from(stmt.order_by(None).subquery())
        )
        rows = session.execute(
            stmt.offset((page - 1) * page_size).limit(page_size)
        ).scalars().all()
        return Page(items=list(rows), total=int(total or 0), page=page, page_size=page_size)
```

（约 340 行；PEP8＋类型标注；除 stdlib 外仅依赖 SQLAlchemy——ORM 已定型 SQLAlchemy 2.0（ADR-0003），接缝在 `ConnectionManager`；零 `app.domains`/`app.api` import——B16。三个上下文管理器经 `contextlib.contextmanager` 装配；只读双保险＝ORM flush 守卫（意图级恒挂）＋连接级 `default_transaction_read_only`。）

### 4.3 模块怎么用：仓储归模块包（B16 兼容的依赖倒置）

经典依赖倒置（接口在领域、实现进 infra）与 B16「infra 禁 import domains」冲突——**裁决：仓储接口（Protocol）与实现都放模块包内，二者只向下依赖 `infra.db`**；模块内部分层为 `service.py（编排薄）→ store.py（仓储，薄）→ domain.py（聚合厚）`，跨模块仍只 import 公开接口符号（B11）。示例（semantics）：

```python
# app/domains/semantics/store.py —— 仓储实现（模块包内，import infra 向下）
from sqlalchemy import select
from app.infra.db import ConnectionManager, ReadOnlyRepository

from .models import SemMetric            # 本模块 ORM 模型（归模块包）
from .domain import MetricRow            # 领域值对象


class MetricRepository(ReadOnlyRepository[SemMetric]):
    model = SemMetric

    def by_slot(self, session, slot_name: str) -> MetricRow | None:
        stmt = select(SemMetric).where(SemMetric.slot_name == slot_name)
        row = session.scalars(stmt).first()
        return None if row is None else MetricRow.of(row)
```

```python
# app/domains/semantics/repository.py —— 领域接口（Protocol，供 service/expose 依赖）
from typing import Protocol
from .domain import MetricRow


class MetricReader(Protocol):
    def by_slot(self, session, slot_name: str) -> MetricRow | None: ...
```

- 组装根（`app` 组装处）把 `MetricRepository` 注入为 `MetricReader`——领域面向 Protocol 编程，替换实现不动用例。
- **写仓储**（如 `change_ticket` 状态机迁移）继承 `Repository`，事务边界由 service 层 `db.transaction()` 划定（「同一服务端事务内完成」各合同条款的落点）。
- 机检候选：import-linter 追加两条 contract——①`app.domains.**` 禁 import 数据库驱动模块（`psycopg`/`kingbase` 等，B3——驱动符号只许出现在 `app.infra.db`）；②`app.infra.db` 禁 import `app.domains`/`app.api`（B16）。
