# specs/api/ —— 页面 → 后端接口需求合同（册首）

> **性质：需求合同，不是技术承诺。** 冻结的是数据形状、业务语义与验收口径；框架、存储、鉴权基础设施等实现选型**不在冻结范围**——各文档内标注"结合实际框架定"处即悬置点。逐页商定框架/存储时，以本册为**输入**反推（访问模式/量级/一致性要求写在各端点下），不是重开需求。

## 产出方式

- 页面产品化改造时逐页产出，**一页一文件**：`specs/api/<页码>-<页名>.md`；前端 mock 实现＝`prototype/app/src/api/<页码>.js`（**函数签名即契约**，mock 只在这一层，页面组件不持有业务数据）。
- **2026-09-29 缺口补齐批口径**：本批 14 册新合同 + 00 册 + F1 升版为**合同先行**（真实开发前期调研），按 Owner 指令未产前端 mock、未动页面代码——mock 补建归前端接线批（各册「mock 更正清单」已随文冻结接线批必改项）。
- 后端就绪后：mock 函数体换 fetch，签名与返回形状不变——前端零改动切真实接口。

## 演进纪律

1. **版本与性质声明**：每份文档头标注版本（v0.x）与性质行。
2. **变更走记录**：字段/语义变更在文档尾「变更记录」留行；后端实施中发现合同不合理——先改文档再改码，**不许静默分叉**。
3. **合同是页面与后端之间的唯一口径**：页面改交互涉及数据形状时，同步改契约文档与 mock 三处，一个 commit 内完成。
