## 统一入口与事件驱动总纲（合同常量）

**所有问句无例外走单一主端点 `POST /api/chat/asks`**，四层流水线全部在服务端（F56）：①D1 统一安检（字面规则，任一 ✗ 拦截出终局）→ ②知识装配（六路匹配器并行查表共池）→ ③D2 意图裁决（LLM·闭世界 17 链枚举·结构化输出）→ ④执行链分发（链内闸门代码值守）。**前端不编排链路顺序**——右侧"思考过程"树路径叙事由 SSE 事件帧驱动：节点 on 条件不满足不渲染，过程是"长出来的"（页面规格 F2 语义照抄；同 C3"短路由服务端判定、前端不自行编排"先例）。

## DTO 定义（关键形状）

### 1. GET /api/chat/scenarios → 200

```json
{
  "items": [ {
    "id": "data-fix", "name": "上个月产量最高的三口井",
    "group": "问数据 · 状态机",
    "tag": { "color": "blue", "label": "数据 · 状态机" },
    "chain": "状态机六站链",
    "configs": [ { "item": "反思回边上限（试错 3 次）与熔断阈值", "page": "D2" } ]
  } ],
  "total": 23,
  "groups": ["问数据 · 状态机", "问数据 · 大结果", "问数据 · 熔断", "语义层闸口", "问报告 · 检索",
             "专业工具", "设备上下文", "安全与权限", "受控写入", "关系追溯", "做汇报"]
}
```

- `name`＝场景示例问句（左栏历史条目文案同源）；`chain`∈17 链枚举，拦截/澄清场景可为 null（injection/ban 走安检终局、ambig/askback 裁决未定）；`configs`＝思考过程底部"⚙ 本场景全过程受这些配置影响"跳转行（item 文案照抄 SCENARIOS，page∈roles.js 页键）。
- **`configs[].page`∈现役页键（`roles.js` MENU 为准）**：D4 已撤页，内容分流 D5/D3/E2）——演示种子 bigresult/deck 两条 `page:"D4"` 引用为撤页前遗留，接线批按现役页键归位，不复活已撤页。**D5 已撤页归并 D1（Owner 2026-10-01）——演示种子 fuse/reject/injection 三条「留痕查看」配置行已随企业化清理批归位 `page:"D1"`**（熔断/拒答/拦截留痕＝D1 记账流水按 call_id 定位）。
- **演示版路由关键词（kw）与优先级（pri 10–96）不入合同**——关键词表会沦为第二裁决源；真实意图路由唯一真源＝D2 模型裁决（F56③），23 场景 kw/pri 属前端演示资产照抄 `A1Chat.jsx`。
- 23 条注册行是**演示种子数据**，逐条注源：场景构成＝19 原版＋提及≠问句＋受控写入＋关系追溯＋外表引用人工审批（页面规格 F3）；链路标签/分组照抄 SCENARIOS，业务事实零新增。

### 2. GET /api/chat/sessions → 200

```json
{ "items": [ { "id": "sess-0318", "title": "上个月产量最高的三口井",
  "group": "问数据 · 状态机", "scenario_id": "data-fix", "updated_at": "2026-09-27T18:40:00" } ] }
```

- 会话记录**存服务端**（会话历史库档，m3/m4——页面 DEV 注记"换设备、断线重连都不丢"）；`group` 取值＝注册表 `groups`（分组顺序以页面规格 F3 为准）；按 `updated_at` 倒序。
- 新会话不设独立端点——`POST /api/chat/asks` 的 `session_id` 缺省即新建。

### 3. GET /api/chat/sessions/{id}/messages → 200

```json
{ "items": [ {
    "id": "msg-01", "role": "user", "text": "上个月产量最高的三口井", "run_id": "run-0918"
  }, {
    "id": "msg-02", "role": "assistant", "run_id": "run-0918",
    "answer": { "kind": "table", "…": "六种 kind 见下" }
} ] }
```

- `answer` 与 SSE `answer` 帧**同形**（一份 DTO 两处消费）；出处/血缘/工具调用随 answer 内嵌。历史"思考过程"逐帧回放不在本版合同（见开放问题 2）。

### 4. POST /api/chat/asks → `text/event-stream`（SSE）

入参：

```json
{ "session_id": "sess-0318", "question": "上个月产量最高的三口井",
  "page_context": { "page": "A2", "object_type": "well", "object_id": "N-02" },
  "anchors": ["工具·测井岩性识别"] }
```

- `session_id` 缺省＝新建会话；`page_context`＝对象页背景（井档案页当前打开的井等）——服务端**确定性注入**提示词（F44 Context 层："打开对象页即注入，不靠模型自觉检索"，context 场景「那口井」指代解析的数据来源）；`anchors`＝输入框已落 @ token 的资产（服务端按主键直取装配，检索瀑布 S1 早停配套；取不到＝落空拒答）。
- **断线重连模式**：同路径重发、`question` 等入参不再需要，改携 `resume_run_id` ＋ HTTP `Last-Event-ID` 头——服务端识别已存在 run，不重新执行，从 Redis 事件缓冲按断点续推（CONTEXT「断线恢复」；PRD F4：SSE 事件按 thread_id 追加 Stream）。
- 事件信封：`id: <帧序号>` / `event: <类型>` / `data: <JSON>`——帧序号即 Last-Event-ID 依据。传输形态（EventSource 原生仅 GET，POST 流式需 fetch 读流）结合实际框架定，本合同只冻结帧协议。

## 行为规则汇总

1. **单入口无旁路**：全部问答走 `POST /api/chat/asks`；四层流水线（安检→装配→裁决→分发）服务端完成，前端零编排（PRD F1/F56；按端点分链的旧 `POST /chat/{agent}` 形态不复活）。
2. **帧类型集不可改**：19 类事件帧与载荷形状是本合同核心冻结物；帧命名与全景树节点键一致；术语纪律照抄 flows/common.jsx 头注（发起对话/意图识别/工作流/17 链清单内选择；禁偏门词）。
3. **链内节点行内容不另立新值**：S0–S8 检索瀑布分级（F58/W-F21）、GuardChain 五段短路（F14/W-F14）、状态机六站与三要素校验（F7）、沙箱三闸与 sandbox_denied 三字段 gate/trigger/disposal（F57）、反思回边 3 次与熔断转人工工单话术（F7/CONTEXT）——均为既有链内合同，本页经 `node_line`/`answer` 承接呈现，值照抄各源。选表节点行只显示命中表名；逐表八信号评分 breakdown（F26）属链内 trace 面、不落页面（PRD F26"信号不落库——查询时经公开面现算"，页面无该 breakdown 展示位），不在本页合同。
4. **拦截场景是终局不是错误**：injection（注入扫描命中——与 promptfoo 红队用例同源）/ ban（禁用词 0 号位）在 `sec_check` blocked 后直接出 `answer` kind=alert 拦截话术并 `done` 收尾，审计留痕（拦截也是审计事件）；话术照抄 SCENARIOS（"平台规则不可能被对话内容覆盖"等）。外发判定不在 D1——"想外发"是意图，归 D2 出口分派外发拦截链（F16 归位注记）。

6. **成本熔断**（网关侧，F2）不属本页端点；出口"配置核对"行可展示"单次花费阈值未触发"等核对结果（展示面），阈值合同值归 D5/D2 配置。
