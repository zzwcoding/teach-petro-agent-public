## 本册最重要的合同裁决：纯读面（不设写端点）

1. **页面现实现零编辑入口**（全页仅筛选/详情抽屉/登记卡 Modal/演示卡——无新增/修改/删除/导入导出任何写交互），故**本册不设任何写端点**：语义资产的创建与修改唯一入口＝**C2 语义修订提案池**（提案 → C3 五道检查 → 负责人批准发布＝版本 +1〔m16 `Lifecycle.approve`〕→ 可回滚；F25 四红线「不直接改主干」同源）；草案补登、白名单扩条目、工作流账号绑定全部走提案池（页面底字照抄：「双击行查看登记卡，补登走语义修订提案池」）。
2. 对 `/api/semantics/*` 资源的 POST/PUT/DELETE 无对应路由（**405** 兜底）——"台账只能经正门改"在接口面就是没有旁门（与 C3「无跳过流水线」正门语义同族）。
3. **写路径对端的合同归属**：C2 汇入合同（定义族＝台账行版本 +1；对象与关系附加 Join 白名单扩条目·正门五步）生效时由服务端写台账，写端点形状归 C2 合同（已立据 C2-语义修订提案池.md v0.1〔终检批闭合注记〕）；本册只冻结**读形状**——C2 汇入后的台账行必须能被本册端点原样读出（字段一一对应，版本字段随汇入 +1）。
4. YAML 导入/导出与 F23 Ossie 兼容导出：F6「账本总览与通用格式导出」已随 规格重写移除、页面 `__traces` 仍注记 F23——**现页面无落位即不设端点**（悬置见开放问题 3）。
