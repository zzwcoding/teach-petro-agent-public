## 1. 全局约定

### 1.1 Base URL 与版本化（悬置）

- 各册合同只写 `POST /api/...` 相对路径，**Base URL 不入合同**（部署形态结合实际框架定）。
- **版本化策略悬置**：20 册均未出现 `/v1/` 类版本段；语义层版本（`semantic.current`＝v37，C3）/配置版本（D2 `version.no`）是**业务版本**，与 API 传输版本是两回事。是否引入 URI 版本段待真实部署批定——引入时走本册变更记录，各册路径不变。

### 1.3 字符编码与媒体类型（本册补立的默认）

- 请求/响应体一律 **UTF-8 + `application/json`**（SSE 为 `text/event-stream`，见 §6）；各册未显式声明，本册补立为全平台默认。
- 时间戳格式与数字形状见 §1.4/§1.5。

### 1.4 时间与数字形状

**时间两类字段，判据＝是否被服务端/客户端用于计算**（先例归纳）：

| 类别 | 格式 | 判据 | 先例 |
|---|---|---|---|
| 机器时间戳 | **ISO 8601 `YYYY-MM-DDTHH:mm:ss`**，东八区本地时间、不带时区后缀 | 参与排序、TTL 计算、保留窗口、跨端比对的字段（`started_at`/`expires_at`/排序键 `updated_at` 等） | D1 spend-logs `time:"2026-09-28T09:52:30"` · D5 `started_at`/samples `time` · A1 sessions `updated_at:"2026-09-27T18:40:00"` |
| 展示串时间 | `YYYY-MM-DD HH:mm`（或各册冻结粒度） | 直接进页面单元格、服务端不做计算的展示字段（列表 `time` 列/活动流 `time`/`saved_at` 等） | A3 `time:"2026-09-26 09:41"` · B1 活动流/`saved_at` · C2 `created_at`/流转 `time` · E2 任务 `time` |

- 展示串时间**不入计算**；页面需要别的展示格式由前端按机器字段拼装——与 D1/D5「数据形状红线」同构（见下）。
- 展示串混入结构化字段的（E3 `finishedAt:"2026-09-28 22:40（人工）"` 含触发方式后缀、A3 `executed_at` 含「自动执行」后缀）＝各册已声明的"结构化拆分待存储设计批"遗留，迁移见 §14。
- 时区：全平台东八区本地时间；不带 `Z` 后缀（F1 voucher `expires_at` 带 `Z` 的示例为演示遗留，§14 迁移项）。

**数字形状红线（D1/D5 同款，推广为全平台）**：

- 耗时＝毫秒整数（亚毫秒落 0）、token＝整数（`null`＝不走模型展示「—」/`0`＝不走模型记 0/正整数三态，D5 口径）、花费＝元数值——**不得返回拼接好的展示串**（`"5.2 秒"`/`"¥0.34"`/`"2,140＋1,380"` 一律前端拼装）。先例：D1 spend-logs、D5 runs/latency。
- 分数/比率：E1 三维评分为字符串演示值照抄（`"0.94"`）——真实实现落数值，展示格式前端拼（§14 注记）。

## 2. 鉴权与身份

### 2.1 双轨：内部登录会话 ＋ 外部 API 凭证

| 轨 | 凭证形态 | 覆盖面 | 先例 |
|---|---|---|---|
| 内部 | 登录会话（**Token/Session 具体形态悬置**——页面现"角色切换"为演示静态标注，DESIGN §2；真实会话设施结合实际框架定。**选型落盘（ADR-0003）：企业 OAuth2.0，开发期预留不校验——开发期身份桩见 §2.4**） | 全部管理面与工作台端点（`/api/*` 除 `/api/expose/*` 外） | 各册权限行（"未认证 401、无权 403"全 20 册同款） |
| 外部 | `Authorization: Bearer pa-live-…`（F61 API Key，服务端只存指纹） | `/api/expose/*` 全部端点（含清单读——"清单读不豁免鉴权链"） | F1 调用鉴权链：身份解析→scoped 默认拒绝→可见性复核→D3 查询安检→执行与出门 |

- **内外同权同闸、协议层不加权**（F49 原句，F1 合同值）：外部 Key 与内部用户过同一套 D3 查询安检，无旁路；拒绝帧与内部权限拒同形（不是"Key 无效"）。
- Key 纪律（F61 收拢）：明文仅在签发/轮换响应出现**一次**、服务端仅存指纹、轮换/停用**立即生效**（停用后新调用一律 401、在途调用不追溯撤回）、每笔调用自动更新 `lastUsedAt`、scoped 未声明能力默认拒绝（fail-closed）、非 full-access 时 `scopes` 至少一项（防哑 Key）。

### 2.2 who 字段服务端解析（全平台统一纪律）

**审计/留痕的 `who`（及发起角色、固化人、操作人）一律由服务端从当前会话解析，不信任前端**——20 册中 A3/B1/B2/B3/B4/B5/C1/C2/D5/E1 十册显式声明此句（D5 见其行为规则 9，注「D1/D3 同款」为跨册引用）；A1/D1/D3/E2 权限行未显式声明（仅声明 401/403 同闸与角色鉴权），本册收拢为全平台纪律后对全册生效。E1 mock `RUN_ROLE` 写死、A3 种子 who 含「老王」与角色限制不一致等均为演示遗留（各册已如实标注，接线批按会话解析更正）。低风险自动执行类留痕 `who`＝「系统」（A3 先例）。

### 2.3 401 / 403 / 404 语义统一（全平台判例）

| 码 | 语义 | 判例（先例） |
|---|---|---|
| 401 | **未认证**——身份解析失败（D1 统一安检第三道"身份与数据域"同闸；外部 Key 缺失/指纹不符/已停用已轮换） | A1/D1/D3 同闸声明 · F1 凭证闸 |
| 403 | **已认证但越权**，分两型：①页面角色组越权直调（设置中心组仅运维角色等，整页端点组同闸）；②行级/资产级直调越权（A2 直调无权井、A1 对无权工具 anchor 直取）。**列表/面板路径走过滤不报 403**——无权资产不出现（"世界里没有"，F48），403 留给直调 | A2「直调无权井 403；列表路径走过滤不报 403」· A1「资产面板走过滤不报 403，403 留给直调越权」· B1/B2/B3/B4/B5/C1「403 留给基础设施层越权」同款 |
| 404 | 资源不存在或已过期清理（含已合并删除、已过期 upload_id/任务） | 各册错误码草案 |

- 外部面 403 细分（F1 冻结值）：`reason` 区分 `capability_denied`（能力未声明）/ `not_in_list`（清单外直调）/ `security_blocked`（D3 安检拦截），附出路指引；**未注册工具名 404 vs 已注册但不在放行清单 403** 的分界照抄 F1（lesson 30 捣乱 A/B 同形状）。

### 2.4 实现选型预留：企业 OAuth2.0 与开发期身份桩（ADR-0003）

- **认证选型**：企业 **OAuth2.0**（生产形态接企业统一认证）；**开发期预留不校验**——401/403 判例（§2.3）不依赖认证实现，开发期即用身份桩保证全链路语义真实。
- **开发期身份桩**：身份解析 seam 不变（98 冻结卡 3.13 `security.authenticate`——ADR 拍板稿称 `resolve_actor`，同位同义）——开发期实现＝**读请求头 `X-Dev-User`**（取值＝§9.1 五角色键；**缺省落默认角色**）；who 字段服务端解析（§2.2）与角色过滤语义全部保真。
- **接 OAuth 只换一处**：生产接 OAuth2.0 时仅替换该身份解析函数实现，各册合同、DTO、401/403/404 判例零改动；本节为实现预留，不改动 §2.1 双轨数据形状。

## 3. 统一错误包与 HTTP 状态码

### 3.1 错误响应 JSON 形状（本册新立的统一形状）

各册错误码草案只定 HTTP 码与人话说明（"错误体带字段名与允许区间" D1/D2/D5、"message「处方段缺项：<清单>…」" C2、"拒绝帧附缺失参数清单" F1）；本册收拢为**统一错误包**（各册 message 文案照抄不变，形状归本册）：

```json
{ "code": "invalid_patch", "message": "条数越界——semanticTopK 下限 1",
  "detail": { "field": "params.semanticTopK", "constraint": ">=1" },
  "trace_id": "call-8c31" }
```

- `code`：业务错误码，**字符串枚举**（§3.3 空间预留）；`message`：人话原因，页面可透传（B1 F32 红线"失败原因不写数字，只到停在哪一步＋人话原因"同族）。
- `detail`：结构化附加，可选——字段名与允许区间（D1/D2/D5 先例）、缺失参数清单（F1 补参拒绝帧先例）。
- `trace_id`：可选，预留字段位——取网关调用号 `call-id`（PRD F2 改注 / W-F2-1：响应头 `x-litellm-call-id` 记入调用记录；D1 spend-logs `id` 如 `call-8c31` 即同一调用号族）或 run_id（D5 `GET /api/observe/runs/{run_id}` 直查先例），是否恒携带结合实际框架定（§15-Q3）。
- SSE 流内异常不走 HTTP 错误包——以 `error` 帧 `{code, message, hint?}` 收场后关闭流（PRD F1 合同值，A1 冻结；`hint`＝fix_hint 三元组 `{stage, rule, fix}`，D3 422 驳回理由同语义）。

### 3.2 HTTP 状态码统一表（从 20 册错误码草案归纳）

| 码 | 统一语义 | 先例出处 |
|---|---|---|
| 200 | 成功（含查询、写操作返回落库后快照——"返回快照为唯一真值" D1/D5）。**检查/自检类端点失败也是 200，必须查 body 的 `ok` 字段** | D3 `key-selfcheck`（WeKnora 语义吸收） |
| 202 | 异步受理（任务入队、变更申请送审）；受理即回、不阻塞 | C3/D1/D2/E2/E3/B3/F1/A1 artifacts 任务受理 · D2 change-requests |
| 400 | 入参形状非法：枚举越界、数值越界、缺项、形状不符——错误包 `detail` 带字段名与允许区间 | D1「参数越界」/ D2 / A3 / B3 / C2 / E1 / F1 / B1 全册同款 |
| 401 / 403 / 404 | 见 §2.3 | 全册 |
| 405 | **纯读面合同的路由级兜底**——只读域收到写请求（POST/PUT/DELETE）回 405 | C1「对 /api/semantics/* 的写请求 405——台账只能经 C2 正门改」 |
| 409 | **状态机或并发冲突**：任务重入（"同一时刻最多一个任务进行中"）、非预期状态下的状态迁移、乐观锁冲突（`base_version` 落后）、双入口后到（先到先得）、重复操作（重复标记/重复确认/重放）。语义上"状态前置条件失败天然幂等"（A3）——安全做法是刷新状态后重试或放弃 | C3/D1/D2/D3/B1/B3/B4（回滚防呆）/B2/E1/E2/A3/C2/F1（elicitation 重放）全册 |
| 422 | **业务规则拒绝**（形状合法但语义校验不通过，不可执行）：受理但被安检驳回（附驳回理由/fix_hint）、复验不达拒绝关闭 | D3「写操作未过 C3 · 422」（W-F14-6）· E2「关闭复验不达 · 422」 |
| 500 | 服务端内部错误——不带堆栈，错误包携 `trace_id` 供 D5 排障 | A2「台账/投影查询内部异常 500」· D1「配置写回失败 500，需回滚提示」 |

- **202 vs 200 判据**（任务创建两形态，先例并存）：受理仅入队、任务号即凭据 → `202`（C3/D1/A1/F1/B3/D2/E2/E3 先例）；受理动作同步完成（核实落桶＋配置定型）并返回任务资源初始态 → `200`（B1 confirm 先例）。
- **400 vs 422 判据**：请求还没进门（形状/枚举/缺项）→ 400；进门后业务规则说不（安检驳回/复验不达）→ 422。C2 晋升闸不达现用 400，归入 422 更贴切——迁移见 §14-R8。

### 3.3 业务错误码空间（预留，不冻结具体值）

- `code` 采用 `<域>_<语义>` 蛇形字符串；已冻结值域保留：F1 外部面 `capability_denied` / `not_in_list` / `security_blocked`；A1 SSE `error` 帧 code（会话域）。
- 其余域（kb/quality/eval/…）按需在各自册错误码草案追加，**不抢注他域前缀**；系统级不设全局错误码注册端点（悬置）。

**系统级错误码登记表**（阶段 0 对齐批立，2026-09-30——`<域>_<语义>` 形状之外的系统级码归口于此；实现仓已用的系统级码收编如下）：

| 码 | HTTP | 语义 | 装配位 | 来源 |
|---|---|---|---|---|
| `request_invalid` | 400 | 请求体/参数校验失败——形状/枚举/缺项「请求还没进门」（§3.2 400 判据）的统一码；框架缺省 422 与本册冲突，统一映射 400，`detail.errors` 逐项 `{loc, msg}` | api 层统一错误包装配点（框架校验异常全局 handler） | 阶段 0 · P0-04 差异 6 |

## 4. 分页、筛选与计数

### 4.1 分页参数

- Query 参数：`page`（≥1）＋ `pageSize`（默认 **20**——D5 先例；各册已冻结的默认值保留，D1 spend-logs 现为 15）。
- **本版整表返回为常态**：演示量级下各册均整表返回、`page/pageSize` 为预留参数（"量大后加"——C3/A2/A3/B1/B3/B4/B5/C1/C2/E1 同款预留句）；D6 明示数据恒定小集合、整表返回不设分页。
- 分页响应携带回显：`"page": 1, "pageSize": 20`（D1/D5 先例）。

### 4.2 total 与 counts 的统一语义（裁定值，§14-R3 迁移）

| 字段 | 统一语义 | 先例 |
|---|---|---|
| `total` | **当前筛选条件下**的记录总数（"筛选结果 X / Y 条"分子） | D5 端点 2（明示"当前筛选过滤后总数"）· A3/B1/C3 列表 |
| `counts` | **恒为全局计数**——不随筛选条件变化，页签徽标/摘要行分母的数据源；`counts.all`＝全局总数 | C3 releases `counts{all,published,blocked}` · A3 `counts{all,pending,…}` · D5 `counts{all}` · A2 页签计数（随井联动，投影特例） |

- 变更类操作（批准/驳回/流转）的响应**可携带流转后最新 `counts`**，前端免整页重拉（A3 端点 3/4 先例，推广为横切约定）。
- 特例保留：F1 expose tools 现用 `total`（清单总数）＋`filtered`（筛选命中）——语义对调迁移见 §14-R3；B4 `total` 现为全量计数、前端拼"X / Y"——同 §14-R3；C1 `counts`＝页签徽标计数族（terms/metrics/objects/relations/workflows），属计数投影非列表分页计数，不受本条约束。**另登记（终检批）**：B3/C1（列表端点）/C2/E1 列表响应均用 `total`（筛选后）＋`grand_total`（池内/库内全量——页面「/ m 条」分母）——`grand_total` 与 `counts.all` 同语义异名，收拢迁移一并归 §14-R3。

### 4.3 排序与"种子书写顺序"纪律

- 排序由**服务端完成、各册合同值优先**（倒序主流：B1/A3/C2/B4 目录/E1 任务/D1 `time`/D5 `started_at`；正序各自拍板：B3 问答清单、E1 题库 id 升序、B4 版本升序）；合并视图类（A2 `events` 多键合并倒序）由服务端拼装、前端零编排。
- **"种子文件书写顺序不构成排序合同"为全平台纪律**（A3/B1/C2/B4 同款声明）——接线批一律改为显式排序字段。
- **可配排序参数命名（P1-00b 补冻）**：页面提供用户可切换排序时，query 参数统一 `sort_by`＋`sort_order`（`asc|desc`；缺省＝该端点合同排序）。`sort_by` 值域由端点合同白名单冻结（如 `time|cost_yuan|calls`），越界 **400 带允许值清单**（D1 400 带区间先例）。本版各册合同排序为冻结值的端点不强制开放可配排序。

### 4.4 批量操作响应口径（P1-00b 新立）

- 批量端点（如未来 B3 批量导入扩展/B1 批量重试）响应恒 **200**，逐行结果走行内状态，不用 207：
  `{ "items": [ { "key": "…", "status": "ok|failed", "code?": "业务错误码", "message?": "…" } ], "sums": { "ok": n, "failed": m } }`
- **HTTP 层与业务层分离**：入参形状非法＝400（请求没进门）；形状合法但部分/全部行失败＝200（业务失败归行内 `status`）；`sums` 恒给，前端汇总展示。
- 行内 `key`＝调用方提交时的行标识（无标识时服务端回序号），幂等重试按 key 去重。

### 4.5 筛选参数通用命名（P1-00b 补冻）

- 全文检索词＝`keyword`；状态枚举筛选用 `status`，**多值＝逗号分隔单参数**（`status=pending,published`），值域各端点合同冻结、越界 400；
- 外键/归属过滤＝`<资源>_id`（`lib_id`/`report_id`/`run_id` 先例沿用）；布尔开关筛选用 `only_<形容词>`（`only_fallback` 先例沿用）；
- 时间窗＝`from`/`to`（ISO 8601，00 §1.4 口径），闭开区间由各端点合同注明，缺省＝不限。

### 5.2 统一约定（从上表归纳；状态命名映射见 §14-R4）

1. **受理**：`POST` → `202`（或 B1 同步特例 `200`）＋任务号＋初始状态；**受理即回、不阻塞调用方**（A1"受理即回任务号，不阻塞对话"原句）。
2. **轮询**：`GET …/{id}` → `status` ＋进度；轮询节奏由服务端真实进度决定，**页面演示动画（650ms/700ms 级步进）一律不入合同**（B1 明示，推广为全平台纪律）。
3. **重入 409**："同一时刻最多一个任务进行中"——已有进行中任务再受理回 409；**前端按钮禁用是兜底，不依赖此码**（C3/D1/D3/B1/B3/E2/E3 同款句）。
4. **过期/不存在 404**：轮询已过期清理的 id 回 404（B3"已过期清理"、C3/D1"轮询已过期的 id"同款）。
5. **终态落痕**：done/failed 时服务端落任务记录/历史（D1 演练历史、B1 任务列表、D3 试跑历史、E2 任务记录、C3 试运行记录——"试运行与真实发布走同一条流水线，留痕可查"）；任务历史累积保留、不清（E2/E3 明示）。
6. **stuck（疑似卡住）**＝超时无进展、服务端后台巡检判定（B1 冻结值）；重试**内含停止语义**（先终止旧执行再重建）；卡住阈值结合实际框架定。
7. **失败语义**：按阶段定位（`stop_at`/节点 `error`）＋人话原因（`reason`）——**不发明错误码数字**（B1 F32 红线）；可人工重试，重试＝按当前配置重新定型（B1"重跑＝一次新入库"）。

### 5.3 节点步进形状（管线可视化通用形）

```json
{ "nodes": [ { "key": "parse", "label": "解析（读出文字和图）", "state": "finish", "note": "…", "skipped": false } ] }
```

- `state` 四态 **`wait | process | finish | error`**（C3/D1/D3/B1/D2 五册同形，与 antd Steps 语义对齐）；`note` 由**服务端按该 run 的上下文组装、前端零拼装业务文案**（B1"A3 outcome 先例"）。
- **跳过的表达（两种并存，判据不同）**：①流程级早停跳过——`state:"wait"` ＋ `skipped:true`，**不扩 state 枚举**（D2 合同裁决，推广为通用形）；②配置性支路跳过——关掉的支路直接不跑、不设节点态，由对应节点 `note` 的 ✓/✗ 承载（B1 F32"关掉的支路不跑不花钱"）。前者＝"跑到这里决定不往下"，后者＝"配置上就没有这一步"。

## 6. SSE 事件帧规范

### 6.1 帧信封（PRD F1 合同值，A1 冻结）

```
id: <帧序号>
event: <类型>
data: <JSON>
```

- 帧是 SSE 流里的最小单位 `{event, data}`（CONTEXT「事件帧」）；**帧序号即 Last-Event-ID 依据**。
- 结束帧 `event=done`（`data:{}`）；异常帧 `event=error`（`data:{code, message, hint?}`）**发出后关闭流**——SSE 内异常不走 HTTP 错误包（§3.1）。
- 传输形态悬置：EventSource 原生仅 GET，POST 流式需 fetch 读流或网关配合——结合实际框架定，合同只冻结帧协议（A1 开放问题 6 收拢为系统级悬置）。

### 6.2 断线恢复（三收场，A1 合同值＝全平台 SSE 通道约定）

| 收场 | 条件 | 行为 |
|---|---|---|
| ① 窗内重连 | 断线在事件缓冲（约 200 帧，Redis Stream MAXLEN 裁剪）内 | 重连带 `Last-Event-ID` → 服务端补发断点后帧，**已出内容不丢、不重复** |
| ② 缓冲耗尽 | 超出缓冲窗口 | 收场话术「会话中断较久，中间漏了一段（超出缓冲窗口），请重新提问。」——**不静默丢帧** |
| ③ 生成已被取消 | 断线期间生成已被取消 | 以 `replay_truncated` 帧收场 |

- 重连模式：同路径重发、携带 `resume_run_id` ＋ `Last-Event-ID` 头——服务端识别已存在 run，**不重新执行**，从事件缓冲按断点续推。
- 本节为信封级约定；**帧类型集不收编**——19 类事件帧（session/stage/sec_check/…/done/error/replay_truncated）是 A1 会话域合同值。他页若开 SSE 通道，复用本节信封、`done`/`error`/`replay_truncated` 三帧语义与断线三收场，业务帧自行立集走各自册。

## 7. 文件传输

### 7.1 预签名直传两拍（B1 先例＝全平台上传约定）

```
① POST 受理（登记文件名/大小/目标域）→ 200 { 上传受理 id, put_url（预签名 PUT）, expires_at }
② （客户端直传对象存储——平台不经手文件字节，F5）
③ POST confirm（服务端向对象存储核实已落桶 → 创建下游任务/登记）
```

- **直传不绕平台**（F5 `presigned_put_object`；B1"报告从客户端直接传进文件库，不绕平台服务"原句）。
- 直传凭证过期 → 重新受理（旧 id 作废）；对象未落桶/凭证已用时 confirm 回 409（B1 先例）；孤儿对象回收策略悬置（B1 开放问题 7，§15-Q6）。
- 前端本地选择状态（"已选择：《…》"类提示）不设服务端端点（B1 显式声明，F1"显式不立端点"同款声明方式）。

### 7.2 下载直链与句柄（voucher）

- **统一 TTL 口径：预签名 GET 直链、小时级有效、上限 7 天**；A1 出口直链/B1 下载直链/F1 voucher 同族）。直链下载**直达对象存储、不走平台转发**。
- **voucher 句柄四字段**（A1/F1 同形，F27 合同值）：`artifact_id` / `download_url`（GET 预签名）/ `preview.total_rows`（总行数随预览声明携带）/ `expires_at`；`preview`＝预览协议：**5 行预览＋列名表头＋总行数声明＋数值列 min/max/均值摘要**。
- **落盘顺序闸**：落桶→落库→签 URL，三步走完句柄才出门（F27/A1 合同值）。
- **大结果以句柄出门**：超阈值结果正文不落数据、凭证出门（A1 voucher 卡/F1 收场 C 同形；阈值归属 A1/D2 同源悬置——本约定只冻结出门形状）。
- 产物三件套 `kind ∈ ppt | img | audio`（PRD F10）；产物卡形状 A1 端点 8 冻结（F1 同形引用）。

### 8.2 只读追加与不可关闭（合同级语义）

- **审计只读追加**：不提供删除/改写留痕的界面与端点（B1 活动流底注「只记录，不改任何数据。」原句；E2 隔离区 append-only 同教义）。
- **审计不可关闭**：全部写操作（启停/发起/流转/关闭/批准/驳回/撤回/修正/配置修改）留痕；**拦截也是审计事件**（A1——注入/禁用词拦截在 `done` 收尾前留痕）；外部调用也是审计事件（F1 行为规则 7）。低风险自动执行同留审计行（A3 `who`＝系统）。
- 驳回/撤回类负动作须留理由：A3 驳回可空但服务端兜底落默认话术「影响测算不足」、C2 兜底「理由未填写」（**两入口各自拍板、防静默归一**——A3 分治注记）；A1 Action 链链内驳回 `reason` 必填（400）。

### 8.3 脱敏与密文

- 凭证类只回脱敏占位（`pa-****9f2c`、`sk-****`）；**编辑提交占位值＝保留旧凭据**（D3 WeKnora 语义吸收）；密文存储在服务端；Key 明文仅签发/轮换响应一次（§2.1）。

### 9.2 页面可见性与"世界里没有"（F48）

- **"不是被拒答，而是世界里没有"**：菜单不可见＝界面对该角色不存在（F48 原句；E1"老王/实习生本页不存在于其世界"）；列表/面板数据按角色过滤后返回——无权的**不出现**，不是出现后打码（A1"无权的数据查不出来，不是打码"；D3 权限矩阵"没配＝结构上没有入口"）。

### 9.3 行级权限与双重权限

- **行级权限**＝数据域（区块/井）裁剪：D3 `row_filter` 开关（"按对方身份过滤数据行"）；A2 直调无权井 403；A1 行级权限链（WHERE 由权限层拼接、不靠模型自觉——lineage「（权限注入）」独立成行为合同值）；指标卡汇总不按行裁剪、口径级管控在指标卡（边界不同不重复设防）。
- **双重权限**：第一道闸＝资产面板服务端过滤（@ 资产 `panel_view(user)` 投影）；第二道闸＝执行前复核（F8/A1 合同值）。
- 跨区查看的出路＝D3 数据域授权申请（A1 出路指引先例）。

### 9.4 五层能力与外部 scoped 档

- 五层能力（F48 五层裁剪；F61 scopes ＝ D3 权限矩阵 layers 同族）：`context 能看 / query 能查 / compute 能算 / write 能动 / governance 治理`。
- **外部凭证＝scoped 只读档**（agent-card authentication 合同值）：外部 Agent 默认只读档、行权限随档注入；`write` 能力对外默认不授予（F61"对外默认不授予"原文）；读到的数带审定口径与出处、不是原始表（F49 要点）。
- 本体双通道边界（F49）：外部走消费通道（读对象/执行查询类工具）；管理通道（改类型/口径定义）不在外部调用面——外部对口径/术语只能提修改建议＋人工审批（F1 行为规则 3）。

### 9.5 正门语义（无免审通道）

- 高风险操作必须人工点：A3"无批量批准端点、无免审通道"、C2"无批量批准、无免审通道"、C3"无跳过流水线类接口（不设临时豁免通道，F57 正门语义同源）"——**全平台不设任何免审/跳过/批量批准通道**；`status=pending` 类前置条件在服务端裁决、不信任前端按钮。
- 双入口操作同一状态机：先到先得、后到 409（A1↔A3 审批、C2↔C3 批准同款）。

## 11. 与国产化的关系

- **金仓 ≈ PostgreSQL 方言**（PRD F3/F11）：开发库 PostgreSQL、生产切金仓；金仓兼容模式在 initdb 期一次性固化，安全检查按"近似 PostgreSQL 口音"解析（D5 环境健康带悬浮文案合同值）；迁移踩坑对照（PG↔金仓方言差异）是 F11 素材——**本合同体系 SQL 演绎为 PostgreSQL 方言**（仓库红线：金仓≈postgres 近似）。双库并存为常态（D5 四灯双库同列）。

## 15. 开放问题（悬置点）

1. **API 版本化策略**：URI 段 / header / 不版本化——待真实部署批定（§1.1）。

3. **trace_id 携带策略**：错误包是否恒携带、生成规则（网关 call-id / run_id / 独立 trace）与 D5 关联查询的接线——待可观测批。
4. **camel/snake 迁移时机**（R1）：接线批一次性 vs 各册自然演进——建议前者（mock 签名即契约，一次切换零双轨）。
5. **配置版本化与回滚**：各册配置是否统一版本化/可回滚（B1 无、D2 演示 v23、A3 叙事"一键回滚"）——待存储设计批统一。
6. **直传孤儿对象回收**：受理后未 confirm/凭证过期的半程对象清理——结合对象存储生命周期规则定（B1 开放问题 7 收拢）。（对象存储已拍 MinIO——ADR-0003，本条**维持悬置**：回收策略随 MinIO 生命周期规则与部署批定。）
7. **审计存储归一**：四族审计列形是否归一审计总表（含 D3 digest/SM3 通道）——数据库设计批。
8. **外部面限流与防重放**：20 册均未出现限流/幂等键/防重放约定（F1 elicitation 重放 409 为唯一相关判例）——外部调用面真实化批决定是否补立。
9. **CORS 与部署拓扑**：前端/网关/对象存储跨域策略——部署批。（**部分收口·选型落盘批（ADR-0003）**：部署拓扑已拍双服务——主平台模块化单体＋数据面独立服务（`/api/ingest/*` 经数据面 HTTP API 拉投影、零共享库）；CORS 跨域策略细节（前端域/对象存储直链域）仍悬置部署批。）
10. **liveness/readiness 分离**：容器编排探活端点是否独立于 `/api/observe/health`——部署批（§10）。
