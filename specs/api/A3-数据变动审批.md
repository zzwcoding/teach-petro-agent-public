## 页面定位（先于端点的合同常量）

数据面/配置面变动的**审批台**——每条变动像一份合同（F47 Action 四部分），高风险必须人工点批准；批准后只写变更记录区（**Writeback**，CONTEXT：修改写独立变更记录区、不污染源数据），生产原表永不动，全程留审计。卡右上定位行（照抄页面）＝「低风险自动执行 · 高风险必须人工终审 · 批准后只写变更记录区，生产原表不动 · 全程审计」。**语义面修订不走本页**——转 C2 语义修订提案池；语义面权限申请驳回转角色权限流程（F47 三面模型）。

## 变动单的产生与生命周期（主单合同，先于端点清单）

- **产生通道＝服务端内部，不设页面创建端点**（页面只审批不提单）：①A1 Action 链（action 场景）interrupt 挂起时创建高风险待审批单，`run_id` 落主单；②工作流承接（F19 触发三路：人工指令承接/监控数据表触发/周期回放）创建，`run_id` 可空；③**低风险单在创建事务内自动执行**——`status=auto`＋`executed_at`＋审计行（who＝系统）同事务落库，不经审批（F47"低风险自动执行并留审计"；F47 红线：高风险操作永无自动执行）。
- **主单结构化字段**（页面列表不直接消费、服务端与跨页消费）：`run_id`（nullable，A1 对齐锚点）、`workflow`＋`account`（提出人＝工作流&账号的结构化拆分——工作流名与 C1 台账 WORKFLOWS 同源；账号绑定两态见 F19）、`object_refs`（对象实体引用数组，形状见端点 1——A2 按井投影的过滤依据）、`short`（事项列文案）。
- **`approval_id` ≡ 变动单号**（# 前缀单号即 A1 `approval` 帧 `approval_id` 的对齐值——A1 合同端点 5 留的跨页锚点在本批冻结；A1 resume 与本合同端点 3/4 操作**同一主单状态机**）。
- 状态机（合同值，F47 四态）：`pending →（批准）approved ｜（驳回）rejected`；`auto`（低风险自动执行，创建即终态）；`withdrawn`（提出方主动撤回，重复单合并重报）。`approved|auto` 同映展示态「已执行」。

## DTO 定义（关键形状）

### 1. GET /api/change-tickets → 200

入参 `status=all|pending|executed|rejected|withdrawn`（展示态过滤；`executed` 服务端映射机器码 `approved|auto`）· `risk=all|high|low` · `plane=all|数据面|配置面|语义面` · `workflow=<提出人去重清单项>` · `keyword=<单号/对象模糊>`——**四条件 AND 过滤**（页面规格 F2）。

```json
{
  "items": [ {
    "id": "#WB-20260926-05", "risk": "high", "status": "pending",
    "plane": "数据面",
    "object": "N-11 井（渤中 / CEP-B · 采油 · 停产）",
    "proposer": "《复产确认检查》工作流（账号：复产建议）· v2 已补充含水测算",
    "workflow": "《复产确认检查》工作流",
    "short": "N-11 台账状态 停产 → 复产待确认（v2）",
    "time": "2026-09-26 09:41"
  } ],
  "total": 17,
  "counts": { "all": 17, "pending": 6, "executed": 5, "rejected": 4, "withdrawn": 2 },
  "workflows": [ "《复产确认检查》工作流", "《区块注采平衡评估》工作流", "《低产井措施筛查》工作流",
    "《机采井工况诊断》工作流", "《幻觉拦截周报》工作流", "《注水井措施评估》工作流",
    "《平台运行周报》工作流", "《档案质量体检》工作流", "《月度统计对账》工作流", "账号：小李" ]
}
```

- **列对应**：变动单=`id` / 风险=`risk` / 状态=`status`（机器码，展示映射按合同常量表） / 面=`plane` / 对象·工作流&账号＝`object`＋`proposer`（两行拼装）·`time`（页面渲染） / 操作列＝前端"详情"按钮。`proposer` 逐字照抄数据文件（含「· v2 已补充含水测算」版本后缀）。
- **`short`（事项摘要——挂账收口批补列）**：主单结构化字段（主单合同节定位为「服务端与跨页消费」）自本版起在列表项携带——消费方＝**C1 工作流登记卡变动单回链块「单号 · 事项」渲染**（C1 合同「复用 A3 端点 1」节渲染字段注记①案「A3 端点 1 列表项补 `short`」的兑现）；详情端点 2 已有同名字段，两处同源主单。页面列表渲染不消费此列（F3 列对应不变——对象·工作流两行拼装照旧）。
- **`counts` 恒为全局计数**（不随过滤条件变化，页签徽标联动数据源——C3 releases 同款纪律）；批准/驳回后经端点 3/4 响应携带的最新 `counts` 联动，或整页重拉端点 1。演示种子计数＝待审批 6 / 已执行 5（approved 0＋auto 5）/ 已驳回 4 / 已撤回 2。
- **`workflows`＝提出人去重清单**（工作流下拉数据源，`showSearch`）——服务端从台账主单 `workflow` 字段现派生，**现取不建仓**（台账同源纪律——本清单不是第二份工作流注册表）；「工作流：全部」选项为前端常量。账号直提单（#ACC-20260922-15）以账号段「账号：小李」为提出人（F47：工作流&账号为主、账号直提为补充）。
- **`object_refs`（主单结构化字段，本响应不携带、按单详情/服务端内部消费）**：`[{ "type": "well|block|config|role", "id": "N-11" }]`——演示四值照对象列分类（井/区块/平台配置/角色权限）；type 值域按本体对象类型注册表收编（开放问题 6）。**A2 端点 4 按井过滤口径＝`object_refs` 含 `{type:"well", id:<路径井号>}`**（回对冻结，见「与 A2 的回对」节）。`plane` 为主单必填字段——演示 17 单前缀与面一一对应（#CFG→配置面、#ACC→语义面、#WB/#MS→数据面）仅为数据一致性，**不是推导规则**（mock 前缀推导为接线批更正项）。
- `keyword` 模糊匹配范围＝单号＋对象（页面规格 F2 口径；现 mock 多匹配了 `short`，接线批更正）。过滤枚举值越界回 400（预留）。

### 2. GET /api/change-tickets/{id} → 200（详情）

配置面示例（#CFG-20260924-09，合同栏照抄数据文件）：

```json
{
  "id": "#CFG-20260924-09", "risk": "high", "status": "pending", "plane": "配置面",
  "object": "平台配置 · 问数链置信度阈值",
  "proposer": "《幻觉拦截周报》工作流（账号：平台运维）", "time": "2026-09-24 14:50",
  "short": "问数链置信度阈值上调（中档下限 0.70 → 0.75）",
  "contract_items": [
    { "key": "param", "label": "参数", "body": "问数链 SQL 置信度阈值：低于阈值强制走反思改错 / 人工。只写平台变更记录区，不直接改任何生产表。" },
    { "key": "value", "label": "当前值→建议值", "body": "高 ≥0.90 / 中 0.70–0.90 / 低 <0.70 → 建议改为 高 ≥0.93 / 中 0.75–0.93 / 低 <0.75。" },
    { "key": "scope", "label": "影响范围", "body": "近 7 日回放 23 条问数：4 条中置信样本将强制反思，预计多问 2–3 轮；误放率预计降 1.8 个点，误拦率升 0.6 个点。" },
    { "key": "rollback", "label": "回滚方式", "body": "配置版本化保存，可一键回滚至 v23；先灰度 3 天再全量。" }
  ],
  "audit": [],
  "outcome": { "state": "pending", "text": null, "executed_at": null, "reason": null }
}
```

- **`contract_items`（合同项表，两列 项/内容，全状态可见——F47 收口语义）**：按面组织的模板族——配置面基准四项＝`param 参数 / value 当前值→建议值 / scope 影响范围 / rollback 回滚方式`；数据面基准四项＝`change 改动内容 / why 理由 / impact 影响测算 / side 副作用`（页面规格 F4 静态数据）。演示变体照抄数据文件：#MS 措施类＝`change / window 实现窗口 / occupy 占产影响 / cost 费用与口径`；低风险勘误类＝`change / basis 触发依据 / impact 影响评估`；#ACC 类＝`change 申请内容 / why 理由 / min 最小权限评估 / alt 替代方案`。服务端按单存原样返回（`label/body` 照抄），前端零拼装；`body` 为文本（种子改动内容内的加粗声明「只写平台变更记录区，不直接改任何生产表。」为语义性文本，加粗与否属前端渲染）。落库形态与 Action 合同四部分（参数/规则/前置条件/副作用，F47）的映射待存储设计批（开放问题 6）。
- **`audit`（本单审计记录，`when/who/agent/what` 四列照抄页面）**：`agent`＝提出人工作流段（服务端从主单 `workflow` 派生——mock 的 `agentOf` 字符串切分为接线批更正项）；`who`＝审计者身份（服务端会话解析；种子演示值含「系统（低风险自动）」「老王」「提出方（配注优化助手）」等，照抄不改）。空态＝`[]`，页面渲染「暂无审计记录」（照抄页面——pending 单初始无审计行，演示种子中 6 张待审批单均为空审计）。
- **`outcome`（底部状态区，服务端按状态拼装 `text`——前端零拼装业务文案，A2 `foot`/`measure_foot` 先例）**：
  - `pending`：`text=null`——前端按 `state` 渲染两键处理区（「批准（高风险，必须人点）」「驳回（须写理由）」按钮为前端行为）。
  - `approved`：`text`＝批准完成文案（单号代入，合同值）。
  - `auto`：`text`＝自动执行底态文案；`executed_at` 照抄数据文件（如「2026-09-23 17:03 自动执行」——演示值含「自动执行」后缀，结构化拆分待存储设计批）。
  - `rejected`：`text`＝驳回底态文案；`reason`＝主单落库理由全文（含时间后缀，如「影响测算未覆盖复产初期含水波动，补测算后再议（2026-09-20 14:22 驳回）」）。
  - `withdrawn`：`text`＝撤回底态文案；`reason`＝撤回原因全文（如「提出方主动撤回：与 #WB-20260923-01 内容重复，合并为上调 10% 后统一重报（2026-09-22 12:00 撤回）」）。
- 数据面高风险单基准合同项示例（#WB-20260923-01，`contract_items` 键集 `change/why/impact/side`，内容照抄数据文件：改动内容含「只写平台变更记录区」声明＋理由注采比 β＝月注水量÷月产液量（体积折算）＋物质平衡偏差 ≤3%（设定书 §3 指标 6 / §4 规则 12）＋影响测算劈分系数（Σ=1）与响应起始日（§5 受效关系）＋副作用三条）。语义面指路单示例（#ACC-20260922-15）：`reason`＝「权限变更不走变动单，转角色权限流程审批（2026-09-22 11:20 驳回）」。

### 3. POST /api/change-tickets/{id}/approve → 200（批准——高风险必须人点）

请求体为空（无参数）。前置条件：`status=pending`（服务端裁决）。

```json
{ "id": "#WB-20260926-05", "status": "approved",
  "audit_row": { "when": "2026-09-29 14:30", "who": "阿强（当前角色 · 高风险终审）",
    "agent": "《复产确认检查》工作流",
    "what": "N-11 台账状态 停产 → 复产待确认（v2） —— 写入变更记录区 #WB-20260926-05；生产原表未动" },
  "counts": { "all": 17, "pending": 5, "executed": 6, "rejected": 4, "withdrawn": 2 } }
```

- **同一服务端事务内完成**：①`status` → `approved`；②审计追加一行（`what` 按批准审计行模板拼装，`who`＝当前会话角色——演示值「阿强（当前角色 · 高风险终审）」照抄页面，真实由会话解析）；③**Writeback：写入平台侧变更记录区条目，生产原表不动**（F47 写回纪律——变更记录区的读取端点不在本版，见开放问题 1）。
- **幂等与状态机约束**：仅在 `pending` 可达——重复批准、对 `approved/auto/rejected/withdrawn` 单批准一律 **409**（状态前置条件失败天然幂等；低风险 `auto` 单无批准入口，同撞 409）。**不设批量批准端点、无免审通道**（F47 红线"高风险必须人工终审"，同 C3"无跳过流水线"正门语义）。
- **与 A1 双入口（状态机单源）**：A1 链内审批卡批准（`POST /api/chat/runs/{run_id}/resume`，`{kind:"approval", decision:"approve"}`）与本端点操作**同一主单资源**——先到先得，后到 409（A1 侧 resume 收 409 链路按既有错误帧收场；本侧 409 契约见错误码草案）。

## 行为规则汇总

1. **Writeback 纪律（合同级）**：批准＝授权写入变更记录区；生产原表永不动；低风险自动执行与高风险人工批准同一纪律；全程审计（谁/何时/哪个工作流或账号/改了什么——F47 审计四元组）。变更记录区的读取消费端点不在本版（页面无展示区，开放问题 1）。
2. **高风险必须人点**：无批量批准、无免审/跳过通道；`status=pending` 前置条件在服务端裁决，不信任前端按钮（非待审批一律 409）。
3. **驳回须留理由**：缺省由服务端落「影响测算不足」；理由落主单（含时间后缀）＋审计行＋退回提出方。
4. **双入口状态机单源（A1）**：见「与 A1 的关系」节——`approval_id`≡单号、`run_id` 落主单、后到 409；extable 不进本页。
5. **A2 投影兑现（回对）**：见「与 A2 的回对」节——`object_refs` 冻结、机器码/展示值映射冻结、按井过滤认实体引用。
6. **语义面边界**：修订转 C2（单据分流）；权限申请处置＝驳回指路转角色权限流程；本页可见但操作出口受限（见「与 C2/C3 的关系」节）。
7. **权限语义**：整页端点组同闸（阿强/主任，`roles.js`）；未认证 401、无 A3 角色 403（C3 设置中心组同口径——页面不可见＝世界里没有，403 留给直调越权）；审计 `who` 服务端会话解析。**种子审计 who 含「老王」（4 处驳回＋1 处低风险自动，共 5 行）与 A3 角色限制不一致——演示数据历史遗留，照抄不改、不构成 who 值域约束**；真实 who 值域＝阿强/主任（审批）＋系统（低风险自动）＋提出方（撤回）。
8. **台账同源与现取不建仓**：`workflows` 去重清单从台账现派生；工作流名与 C1 台账 WORKFLOWS 同源）；账号绑定两态（登记/草案）治理归 C1/F19——本页不重复设防。
9. **样本业务事实零新增**：17 张种子与合同栏内容逐字照抄 `data/changeTickets.jsx` 与页面规格 §A3；有设定书直锚处已注源（β/物质平衡 ≤3%/劈分系数 Σ=1/响应起始日/配注合格率 §6/商品量 §3 指标 11/递减增油 §3 指标 10/含水 87.1 §A.2/N-11 检泵 §A.4/2025-09-06 酸化参照 A2 关系链种子）；**无设定书直锚的演示值如实标注**：β 下限 0.95、泵效 45%→55%、超时 30s→45s、配注上调规程上限 10%、灰度 3 天/回滚至 v23、恢复期贡献 100–150 吨等——演示数据照抄不洗白。
