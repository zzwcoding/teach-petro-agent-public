## 入库任务生命周期（主单合同，先于端点清单）

- **直传两拍受理**：①`POST /api/kb/uploads` 受理——登记文件名/大小/目标库，返回**预签名 PUT 直传凭证**（客户端直传对象存储，平台不经手文件字节，F5）；②`POST /api/kb/uploads/{upload_id}/confirm` 确认——服务端核实对象已落桶后**创建入库任务开跑**。页面"已选择：《…》→ 完井报告库"提示＝前端本地选择状态（受理请求的入参来源），不设服务端端点。
- **配置定型点在受理确认时刻**：confirm 时按该库**当前待生效配置**生成 `config_snapshot`，本次入库全程用这份快照——此后配置修改（端点 13）与正在处理的任务无关（「上传时不做单次覆盖，正在处理的报告不受影响」的合同落点；F32 开关入库时定型）。
- **状态机（合同值）**：`running →（五步全过）done ｜（某步失败）failed ｜（超时无进展·后台巡检判定）stuck`；`failed/stuck/done` 均可人工重试（端点 10）回 `running`。stuck 重试**内含停止语义**（服务端先终止旧执行再重建管线）——页面无独立停止按钮，不设独立 stop 端点。
- **失败语义（F32）**：按阶段定位（`stop_at`＝停在五步之一）＋人话原因（`reason`，**不发明错误码数字**——F32 红线）；**富化子任务失败不阻塞整卷完成**（整卷照常 done；子任务粒度本版不建模——开放问题 3）。
- **跳过语义（F32 分发枢纽）**：四管线按开关扇出、缺管线也能跑——关掉的支路**直接跳过、不跑不花钱**；切段必然执行（四管线都依赖分块，F32 `NeedsChunks()`）；跳过发生在向量化支路/建索引的对应索引支路/索引期加法。
- **重跑定型语义**：重试/重跑＝一次新入库——按该库**当前**待生效配置重新生成快照（页面步 2/步 4 说明随当前配置联动同象）。

## 行为规则汇总

1. **原文一个字不动（页面定位行合同化）**：报告原文原样存文件库（桶：报告原文），以后任何引用都能翻回原文——下载直链（端点 3）与 F36 图本体回读共用原件定位，不走索引。
2. **五步合同值不可改**：节点名、顺序、四态标记均照抄；管线推进/短路/跳过由服务端判定编排，前端不自行编排（C3 短路由服务端判定同纪律）；切段必然执行（F32 `NeedsChunks()`＝四管线都依赖分块），关掉的支路直接跳过、不跑不花钱。
3. **配置定型语义**：保存＝待生效配置、下次入库定型、不做运行时热切换；上传不做单次覆盖；正在处理的报告不受影响；重跑＝重新定型。库列表展"最近一次入库所用"快照、配置端点管"下次入库"——两态分离不许合并。
4. **失败与卡住（F32 增补）**：按阶段定位＋人话原因、不发明错误码数字；卡住＝超时无进展后台巡检；人工重试入口；富化子任务失败不阻塞整卷；界面只到"停在哪一步＋人话原因"。
5. **索引期加法＝chunk（F37）**：摘要 ×1＋每 20 段问题一批，入索引带类型标；是否生成随该 run 快照；A1 追问建议消费走检索不经本页。
6. **chunk 契约与父子分块**：三切段方式中 `mixed`＝F30 父子分块（小段进索引负责被找到、大段只入库不索引负责被读懂、父块永不出现在检索结果集——INV）；`smart`/`fixed` 为既有单级分块对照选项（F30 保留）；面包屑前缀（F31）＝索引投影，涉及时引用、不改 chunk 原文。
7. **权限语义**：页面全员可见（roles.js MENU B1 无 roles 限制）；端点组对五角色开放；未认证 401、直调越权 403（页面不可见判例不适用本页——全员可见）；**写权限细分已关单（Owner 2026-10-01 权限统一口径）**：阶段 1 单一角色「系统管理员」拥有全部权限、写功能照做照建，细粒度分权随 D3 权限矩阵批（设计批提前到阶段 1 开工前）；审计 who 服务端会话解析、不信任前端。
8. **活动流只读（F62）**：追加写、五角色 who、无删除/改写界面；跨库全平台视图不在本页。
9. **样本业务事实零新增**：三库名/七报告名/五步节点名/四开关/三切段/参数（256–1024/10–20%/每 20 段）/摘要文本/10 问/种子任务/活动行全部注源（页面规格 §B1＋B1.jsx＋PRD F5/F6/F30/F31/F32/F36/F37/F62＋设定书 §A.1/§A.2/§A.4/§A.5/§5/§2.2＋CONTEXT.md）；**无设定书直锚的演示值如实标注**：refs 5/3（＝B2 片段数同源演示）、wiki v3/v1、"20 多分钟"、扫描件失败原因、活动时间戳、上传/配置操作人分工。
10. **mock 简化更正清单（接线批执行）**：①上传文件名恒写死 TASK_DOC→按 confirm 登记文件名；②500ms Skeleton→端点加载态；③650ms/步动画→真实轮询端点 8；④任务/配置/活动/版本全部本地 state→端点 4–14；⑤复选框未接 run（done 恒展示两卡）→按快照 add_summary/add_questions 展示；⑥fragment path 含「（图片说明块）」后缀→由 type 字段派生；⑦f1–f4 仅两卷→全部已入库报告可预览（未收录提示文案保留）；⑧lib-1 开关三处矛盾→快照由 run snapshot 派生、自洽；⑨修正空文本回退原文→400 拒绝；⑩台账/任务排序按种子书写顺序→时间倒序（台账「入库中」标企业化清理批由前端按任务状态派生——接线批改由端点 1 `status` 直出，页面同象先行）；⑪failed 种子 `current_step=0` 与 `stop_at=切段` 并存→按「current_step＝stop_at 对应步序号」对齐（渲染以 stop_at 为准，端点 7/8）；⑫新建库/停用启用/活动追加全为本地 state→端点 15/13/11/14（v0.3 建库批页面交互，接线批随 ④ 一并接真实端点）。
