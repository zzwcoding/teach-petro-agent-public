> 版本：v0.4（2026-09-29）· **需求合同**——冻结数据形状与业务语义，不承诺实现技术（文中"结合实际框架定"处即悬置点）；字段/语义变更走文末变更记录，演进纪律见 `specs/api/README.md`。

> 契约来源：`specs/modules.md` m18「评估证据链」`SemanticCI.validate_change`（L1–L5）/ `PromptfooExport.cases` · （行为回归＝逐题逐槽比对当前基准）· （同配置才谈降级）· PRD F16（红队 8 条）/ F20（基准供给）· m16 `Lifecycle.approve`（发布动作，版本 +1）。
> 权限：页面仅「平台运维」角色可见（`roles.js`）；流水线为系统强制闸门——**无"跳过流水线"类接口**（不设临时豁免通道，F57 正门语义同源）。

## 流水线五阶段（L1–L5 页面口径，合同常量）

`格式检查（配置装载）→ 引用一致性 → 查询安全（只读 · 粒度 · 零分母）→ 治理合规（负责人 · 敏感字段 · 高影响审批）→ 行为回归（考核基准逐槽比对）`

结果标记四态：`过 | 拦下 | 不涉及 | 未跑`——**短路语义：按顺序执行，任一阶段"拦下"即停，后续阶段一律"未跑"**。

## DTO 定义（关键形状）

### 1. GET /api/ci/overview → 200

```json
{
  "engine": { "status": "running" },
  "lastBatch": { "id": "#214", "time": "2026-09-27 18:40", "result": "通过" },
  "semantic": { "current": "v37",
    "lastRelease": { "id": "2026-0921-03", "time": "2026-09-21", "name": "新增术语「躺井」（限作业区语境）" } }
}
```

`semantic.current`＝语义层全量版本锚点——**每次发布成功 +1，全平台问答按该版本作答**（D3 页头策略徽标、C1/C2 治理链提示引用同一口径）。

### 2. GET /api/ci/releases → 200

入参 `status=all|published|blocked · gate=1–5 · keyword=`（匹配单号/变更/目标）。

```json
{
  "items": [ {
    "id": "2026-0920-02", "name": "「产量完成率」定义修订提案", "target": "指标口径 | 业务术语",
    "blocked": 4,
    "version": { "from": "v36", "to": "v37", "released": false },
    "summary": "指标「产量完成率」：修订计算定义",
    "submitter": "阿强",
    "proposal": { "id": "#PP-0394", "name": "「产量完成率」定义修订", "state": "待审" },
    "detail": [ { "gate": "治理合规（负责人 · 敏感字段 · 高影响审批）", "result": "拦下", "why": "…" } ]
  } ],
  "total": 7,
  "counts": { "all": 7, "published": 2, "blocked": 5 }
}
```

- `blocked`=0 表示已发布（`version.released=true`，语义层版本已升至 `to`）；1–5 为拦下阶段序号，`released=false`（版本号回落，语义层维持 from）。
- `id`＝发布记录单号（release 型 run 的台账行标识——与 `pipeline_run.id` run 号的两标识关系见「与 C2 提案池的工单关系」节 v0.4 澄清；rollback 行沿用 run 号）。
- `detail[].why` 必须写清判据与处置（如"整包退回提案池补审批"）——拒绝留痕是本页核心语义。
- `counts` 恒为全局计数；台账量大后加 `page/pageSize`（分页参数预留）。

## 与 C2 提案池的工单关系（数据表设计，v0.2 定稿）

**主工单只有一张：提案单（C2）。C3 台账不是第二张工单，而是同一提案的流水线执行记录（1—N）。** C2 点「送检」＝创建一条正式流水线执行记录（run）；C3 台账的每一条＝一次送检的执行视图；改一次不过、改完再送检＝同提案下第二条 run。

```
proposal（提案单 · C2 主单）               pipeline_run（流水线执行 · C3 台账本体）
├─ id              #PP-0394               ├─ id              run-0318
├─ object/type     产量完成率 · 指标口径    ├─ proposal_id     #PP-0394        ← FK
├─ prescription    变更处方（三槽位）       ├─ run_type        release | dry_run | rollback（v0.4——回滚呈现）
├─ evidence        证据与证据形态           ├─ triggered_by    送检人 / 提案人
├─ state           待分诊|待审|已过安检|    ├─ stages          5 阶段 gate_report（JSONB 或子表，
│                  已生效|已驳回           │                  阶段数固定、整读整存）
├─ owner           责任人                  ├─ verdict         通过 | 被「X」拦下
└─ version         语义层 from/to          ├─ version         from/to（通过且批准后 to 生效）
                                          └─ started_at / finished_at
```

**状态回写规则**（run 结束 → 提案单状态，服务端事务内完成）：

| run 结果 | 回写 | 后续 |
|---|---|---|
| 五阶段全过 | proposal.state＝**已过安检** | 人工批准（m16 `Lifecycle.approve`，C2「批准」按钮）→ **已生效**，语义层版本 to 生效；检查通过本身不推版本 |
| 被某阶段拦下 | proposal.state＝**待审**（回到提案池）+ 流水线报告附单 | 提案人修改后可再次送检（新 run）；或负责人**驳回**＝"直接关闭"（终态，附理由） |
| 试运行（dry_run） | **不回写**、不推版本、不进台账 | 仅预检用途，结果落试运行记录 |

- 批准动作归属提案生命周期（C2「批准」按钮）；C3 对"已过安检"的提案可提供同一 API 的确认发布入口（UI 双入口、状态机单源），待 C2 产品化批接线。——**现势注记（终检批）**：C2 已立据 v0.1 并注「本册即接线点」（C2 端点 7 双入口状态机单源条），接线批执行。
- C2 现页面"送检即视为通过"是 mock 简化——接线后送检按钮调 `POST /api/ci/drills`（release 型），状态由流水线回写，本节即两页接线的合同。
- **回滚的台账呈现（v0.4 裁决——C2 开放问题 9② 兑现）**：C2 端点 9 回滚（`live→checked` 双版本轴回退）在发布台账呈现为**一条 `run_type="rollback"` 的执行记录**——`verdict`＝「回滚至 <from>」；**不推新版本号**：`version` 字段 `to`＝from 回退值（语义层 `semantic.current` 随 C2 端点 9 事务回退——C2 已冻结「`semantic.current=from`」）；`triggered_by`＝回滚操作人。回滚 run 不改动任何既有 release run 行（历史留痕不动）。
- **两标识关系（v0.4 澄清——99 册出入 #15「两标识的对应关系待 C3 澄清」就此落判）**：`pipeline_run.id`（`run-0318` 族）＝流水线执行记录的**统一主键**（三类 run_type 皆有）；**发布记录单号**（`2026-0920-02` 族——releases 台账行 `id`、端点 1 `lastRelease.id`）＝**release 型 run 的台账行标识**（通过/拦下均生成——台账行＝一次送检的执行视图，本节原文）；**dry_run 不进发布台账、不生成单号**（落试运行记录，端点 5）；**rollback 呈现在台账但沿用 run 号作行标识、不占用发布记录单号序列**。同一提案多次送检＝多条 run 各带各的单号（改一次不过、改完再送检＝新 run 新单号）。

### 3/4/5. 流水线执行（dry_run 试运行 ／ release 正式送检）

- **候选选择（dry_run 场景）**：`GET /api/ci/dry-run-candidates` → 提案池「待审」提案投影 `[{ "proposalId": "#PP-0394", "name", "target", "summary" }]`——试运行前先选变更包（弹层下拉）。
- `POST /api/ci/drills` 入参 `{ "proposalId": "#PP-0394", "run_type": "dry_run" | "release" }` → `{ "runId": "run-0318" }`。**`run_type` 可选（v0.4——C2 送检接线兑现，缺省 `dry_run` 向后兼容）**：`dry_run`＝试运行（不进发布台账、不回写提案单、不推版本——下文原语义）；`release`＝**正式送检**（C2「送检」按钮接线——创建正式流水线执行记录，结果按「与 C2 提案池的工单关系」节状态回写规则落提案单、进发布台账并占用发布记录单号）。release 型仅对「待审」（`wait`）提案合法——C2 状态机约束（送检按钮恒在 wait 行），非法态 409；dry_run 变更包不在候选内 404；重入 409。
- 轮询返回：`{ "status": "running|done", "nodes": [ { "key", "label", "state": "wait|process|finish|error", "note": "通过|检查中…|拦下|未检查（短路不查）" } ], "result": { "reason", "conclusion" } }`
- **结果按所选变更包生成**：`reason`＝该包对应阶段的判据原文；`conclusion`＝被「X」拦下＋短路说明——服务端按提案内容判定，前端不编排。
- **短路由服务端判定**：试运行剧本在查询安全阶段踩线（UPDATE 语句 + 除法零分母缺失），后续阶段 `wait`＋note"未检查（短路不查）"——前端不自行编排检查顺序。
- `done` 时服务端落试运行记录（时间/变更包/拦下阶段/结果）——试运行与真实发布走同一条流水线，留痕可查；**试运行不产生正式发布、不推进版本号**（release 型 `done`＝按工单关系节回写提案单＋发布台账落行〔单号生成〕——`run_type` 分派）。

### 6/7. 安全回归用例

- `redteam-cases` → 8 条：`{ "key": "rt-01…rt-08", "pos", "ask", "assert", "line" }`——rt-01~06 藏刀用例、rt-07/08 直说对照条（两道语义不混用：直说走硬闸零审批、藏刀走信任标记＋外发闸）。
- 页面落位：发布单详情内的"安全回归用例"折叠区（仅当查询安全阶段执行过、即 `detail[查询安全].result ≠ 不涉及` 时展示）。
- 用例试跑（rt-01）：`POST redteam-runs` → 轮询返回 `checks: [ { "name", "ok", "state": "wait|running|done", "note" } ]`，断言**逐条核对**；`done` 返回 `conclusion`——全过出绿结论（藏刀指令未被执行，回答照常带引用）。

## 行为规则汇总

1. **五阶段合同值不可改**：定义、顺序、四态标记、短路语义均来自 m18 五级 CI 合同。
2. **行为回归数据来源**：E1 任务管理台固化的当前基准单一基准语义；基准被取消时本阶段显示"无基准"提示且**不拦其他检查**——合同待真实实施时细化）。
3. **同配置才谈降级**）：跑批与基准的答题/裁判模型配置不同时属模型对比，不构成降级判定。
4. **试运行≠发布**：试运行用固定剧本、结果落试运行记录（不进发布台账、不推进版本号）；真实发布走 C2 提案池汇入流程自动触发本链，成功即版本 +1（m16 `Lifecycle.approve`）。
5. **样本业务事实零新增**：台账 7 条注源 C1 台账/C2 提案池（老完成率禁用词、递减增油粒度、注采比 β 数据源等）；版本号（v35–v38）为流水线状态演示数据。

## 错误码草案

| 场景 | HTTP | 说明 |
|---|---|---|
| 流水线执行重入（dry_run/release）/用例试跑重入 | 409 | 已有任务进行中（前端按钮禁用兜底） |
| release 型对非「待审」提案送检 | 409 | C2 状态机约束（送检恒在 wait 行——C2 主单合同） |
| 任务不存在 | 404 | 轮询已过期的 id |
| 用例未配置试跑剧本 | 404 | 当前仅 rt-01 配置 |
| 未认证 / 无权 | 401 / 403 | 设置中心组=运维角色 |
