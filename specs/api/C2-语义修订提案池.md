## 提案主单合同（先于端点清单）

- **单号形状**：`#PP-NNNN`（与 C3 台账样例 `#PP-0394` 同源冻结）。演示种子以数字 `key`（1–6、8——**7 缺号为数据文件现值**，不构成编号语义）为标识，接线批迁移 `#PP` 单号（对账 6）。
- **状态机五态**（合同值，机器码照抄页面 `STATE_META` key——C3 合同以中文态名引用，映射唯一）：

| 机器码 | 展示 | 配色 | 行内主按钮 | 可达迁移 |
|---|---|---|---|---|
| `triage` | 待分诊 | 紫 | 查明转派 | →`wait`（端点 5） |
| `wait` | 待审 | 橙 | 送检 | →`checked`（C3 流水线回写）｜→`rejected`（端点 8） |
| `checked` | 已过安检 | 蓝 | 批准（tip：负责人签字生效） | →`live`（端点 7）｜→`rejected`（端点 8） |
| `live` | 已生效（v\<行版本\>） | 绿 | 回滚 | →`checked`（端点 9——回滚可再批准） |
| `rejected` | 已驳回 | 红 | —（留痕可查） | 终态（C3 工单关系原文：驳回＝"直接关闭"） |

- **主单结构化字段**：`source`（三来源枚举）/`target`（三目标枚举）/`evidence`＋`evidence_class`（诊断段·L1–L4）/`confidence`（可信度展示串＋档位规则）/`priority`（优先级展示串）/`rx`（处方段三槽位 object/change/content）/`state`/`reject_reason`（nullable）/`version`（`{from,to}`＝**语义层全量版本**，与 C3 `pipeline_run.version` 同一字段——通过且批准后 `to` 生效）/`source_ref`（产生通道回指，nullable）/`created_at`。
- **诊断段与处方段（机器初诊 → 人确诊③④站）**：诊断段＝来源/目标/证据形态＋证据全文，**机器诊断不可改写**（改写弹窗只读卡照抄）；处方段＝三槽位可结构化改写，**原始诊断随卡留痕**（改写不动诊断段）。CONTEXT「诊断 schema」六字段（来源/对象坐标/现象/证据/证据形态/去向——CONTEXT 条目计数笔误「五字段」实列六项，与 E3 合同端点 4/PRD F24 ⑦ 同列）与本单字段映射：来源＝`source` · 对象坐标＝`target`＋`rx.object` · 现象＋证据＝`evidence`（现版本单字段承载——结构化拆分悬置，开放问题 6）· 证据形态＝`evidence_class` · 去向＝`target`。
- **产生通道＝服务端内部为主，不设页面创建交互**（页面现实现零新建入口）：①E1 失败题按失败槽拆提案（source＝考核没通过——已立据 E1-答题考核.md v0.1〔全链审查二批闭合，原注「E1 合同未出，挂锚点」〕；`source_ref` 三键形状已由其端点 16 冻结）；②E3 建议确认·转提案（source＝自动体检发现——E3 合同端点 4 已立，双向可追溯）；③用户反馈 runtime 信号归一（source＝用户反馈——F56 落空信号/多候选澄清频繁等，A1 侧信号 schema 悬置）；④人工预填（C1「提交口径变更」联动跳转——端点 4 承接，页面现无创建 UI）。进池统一过**晋升闸**（合同常量 2）与**准入矩阵**（合同常量 3）服务端校验。
- **流转记录**：提案生命周期事件溯源表（时间/环节/说明三列照抄页面 `LOG_COLS`）。环节枚举：`提案进池`（detail＝`来源「X」收口进池 · 证据形态 Lx`）/`查明转派`/`改写`/`通过安检`/`安检拦回`/`批准生效`/`驳回`/`回滚`。**待分诊提案未进流转路线——展开区不显示该区块**（页面照抄）。页面 `stepLog` 按当前状态推演演示记录为 mock 简化（对账 7）——真实实现进池即落首行、各操作在服务端事务内追加。

## 与 C3 的工单关系（接线合同——逐字兼容声明）

以下全部承接 `specs/api/C3-发布流水线.md` v0.2 定稿「与 C2 提案池的工单关系」节，**本册不另立状态机、不另立工单**：

1. **主工单唯一**：提案单（本册主单）为主，`pipeline_run`（C3 台账本体）1—N 挂提案（`proposal_id` FK）；C3 台账每条＝一次送检的执行视图。
2. **送检接线**：页面「送检」按钮（`wait` 行）＝调 C3 `POST /api/ci/drills`（**release 型**）——入参 `{ "proposalId": "#PP-…", "run_type": "release" }` → `{ "runId" }`；进度轮询复用 C3 `GET /api/ci/drills/{id}`（形状以 C3 合同为单一来源）。C3 端点 3 v0.3 冻结的入参形状为试运行场景 `{proposalId}`——**v0.4 已增可选 `run_type` 请求字段（`"dry_run"|"release"`、缺省 dry_run 向后兼容），本节送检入参即 C3 现行合同**（原跨文件待办闭合——开放问题 9①）。
3. **状态回写规则**（run 结束 → 提案单状态，服务端事务内完成，C3 原文）：五阶段全过 → `state=checked`（已过安检，**检查通过本身不推版本**）；被某阶段拦下 → `state=wait`（回提案池）＋流水线报告附单——本册落位：`flow_log` 追加`安检拦回`行，detail＝该 run 拦下阶段判据（C3 `detail[].why`）逐字＋「改完可再次送检」（页面无演示帧，本行按 C3 回写规则拍板）；试运行（dry_run）不回写、不推版本。
4. **批准动作归属提案生命周期**：C2「批准」按钮＝m16 `Lifecycle.approve`（本册端点 7 为状态机单源 API）；C3 对"已过安检"提案的确认发布入口（UI 双入口）调**同一端点**——先到先得，后到 409（A1↔A3 双入口同款纪律）。
5. **版本轴**：`version{from,to}`＝语义层全量版本（C3 `semantic.current` 口径——to 生效即 `semantic.current=to`，C1/C2/D3 引用同一口径）。页面 `STATE_META.live.label` 硬编码「已生效（v3）」为演示种子值（v3 对齐 C1 台账行版本演示种子）——接线批改按 `v<to>` 渲染；**台账行版本**（C1 详情抽屉 v3，汇入 +1）与**语义层全量版本**（C3 v36→v37）是两条版本轴，本单同时承载：行版本在台账侧（C1 读出），全量版本在本单 `version`（对账 8）。
6. **dry-run-candidates 同源**：C3 端点 8 `GET /api/ci/dry-run-candidates`＝本池「待审」提案投影 `[{proposalId, name, target, summary}]`——本册端点 1 `state=wait` 即其数据源，服务端直取不建第二份。

## 行为规则汇总

1. **主工单唯一（合同级）**：提案单是语义面修订的唯一主单；C3 台账＝同提案流水线执行记录 1—N（回写规则按 C3）；A3 是单据分流不是投影（语义面修订根本不产生变动单）；E3 建议确认是产生通道不是第二主单（`source_ref` 双向可追溯）。
2. **四条铁律永不违反（F25）**：不直接改主干/只提建议不自己合并/不改自动生成的文件/大改动必须人工批——接口面即：无任何"直接写台账"端点（C1 纯读面的正门语义），生效只经端点 7 批准事务，批准必须 `checked` 前置（人点），409 兜底。
3. **状态机五态单源**：`triage → wait → checked → live`（＋`live→checked` 回滚、`wait|checked→rejected` 终态）；机器码/展示/配色/按钮映射唯一（主单合同表）；C3 回写、双入口批准、E3 进池、端点 5–9 全部操作同一状态机——非法迁移一律 409。
4. **进池闸双校验**：晋升闸（孤例不进池）＋准入矩阵（source×target 可达性）在服务端创建通道强制执行；前端置灰/回弹为同常量的界面投影（常量 2/3）。
5. **诊断段不可改写、处方段结构化改写**（机器初诊 → 人确诊）：改写仅端点 6 三槽位、选项与 C1 台账同源（台账没有的选不到——服务端现取 slots 校验）、原始诊断随卡留痕；驳回须留理由（可空兜底「理由未填写」）、终态关闭留痕可查。
6. **批准＝发布**：端点 7 批准编排——状态迁移、语义层版本 to 生效（`semantic.current` 推进）、定义族台账行版本 +1（对象与关系附加白名单扩条目正门五步）、流转留痕、审计同一事务；派生物刷新、汇入副作用（B3 hook/A1 默认口径）、Verify 站自动回归为生效后触发副作用（回归失败自动回滚＋新提案闭环收口）；检查通过本身不推版本（C3 原文）；无批量批准、无免审。
7. **可回滚**：端点 9 版本回退（语义层＋台账行双回退）、派生物刷新、可再批准；Verify 回归失败自动回滚＋新提案闭环收口）。
