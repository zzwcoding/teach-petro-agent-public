## 页面定位（先于端点的合同常量）

## 父子分块铁律（INV——本合同的检索侧边界，先于端点清单）

- **列表端点只返回子块字段（DTO 无 context 字段）**：完整上下文段仅经端点 2 按需回捞——铁律「列表只给子块」的结构化落点。父块**不设独立 id**、只能经子块回捞到达（F30「父块永不出现在检索结果集」的台账侧同构；检索侧归 m6/A1 检索瀑布 F21——召回集只见子块，B2 台账同守此界、不重复设防）。
- **按类型的回捞语义**：原文块＝父块正文回捞（F30——真实系统 context ⊇ hit，父块包含子块）；图片说明块/图片文字块＝回读父块正文（F36 原文「与 F30 回捞会师」）；**摘要块/问题块为 F37 索引期加法 chunk、无父块**——端点 2 的 context 为产物说明行（页面原值照抄，不虚构父段）。演示八条 context 与 hit 为页面两段独立书写的示意文本（出入对账 8）。
- 三件套（`report/well/section`）＝F31 面包屑的**索引期投影**，chunk 原文不动（B1 跨页锚点原文照录）；`well` 同时是 F31 「片段关联对象落库」中井号标签的展示面（识别不了的如实空——演示八条全有）。

## 质检复核队列（v0.3 增设——Owner 2026-10-01 拍板，先于端点清单）

- **落位**：队列消费端落在**本页**（标记→队列→复核→修正一页走完）；B2 开放问题 1 的三选（E2/报告库扩展/专项）就此裁决，E2 数据质量台不重复设队列面。
- **队列状态机（合同值，本版冻结）**：`待质检复核`（端点 3 标记入口态，不变）→ **`已修正`**（复核确认＋B1 端点 4 修正完成——终态）｜**`已驳回`**（复核驳回、必带理由→回到标记人）→ 标记人二选一处置：**重新标记**（对片段再发端点 3 产生新标记单，旧驳回单转 `已销记`）｜**销记**（端点 6，转 `已销记 · 不修正`）。**队列零悬挂**：每张标记单必达终态（`已修正 / 已销记`），`已驳回` 为必经回流态不留存终。
- **驳回语义**：`reject` 必带 `reason`（缺理由 400——「驳回须写理由」A3 分治同款纪律）；驳回后片段回到可重新标记状态（端点 3 的重复标记 409 只对 `待质检复核` 态片段生效）。
- 队列列形：标记时间倒序；`fragment_label` 三件套同源（端点 3 同款拼装）；`who` 族＝标记人/复核人两列（服务端会话解析）。

## DTO 定义（关键形状）

### 0. 复用 GET /api/kb/reports（B1 端点 1——报告下拉）

形状见 B1 合同端点 1，**零改动**。B2 页消费规则：`items` 中 `refs≠null` 者进下拉（演示＝2 卷：`rpt-n02-completion`《N-02 井完井报告（英文 · 200 页）》refs=5、2026-08 月报 refs=3）；选项文案「{doc} · {lib}」照抄页面；卡头「片段清单（8）」＝下拉各卷 `refs` 求和（5+3）由前端渲染——**总数与台账同源，不另设端点**。量大后「已建切片」服务端筛参是否增设走 B1 变更记录（开放问题 7）。

### 1. GET /api/kb/fragments → 200

入参 `report_id=`（**两读法分派·v0.2**：携带＝按报告整组取数——本页浏览语义，v0.1 原状不变；**缺省＝全库扁平清单**——跨报告片段一维清单，v0.2 增设，见下行）· `page/pageSize=`（**仅全库清单模式必带**——缺任一 400；按报告模式本版整表返回）· `type=all|原文块|图片说明块|图片文字块|摘要块|问题块` · `keyword=`（匹配命中句/井号/章节路径）。

- **全库扁平清单读法（v0.2 增设——B3 开放问题 3「需 B2 变更记录增设」兑现）**：`report_id` 缺省时返回**全库片段台账**——跨报告一维清单、不分报告聚组，`total`＝全库片段数（不与 B1 单卷 refs 对应）；分页 `page/pageSize` 强制（全库量级不受单报告约束）；消费方＝**B3 候选挖掘的引用知识起草**（B3 `slice_ref` 寻址 `{report_id, fragment_id}` 的切片原文下拉数据源——B3 合同「B2 切片管理」节挂锚原文）。**本页 UI 不消费此模式**（页面恒携带 `report_id` 按报告浏览——现实现交互形状不变）；全库清单排序键未定义、不构成合同（同下行排序注记）。
