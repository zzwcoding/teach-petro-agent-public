## 页面定位（先于端点的合同常量；以下为撤页前原文留档）

## 两大边界裁决（先于端点，本合同核心）

### 一、与 D1 记账流水：同源投影，不建第二份账本

花费数字唯一真源＝m2 `record_spend` 落的记账审计表（D1 `GET /api/gateway/spend-logs` 同一来源，m3 落库）。两页分工：

| | D1 spend-logs | D5 链路记录 |
|---|---|---|
| 粒度 | **调用粒度**（每次网关调用一行，call-id） | **运行粒度**（一次提问一行，run_id；总花费＝Σ该 run 的网关调用花费） |
| 侧重 | 花了多少钱、走的主用还是备用 | 走了哪些步、哪步慢（span 树步骤表） |
| 关系 | 账本本体 | **按 run 聚合的投影视图**（m12 span 树＋记账表联查），不建第二份账本 |

| 链路节点耗时 | 行业标准节点时长 | 哪步慢一目了然 |
| 指标口径版本 / 解释链 | **平台特有**（行业标准无对应，显式标注） | 数从哪个口径算来——行业标准没有这项，如实标注、不硬套也不丢掉 |

### 2. GET /api/observe/runs → 200

入参 query：`type=all|问数据|做汇报` · `status=all|normal|done|fused` · `keyword=`（匹配运行号/问题）· `page`（≥1，预留）· `pageSize`（默认 20，预留）。

```json
{
  "items": [ {
    "run_id": "run-0909-01",
    "question": "上个月产量最高的三口井",
    "type": "问数据",
    "status": "normal",
    "six_station": true,
    "total_ms": 1833,
    "total_cost_yuan": 0.0042,
    "started_at": "2026-09-09T10:20:00"

  "total": 4, "counts": { "all": 4 }, "page": 1, "pageSize": 20
}
```

- `total`＝**当前筛选条件下**的记录总数（分页与页面摘要行「筛选结果 X / Y 条」分子的依据）；`counts.all`＝**恒为全局计数**（不随筛选变化，C3 releases / A3 台账同款纪律）——页签「链路记录（4）」徽标与摘要行分母取该值。
- `status` 机器码三值（照抄页面 `STATUS_META`）：`normal` 正常（绿）｜`done` 已完成（绿）｜`fused` 熔断降级（红）——`fused` 即「熔断降级」链路留痕（真实熔断由网关侧产生，见行为规则 7）。

- `started_at`＝**合同补全语义**（页面现实现无时间列；排序与保留窗口需要该字段）——排序恒 `started_at` 倒序，展示列接线批定。
- **演示种子四条照抄页面**（禁发明新量级）：run-0909-01 ·「上个月产量最高的三口井」· 问数据 · normal · 六站 · 1833ms · ¥0.0042；run-0909-02 ·「为什么 N-02 产量下滑」· 问数据 · normal · 5200ms · ¥0.34；run-0909-03 ·「对比 N-02 和 N-05 近两年产量走势」· 问数据 · **fused** · 4600ms · ¥0.13（熔断降级样本——花费沿用本页熔断流程既有数字）；run-0908-07 ·「做一份月度汇报 PPT」· 做汇报 · done · 41000ms · ¥1.86。数字为演示值照抄页面（¥0.08 超限演示值不落 D1 正常记账量级基准 ¥0.002–0.008——基准是正常区间）。

## 与页面规格 §D5 的出入对账（规格落后项——以页面现实现为准）

1. **运行记录 3 条→4 条**：规格 §D5 F1 仅 3 条；页面新增第四条 run-0909-03「对比 N-02 和 N-05 近两年产量走势」（status=fused 熔断降级样本，花费沿用熔断流程既有数字）批次实现内容，规格未同步，以页面为准。
