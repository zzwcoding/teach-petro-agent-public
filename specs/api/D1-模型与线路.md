## DTO 定义

### 1. GET /api/gateway/models → 200

```json
{
  "gateway": { "status": "running" },
  "models": [
    { "key": "main", "name": "工业LLM", "alias": "petro-llm", "role": "main",
      "access": "内网部署 · OpenAI 兼容接口", "note": "…" }
  ]
}
```

- `models[]` 与 `app/gateway/config.yaml` 的 `model_list` 一一对应；`role`: `main | backup`。
- `gateway.status`：`running | degraded | down`（degraded = 主用冷却期内、备用承载中——预留，页头徽标消费）。

### 2/3. GET · PUT /api/gateway/config

```json
{
  "params": {
    "allowedFails": 2,       // 连续失败判故障阈值，1–10
    "cooldownSeconds": 60,   // 故障冷却秒数，10–600
    "numRetries": 3,         // 网关层重试次数，0–5（业务侧永不重试）
    "requestTimeout": 30,    // 单次调用超时秒，5–120
    "perCallCostLimitYuan": 0.05,        // 单次调用成本上限（元），>=0，默认 0.05（F2 改注合同值）
    "gatewayBudgetYuanPerMonth": 800     // 累计预算 GATEWAY_BUDGET（元/月），>=0（变量名为合同值）
  },
  "yaml": "# app/gateway/config.yaml 全文"
}
```

- **PUT 行为**：参数校验越界即 400（错误体带字段与允许区间；预算双阈值约束＝`>=0`，负数/非数值 400）；通过后写回 `config.yaml` 并热加载，返回保存后快照（前端以服务端回值为准，不本地拼装）。
- `yaml` 由 `params` + `model_list` 生成，保证"表单里每个数字对应文件里的一行"。
- **预算双阈值（D5 撤页归并批并入，v0.2）**：消费方＝网关侧熔断判据（m12 `Metrics.over_budget?`，W-F12-4）——单笔管一次调用、累计管全月总额；任一触顶：熔断位置位，后续调用自动改路由到降级组 **petro-lite**（改路由不拒绝、在途照跑完、单向置位不自动恢复，降级组在 model_list/fallbacks 域定义），链路记一笔「熔断降级」、记账留痕；**直接保存即生效**（阶段 1 过渡形态，D2 过渡同款登记——阈值变更记入活动流审计，A3 接入批切审批链）；对**后续调用**生效，触顶前已完成的调用不回溯。

### 4. GET /api/gateway/spend-logs → 200

入参 query：`model=all|main|backup` · `range=all|today|7d` · `keyword=`（匹配调用号/备注）· `page`（≥1）· `pageSize`（默认 15）。

```json
{
  "items": [
    {
      "id": "call-8c31",
      "time": "2026-09-28T09:52:30",
      "modelKey": "main",
      "caller": "chat-ask",
      "inputTokens": 2140,
      "outputTokens": 1380,
      "firstMs": 1000,
      "totalMs": 4000,
      "costYuan": 0.007,
      "fallback": false,
      "note": ""
    }
  ],
  "total": 30, "page": 1, "pageSize": 15
}
```

- **数据形状红线**：token 是两个整数（输入/输出分列）、耗时是毫秒整数、花费是元数值——**不得返回拼接好的展示串**（"2,140＋1,380"/"¥0.0070" 这类格式化一律前端做）。
- `fallback=true` 表示本次由备用模型应答（主用冷却期内）；`costYuan = (inputTokens+outputTokens) × 单价`，单价由网关计费配置决定。
- `caller`＝**调用方归因（D5 撤页归并批新增，v0.2）**：网关侧记录本次调用由哪条业务链路发起（如 `chat-ask` 问一问问答 / `kb-ingest` 报告入库抽取 / `wiki-gen` 百科生成 / `graph-extract` 图谱抽取 / `drill` 故障演练）——枚举**不封闭**，随业务链路扩展；是端点 8 花费聚合的归因基础。历史存量流水（归并批前落账）`caller` 可空（`null`，聚合时归入"未归因"桶）。
- 排序恒为 `time` 倒序；来源 = m2 `record_spend` 落的审计表（m3）。

### 5/6/7. 故障演练

`POST /api/gateway/drills` → `202 { "drillId": "drill-9019" }`；已有进行中任务 → `409`（前端按钮禁用兜底，不依赖此码）。

`GET /api/gateway/drills/{id}` →：

```json
{
  "drillId": "drill-9019",
  "status": "running | done",
  "nodes": [
    { "key": "fail1", "label": "第 1 次调用失败", "state": "wait | process | finish | error" }
  ],
  "result": {
    "conclusion": "主用停机期间备用应答正常…",
    "fallback": {
      "time": "…", "event": "fallback_triggered",
      "request_alias": "petro-llm", "failed_deploy": "openai/petro-72b",
      "failover_target": "openai/deepseek",
      "consecutive_fails": 2, "cooldown_sec": 60
    },
    "ledgerRow": { "…同 spend-logs item…" }
  }
}
```

- 演练节奏（节点推进 ~600ms/步）由**服务端任务**驱动，前端只轮询（300ms 间隔）；`state` 语义与 antd Steps 对齐。
- `nodes[].note`＝**节点步进说明（additive，2026-10-02 补登——实现仓 P1-11c 收官修复批；实现自 P0-04 起已随节点行下发，本册漏登就此补齐）**：服务端组装的人话进度说明（前端零拼装直显）；冻结字段 `key`/`label`/`state` 全保留，`note` 缺省空串。
- **done 时服务端落两笔账**：记账流水追加一条备用应答行（`fallback=true`）+ 演练历史加一条；`consecutive_fails`/`cooldown_sec` 取**当前配置值**。
- `GET /api/gateway/drills` → `[{ id, time, summary }]` 倒序；`summary` 为人读摘要（含阈值与冷却参数）。

### 8. GET /api/gateway/spend-stats → 200（D5 撤页归并批新增）

花费聚合/趋势读面——**m2 `record_spend` 审计表的聚合投影，不建第二份账本**（D5 册边界裁决随归并迁移：消费方由 D5 变 D1，账本唯一真源不变）。

入参 query：`group_by=caller|model|day|month` · `range=all|7d|30d|12m`（默认 `all`）· `page`（≥1）· `pageSize`（默认 15）。

```json
{
  "groupBy": "caller",
  "range": "30d",
  "items": [
    { "caller": "chat-ask",      "calls": 21, "fallbackCalls": 3, "inputTokens": 43260, "outputTokens": 25130, "costYuan": 0.37 },
    { "caller": "kb-ingest",     "calls": 8,  "fallbackCalls": 0, "inputTokens": 19240, "outputTokens": 11020, "costYuan": 0.16 },
    { "caller": "wiki-gen",      "calls": 5,  "fallbackCalls": 1, "inputTokens": 12060, "outputTokens": 8010,  "costYuan": 0.11 },
    { "caller": "graph-extract", "calls": 4,  "fallbackCalls": 0, "inputTokens": 9880,  "outputTokens": 5210,  "costYuan": 0.08 },
    { "caller": "drill",         "calls": 2,  "fallbackCalls": 2, "inputTokens": 2710,  "outputTokens": 1660,  "costYuan": 0.02 }
  ],
  "sums": { "calls": 40, "fallbackCalls": 6, "costYuan": 0.74 },
  "total": 5, "page": 1, "pageSize": 15
}
```

- `group_by` 各维度的行形状：
  - `caller`：`{ caller, calls, fallbackCalls, inputTokens, outputTokens, costYuan }`，按 `costYuan` 降序（谁花得多排前面）；`caller` 值域即端点 4 `caller` 归因枚举（不封闭），存量未归因流水归入 `caller: "unattributed"` 桶。
  - `model`：同上度量，分组键为 `{ modelKey, alias }`（与 `model_list` 同源）。
  - `day`：`{ day: "2026-09-28", calls, fallbackCalls, inputTokens, outputTokens, costYuan }`——**趋势时序**，按 `day` 升序（时间轴读法），行数受 `range` 天然约束（≤31 行），`page/pageSize` 忽略、`total`＝行数。
  - `month`：`{ month: "2026-09", …同上度量 }`，升序（≤12 行）。
- `sums`＝当前筛选窗口内全量合计（不分页截断），供页面"期间合计"行拼装。
- **数据形状红线（端点 4 同款）**：calls/tokens 毫秒除外均为整数、花费元数值——"¥0.74"/"2,140" 展示串一律前端拼装；趋势图（若页面渲染）由前端按 `day`/`month` 行自行绘制，端点不回图片或预拼 HTML。
- 演示种子量级沿用本册记账基准（单次 ¥0.002–0.008，禁发明新量级）；`fallbackCalls` 与端点 4 `fallback=true` 行数对账一致。
- `range` 枚举与端点 4 `range`（all|today|7d）**不同族**：本端点面向统计窗（最小粒度 7 天），不提供 `today`——单日细查走端点 4 流水筛选。

## 观测（Langfuse）入口与五信号统计源口径（D5 撤页归并登记）

- **观测入口**：D1 页头「观测（Langfuse）」外链按钮跳转中间件 Langfuse Web（compose `observe` profile 已就绪，默认 `:3000`——接线时按部署配置调整地址）。D5 页撤除后，链路（trace/span）在 Langfuse 视图回看（F29；不自建第二套观测服务不变）。
- **挂接标识口径（登记，接线批实施）**：Langfuse trace metadata 携带——账本调用号 **`call_id`**（与端点 4 记账流水同域，花费对账键）＋会话运行号 **`run_id`**（与 A1 同标识，一次提问一 run）＋模型别名 **`alias`**（与 `model_list` 同源）。三标识即 Langfuse 与平台账本互查的对账键，不另立第四标识。
- **五信号统计源口径（登记）**：miss（检索落空）/ ambiguous（多候选澄清）/ rewrite（改写重问）/ error（报错）/ feedback（用户反馈）五信号的运行态计数，**归 gateway 域运行时采集**（complete 出口心跳），D1 运行态徽标消费（RouterState）；计数达阈值自动归一成诊断 schema 进 C2 提案池＝服务端内部动作（不经本页端点机制不变），归一后提案仍走 C2/C3 人审。
- **熔断演示**：D5「熔断过程回放」前端演示资产随页撤除；熔断语义与真实流量演练由本册端点 5/6/7（drills）承接——演练即真实流量、记账与切换留痕（行为规则 3），零新增动作。

## 行为规则汇总

1. 配置保存 = 写文件 + 热加载 + 全平台生效；返回快照为唯一真值。
2. 演练是破坏性操作：前端"允许演练"开关默认**关**，接口侧同样应校验演练窗口（预留，403 语义）。
3. 演练结束自动产生一条备用记账流水——演练即真实流量，不另造演示数据。
4. 记账流水量级基准（沿用既有账目，禁发明新量级）：单次 ¥0.002–0.008、总耗时 2.4–4.3 秒、首字 0.8–1.5 秒。
5. **花费账本唯一（D5 归并迁移）**：聚合（端点 8）与流水（端点 4）同源于 m2 `record_spend` 审计表——不建第二份账本、无花费写端点；`caller` 归因由网关在受理时落列，历史存量可空（聚合归"未归因"桶）。
6. **预算双阈值即熔断判据输入（D5 归并迁移）**：`perCallCostLimitYuan`/`gatewayBudgetYuanPerMonth` 随 config 保存即对后续调用生效（不回溯在途与已完调用）；触顶行为＝熔断位单向置位→改路由降级组 petro-lite（改路由不拒绝、在途照跑完）＋链路记「熔断降级」；阶段 1 过渡＝直接生效＋活动流审计，A3 接入批切审批链。

## 错误码草案

| 场景 | HTTP | 说明 |
|---|---|---|
| 参数越界 | 400 | 错误体含字段名与允许区间（预算双阈值＝>=0） |
| 聚合维度/窗口非法 | 400 | 端点 8：`group_by`/`range` 枚举外（错误体带合法枚举） |
| 未认证 / 无权 | 401 / 403 | D 组页面同权限 |
| 演练任务不存在 | 404 | 轮询已过期的 id |
| 演练重入 | 409 | 已有进行中任务 |
| 配置写回失败 | 500 | 网关热加载失败，需回滚提示 |
