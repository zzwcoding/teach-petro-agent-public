# ADR-0006：架构图 v1 过审 + 前端底座裁决

- 日期：2026-09-29
- 状态：已接受（Owner 逐节点过完架构图后回复"过"拍板；前端底座方案口头确认"OK 就按这个来"）
- 关联：ADR-0003（技术选型）· ADR-0004（本体真源）· ADR-0005（双轨宣言）· docs/architecture-v1.md · specs/frontend-foundation.md

## 裁决

### 1. 架构图 v1 过审（深度设计阶段 验收最后闸）

docs/architecture-v1.md 五节（总格局图/14 模块 3 组/四条核心链路/数据流对接面/阶段落位）经 Owner 过审，成为真实开发实现总图：**图已过审，阶段 0 可开工写码**。过审前两轮修订留档：

- **复审修复五处**（2026-09-29）：①总格局图同步器箭头错位（原画在本体仓→数据面之间，实为 本体仓→主平台 投影，数据面挂主平台下方）；②补第四条核心链路「④ 问智链（成品链：问答+问数结合）」——PRD 三专职 Agent 之一，原图被压成问答链尾一行，丢失结合性/异步拓扑/阶段落位三要素；③本体仓计数对齐仓内实况（术语 11＝复用 10+新增 1，对象口径 10，m1 另含 4 个四维空壳雏形位）；④"解环两处"更正为三处（补 governance↔derivatives，B8）；⑤基础设施层 10→11 adapter（补 clock，B14）；身份桩表述改"OAuth2.0 预留，切换时点未拍板"（原"阶段3+"系未拍板主张）。
- **新增依据**：specs/frontend-foundation.md（前端底座设计 v0.1）挂入架构图依据行；总格局图「前端」格与阶段落位表阶段 0 行同步更新。

### 2. 前端底座裁决（Owner 拍板：改现有原型、双树共存、边做边比）

- 在 `prototype/app/` 工程上补底座，**不新建底座搬家、不全做完再重构**：落地页占原 hash 路径（`#/A1`）走真 API，原型页挪 `#/proto/*` 保留 mock，同菜单并列带"原型"角标，一键对比；阶段全做完原型树整体删除。
- 底座五件：请求层 `api/client`（fetch 封装，不引 axios）· SSE 客户端（19 类帧/断线续传/interrupt-resume）· zustand 轻量全局态（新增唯一前端依赖）· 全局组件库（产物卡/取货凭证卡/答案卡/解释链/四态徽标/审批抽屉，原型页与落地页共用）· 工程形态（去 singlefile、vite proxy、eslint 进 CI、**不迁 TS**）。
- 底座与阶段 0 同批建同验收；D1 为首个接真 API 的落地页面。

## 影响备忘

- 架构图 v1 = 实现期对照图；后续阶段若动格局（如数据面 v2 重排），改图重审（diff 节点级）。
- 原型树退役条件：阶段 4 验收通过（写进 frontend-foundation.md §5）。
- OAuth2.0 切换时点仍为悬置项（ADR-0003 预留语义不变）。
- 真实主平台代码仓位置：**本 ADR 不落，Owner 在阶段 0 开工时拍板**（新仓 or 本仓子目录，ADR-0005 §3 预留）。
