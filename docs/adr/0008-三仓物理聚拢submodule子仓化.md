## 裁决

`本体仓` 与 `数据面服务仓` 以 **git submodule** 形式迁入 `平台实现仓`：

```
平台实现仓/          ← 父仓（聚合视图 + 主平台实现）
├── app/ · web/ · compose.yaml · .github/               ← 父仓自有
├── ontology/    → submodule → ../本体仓      ← 独立 git，ffbfc4f
└── data-plane/  → submodule → ../数据面服务仓       ← 独立 git，a8cfcff
```

- **git 各管各的**：三仓独立历史/提交/分支；父仓只记录 gitlink 指针 + `.gitmodules`（相对路径 url，本地可用，远程化时改为绝对地址）。
- **治理边界原封不动**：`ontology/` 仍守 all-agent 纪律（ci.sh 三闸/语义闸/提案 MR 流——ADR-0004 语义不变）；`data-plane/` 仍守其 ADR 链。子仓内部文档（约定与说明）**不改**——其独立性正是本裁决的目的。
- **父仓新增子仓三铁律**（进仓库约定第 0 条）：内容回各自仓提交推送；进子仓先 checkout 分支；改子仓内容必伴随父仓指针提交。

## 理由

- Owner 要单项目视角（一个目录看全三个资产）+ 各仓治理独立；
- 拒绝的备选：subtree 并历史（独立性丧失，与"git 各管各的"相悖）；保持三仓并列（无聚合视图）。
