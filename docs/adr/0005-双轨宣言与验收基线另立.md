# ADR-0005：真实开发与设计资产双轨宣言 + 验收基线另立

- 日期：2026-09-29
- 状态：已接受（Owner 拍板："设计的不需要"——真实开发验收基线另立，不继承设计 W 断言）
- 关联：ADR-0003（技术选型）· ADR-0004（本体真源）· roadmap.md · 仓库约定

## 裁决

### 1. 双轨宣言（仓库约定修订的依据）

本仓自 2026-09-29 起为**双轨仓**：

| 轨 | 资产 | 真源 | 工程纪律 |
|---|---|---|---|
| 设计轨（冻结） | design/NN-*.md、场景文档、specs/modules.md（m1–m27 设计卡）、specs/walkthroughs.md（193 条 W 断言）、 | 各自文件头 | **冻结不再演化**——只读，新设计需求才新增，不随真实开发改动 |
| 真实开发轨（活跃） | specs/api/（21 册合同+98 模块+99 数据库+00 系统级）、docs/adr/0003+、docs/roadmap.md、docs/architecture-v1.md、学习 demo 后端/（学习 demo，另有平行真实实现仓待立） | specs/api/ 21 册为接口真源 | 开发流程（阶段 0 起CI 先行） |
| 本体轨（活跃） | 本体仓 独立仓（本体仓） | 该仓约定文档 | all-agent 纪律（语义闸/出厂集/MR） |

设计产物中的"没有可运行代码、不建 app/ scripts/"纪律**仅约束设计轨产物**；真实开发轨按 roadmap 建仓写码，两者互不引用对方的契约。

### 2. 验收基线另立

- 设计 193 条 W 断言（specs/walkthroughs.md）服务于设计走查，**不作为真实开发的验收基线**。
- 真实开发的验收基线=21 册合同各册「行为规则/错误码/合同常量」节 + 阶段 3 将建的功能 spec 验收测试表（功能规格阶段，过 规格校验脚本 机器校验）。
- 设计断言中描述**同一业务语义**的条目（如 W-F14 安检五段、W-F21 瀑布）在合同冻结时已被吸收为合同值；两轨语义冲突时，**以合同册为准**（合同经 2026-09-29 多轮校核对齐页面现实现与 PRD）。

### 3. demo-backend 定性

`学习 demo 后端/`（另一窗口的学习仓产物）= **学习 demo，与本仓真实实现无关**。真实主平台的代码仓位置由 Owner 在阶段 0 开工时拍板（新仓 or 本仓子目录），本 ADR 只划清"demo 不承担交付义务"。

## 影响

- 仓库约定修订：按本 ADR 第 1 节改写"这个仓库是什么"与改动纪律（设计纪律加"设计轨限定"前缀）。
- roadmap/阶段 3 的功能 spec 工作量+1 项：建立真实验收基线时逐条注源合同册（已在 roadmap 预留）。
- 设计轨文件不加"冻结"水印（不做全量改动），以本 ADR 为准。
