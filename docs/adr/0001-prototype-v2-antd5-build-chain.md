# ADR-0001：原型 V2 引入前端构建链（Vite + React + antd5）

- 日期：2026-09-24
- 状态：已采纳
- 关联：prototype/DESIGN.md §7

## 背景

前端客户端原型 V1（0dbf32b）为纯静态 HTML + 手搓 shell.css，观感被用户评审为"太简陋，不像系统"。经评审决定 V2 用 Ant Design 重做。落地形态有两个候选：无构建（antd4 UMD + 页内 Babel）与轻构建（Vite + React + antd5，构建产物静态化）。本仓库此前的定位为设计文档仓库，无可运行代码、无构建链。

## 决策

V2 采用 **Vite + React + antd5**；仓库提交前端工程源码 + package-lock.json + 构建产物 `prototype/app/dist/`；`node_modules` 与构建缓存入 `.gitignore` 不入库。

## 备选与理由

| 候选 | 不选/选的理由 |
|---|---|
| A. antd4 UMD + Babel standalone（无构建） | antd4 已停更、视觉陈旧（旧主色 #1890FF），恰在"简陋"这条线上；JSX 内嵌 22 个 HTML 维护成本高；页内编译首屏慢。保留"零构建"纪律的代价大于收益。 |
| C. 继续打磨手搓 shell.css | 用户已否（V1 评审结论）。 |
| B. Vite + React + antd5（选定） | antd5 现役视觉质量；组件模块化（侧栏/顶栏/溯源条共享件只写一遍）；`dist` 为纯静态、file:// 可开、完全离线，"离线交付"叙事不变硬反弱；用户观感诉求（解决简陋）最直接。 |

## 后果

1. 仓库定位微调：首次出现真实前端源码。主体定位不变（`app/`、`scripts/` 等骨架目录除本 ADR 明确范围外仍不建），原型目录成为例外——纪律边界以本 ADR 为准。
2. dist 入库 = 交付物可审可直开；改源码后必须重跑构建才生效，变更清单条目须含"构建通过 + dist 同步"。
3. 依赖治理：antd5 及其依赖经 package-lock 钉版；禁再引入第二套 UI 框架。
4. V1 的 22 页内容与交互剧本为迁移对账基线（0dbf32b），V2 逐页对照保留：正文、示例数据、出处、工程注记、契约溯源条一条不丢。
