# ADR-0004：本体真源回归 All-agent 式本体仓（YAML）与两工程衔接

- 日期：2026-09-29
- 状态：已接受（Owner 拍板：以验证 all-agent 可行性为项目目标之一，不考虑成本/时间）
> **状态修订（2026-09-30，Owner 拍板）**：本体真源物理形态由"独立仓 本体仓"改为**平台仓目录 ontology/（git subtree 并入，全部历史可溯）**——Git+YAML 真源、语义闸 ci.sh、逐元素注源、提案→改 YAML→过闸→提交的 all-agent 纪律**全部保留**（闸随目录走，合并位置实跑全绿）；"独立仓+MR 流"中的 MR 环节由单人提交流替代（闸前移为提交前置检查）。本文件其余内容留作历史。
- 关联：ADR-0003（技术选型）· PRD F25（Agent 只提 MR）/ F39（治理本体仓 All-agent 式）· specs/api/98 开放问题 1 · specs/api/C2 合同批准事务 · All-agent 仓 `ontology/bohai/`

## 背景

1. Owner 明确：本项目要**验证 all-agent（企业语义中台，skill+脚本形态）在真实平台工程中的可行性**。
2. PRD 本来就认领了这条路：F39"治理本体仓（All-agent 式）——Git+YAML 是唯一真源，前缀即类型，逐元素注源，进仓必过 MR+语义 CI；图是每次启动重建的派生物"；F25"Agent 只提 MR"。ADR-0003 阶段台账按 DB 行版本先行落表（99 册），但**真源形态未裁**（98 开放问题 1 悬置：YAML 真源+派生行版本 vs 纯 DB 行版本）。
3. 既有资产：All-agent 仓 `ontology/bohai/` 渤海域本体 v1 已建成（m1 对象/m2 行为/m3 规则/m5 actor/m6 流程/m7 报告/glossary，共 3392 行 YAML，语义闸全绿）——与本项目假想业务域（渤中28-1）同源。验证起点是"对齐+接线"，不是从零建模。

## 裁决

1. **本体内容真源 = all-agent 式本体仓（Git+YAML）**。起步位置：主仓 `ontology/` 目录（沿用 all-agent 仓纪律：schema 注册表/前缀即类型/逐元素注源/语义闸），验证成熟后可拆独立仓。以 bohai/ 既有本体为底，按平台七域（术语/指标/对象/关系/白名单/工作流/Action）+映射卡对齐补齐。
2. **平台台账 DB 行版本 = 本体仓的同步投影**。semantics 模块新增同步器（本体仓 YAML → sem_ledger_* 行版本；消费 MR 合入事件触发；幂等）。98 开放问题 1 关闭（选定"YAML 真源+派生行版本"选项）。
3. **治理切分一刀清，防两套治理漂移**：
   - all-agent 本体仓 = 本体**内容**真源 + MR/语义 CI 门禁（内容对不对、格式合不合法、引用是否一致）
   - 平台 C2/C3 = 变更的**业务治理**（提案三来源×准入矩阵 / 负责人批准 / 五级发布流水线 / 行为回归）
   - 连接件：C2 批准 → 自动提交 MR（F25"只提 MR"落地）→ all-agent 语义 CI → 合入 → 平台同步器刷新台账 → semantic.current 推进
4. **生效链语义修订（挂阶段 3 开工前对齐批）**：C2 合同批准事务中"台账行版本+1 / semantic.current 推进"从批准事务内**后移至 MR 合入后**（引入"生效中（MR 待合入）"中间态或复用 checked 态）。这是合同值变更，走 C2 合同 v0.2 修订，本 ADR 只记方向、不私改合同。
5. **all-agent 织进核心链路的三个验证点**（不是旁边摆着试玩）：
   - **类型闸**：B5 抽取图谱"入库前过闸、对不上的关系不立边"= 本体仓模式派生约束。本体=模式层（图纸），Neo4j 抽取图谱=实例层（住户）——CONTEXT 术语各安其位；A2 白名单边一跳同源。
   - **提案闭环**：C2 → MR → 语义 CI → 合入 → 同步 → C3 五道（阶段 3 全链路验证）。
   - **语义对账**：all-agent semantic-service（读仓）与平台检索瀑布/semantics（读投影）同问对答一致性抽查。
6. **可行性验证判据**（怎么算验证成功）：
   - ① bohai 本体对齐平台七域并过语义 CI（本体冲刺产出）
   - ② 台账种子**零手养**——同步器首跑直接从仓导入
   - ③ 变更闭环全通：C2 提案 → 批准 → 自动 MR → 语义 CI → 合入 → 台账+1 → C3 五道过
   - ④ 语义对账抽查一致
   - ⑤ 验证报告落 `docs/`（走通了什么/卡在哪/all-agent 要改什么）

## 风险与对策

- **八模型 schema ↔ 平台七域映射**需一次对齐设计（M1 对象↔对象账、M3 规则↔禁用词/白名单、GLS↔术语账…）——本体冲刺首任务，对齐表落 ontology/manifest。
- **双闸接线**：all-agent 语义 CI（内容闸）与平台 C3 五级（业务闸）串行不重复——语义 CI 在 MR 门，五级在发布门，阶段 3 接线。
- **投影纪律**：台账 DB 行永远只读自仓，禁止手工改台账行（防仓↔DB 漂移）——写进 semantics 模块边界规则（B4 的"写口唯一"补注：apply_definition_merge 仅由同步器/C2 生效链调用）。
