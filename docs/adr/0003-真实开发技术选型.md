# ADR-0003：真实开发技术选型落盘（全量收口"用什么造"）

- 日期：2026-09-29
- 状态：已接受（Owner 会同主控窗口拍板，本 ADR 落盘并同步修订三册设计文档）
- 关联：specs/api/00-系统级API.md（横切合同）· specs/api/98-模块划分与分层.md（模块边界）· specs/api/99-数据库与连接层设计.md（存储结构）· specs/api/ 21 册 API 合同 · specs/data-plane/（数据面 DP1–DP9）· ADR-0002（统一入口决策链——问答链执行引擎选型的上游）

## 背景

specs/api/ 下 21 册 API 需求合同冻结了**造什么**（数据形状与业务语义），98 册冻结了模块边界（四层 14 模块/边界规则 B1–B16），99 册冻结了存储结构（92 表＋`infra.db` 连接层）——但大量实现位以"结合实际框架定"悬置：98 §4 adapter 清单只列职责不定选型、99 §6 开放问题 12 条、00 §15 开放问题 10 条、各模块卡 seam 注记（图存储/索引存储/登录会话/探活机制等）。本轮由 Owner 会同主控窗口完成真实开发**全量技术选型**拍板，一次收口全部悬置点；本 ADR 为唯一裁决记录，三册设计文档同批修订（见「连带影响清单」）。各选型均不改动合同值（状态枚举/字段名/文案/401/403 语义）与模块边界——合同冻结"造什么"，选型只回答"用什么造"。

## 裁决（16 条）

1. **向量索引＝pgvector**。开发 PostgreSQL 直用 pgvector（HNSW/IVFFlat 选择挂实施批）；金仓生产侧以等价插件**交付期验证**——降级为交付批验证项，不阻塞开发。否决：独立向量服务（Milvus/FAISS——多一件中间件，当前量级不匹配）；否决：等金仓验证通过再动工（阻塞主链）。影响面：99 §2.5 `kb_fragment.embedding`（维度待 embedding 模型定，待办）、99 §1.7.1/§6-5、98 §4 db 行。
2. **图存储＝Neo4j**。99 derivatives 域 `graph_node`/`graph_edge` 迁出 PG；98 infra 新增 `graph_store` adapter；B5 整图读/N 跳遍历与 A1 图谱问答链取数改 Cypher；抽取设置（`kb_extract_config`）与活动流（`kb_activity`）仍留 PG。否决：PG 邻接表＋递归 CTE（N 跳遍历深查询代价高、图算法生态缺失）。影响面：99 §2.7（PG 表计数 92→90）/§1.5/§3、98 §4/3.5 卡。
3. **ORM＝SQLAlchemy 2.0**。99 db.py 去"可替换"悬置，按 2.0 风格定型（`Mapped[]`/`select()`/`begin_nested()`）；`ConnectionManager` 保留为测试替身与部署配置注入位（不再承诺"替换持久化方案"）。否决：Peewee/Django ORM（异步面与生态）、裸 asyncpg（手写 SQL 面过大）。影响面：99 §4.1/§4.2 头注。
4. **可观测＝Langfuse 自部署**。LLM 链路追踪挂 Langfuse 自部署实例；D5 端点 7（追踪开关）作挂接开关；OTel GenAI 映射常量不动（合同值）。影响面：中间件五件之一；gateway 观测子域实现细节（模块边界不动）。
5. **认证＝企业 OAuth2.0，开发期预留不校验**。00 册鉴权节补「开发期身份桩」：身份解析 seam 不变（98 冻结卡 3.13 `security.authenticate`），开发期实现＝读请求头 `X-Dev-User`（缺省落默认角色）；21 册合同 who/角色过滤/401/403 语义全部保真；接 OAuth 时只换该函数实现，各册合同零改动。影响面：00 §2.1/新增 §2.4、99 §2.1 注记、`sys_user` 种子承载角色映射。
6. **加密＝SM3/SM4**。Python 国密库实现，落 99 `EncryptedField` 的 crypto 回调注入；金仓侧 TDE/国密函数验证留交付批。否决：DB 侧透明加密先行（跨库一致性差、方言差异区）。影响面：99 §6-8 收口、`infra.crypto`。
7. **问答链执行引擎＝LangGraph**。interrupt（澄清/审批挂起）与 checkpointer（断点续跑/恢复）天然对上 19 类事件帧流的挂起语义；**19 类事件帧桥接层在 chat 模块内实现，不漏进合同**（帧集仍是 A1 域合同值，LangGraph 概念不出现在合同册）。否决：自研运行状态机（interrupt/恢复语义重造轮子）、裸 LCEL（挂起/恢复能力不足）。影响面：98 chat 卡领域内核实现、99 `chat_run.pending_interrupt` 承载映射（合同面零改动）。
8. **E1 跑批执行器＝自研**。平台内异步任务执行器：消费任务队列→逐题调问答链→判分器→渐进写 `eval_run_item`（复用 `infra.queue` 与判分管线，"逐题渐进轮询/重复登记 409"合同语义零改动）。promptfoo 降为**可选离线导出格式**，不作执行依赖。否决：promptfoo 作执行引擎（外部工具形态依赖、四判据逐槽判分语义对不上）。影响面：assessment 考核面执行链。
9. **PDF 解析＝PyMuPDF（试后可换）**；插图说明＝**LLM 视觉理解**生成（B1 管线图片说明块 F36 的生产方式）——依赖内网多模态模型可用性，挂验证项。影响面：kb 入库管线解析步。
10. **任务队列＝Redis Streams**。E1 跑批/B1 入库/FAQ 扫库/C3 流水线共用；00 册异步任务模式 §5 的执行器落位（受理 202/轮询/重入 409/stuck 巡检语义不变，队列只是执行承载）。影响面：98 §4 queue 行；00 §5 合同面零改动。
11. **事件总线＝Redis Streams 当通道＋outbox 表兜底**。98 开放问题 5 收口：批准事务副作用③④⑤（派生物刷新/汇入副作用/Verify 触发）经 `infra_outbox` 保投递；25 领域事件语义不变。影响面：99 §6-4 收口（outbox 表接线批落册）、98 §4 eventbus 行/§10-5。
12. **对象存储＝MinIO；缓存＝Redis；调度＝APScheduler**。调度承载 E2 质检周期/数据面进料管道周期（另含卡住巡检/水位刷新）；MinIO S3 兼容 API 与 F5 预签名直传合同零冲突。影响面：98 §4 三行。
13. **LLM 网关＝LiteLLM，SDK 方式嵌主平台进程内**（不单独起 proxy 服务）。D1 语义映射：路由表/主备 fallback/超时重试＝LiteLLM Router 配置；"触顶改降级组 petro-lite"＝网关记账回调查预算、触顶换降级组配置再发（熔断三语义合同值不变）；金额＝LiteLLM spend 计算＋**模型价格表**（价格数据待 Owner 提供，挂待办）；故障演练＝平台侧开关临时摘主模型路由。**椒图（agentjiaotu）本体不复用，其设计蓝本平移**：切换判据（网络错/超时/5xx 切备，4xx/429 不切）、可切窗口（零字节转发前）、per-attempt 超时、每次切换恰一条审计、条件 UPDATE 记账防竞态、无 usage 时 chars/4 估算；**F1 对外凭证页签实现参考椒图 g1 蓝图**（key 只存 hash/明文一次性/rotate 即废/拒绝全审计——与 99 `api_key.fingerprint` 口径一致）。影响面：98 §4 llm_client 行、gateway 卡、99 §2.13 价格表待办。
14. **总架构＝双服务**。主平台单体（98 四层 14 模块，含进程内 LiteLLM 网关）＋数据面独立服务（数据面服务仓 v2）；中间件五件：PostgreSQL／Redis／MinIO／Neo4j／Langfuse。影响面：98 §1 注记、00 §15-9 部分收口。
15. **数据面裁决**。数据面服务仓 **原仓大版本重排（v2），不重开仓**。职责收窄五件事：进料→清洗→出汇总层→质检→报水位；dp4 语义层/dp5 查询执行/dp8 对外工具面**职责归主平台**（语义＝C1/semantics、查询＝chat LangGraph 链＋安检、对外工具＝F1 expose）。保留资产：20 条质检规则＋隔离区配套）、进料三步契约、104 测试用例、行级隔离思想（修 P7 fail-open）。口径字典必须是主平台 C1 台账的下游投影（台账同源）；agg 三表（fct_daily_metering/dim_well/dim_date）由数据面按 99 DDL **直写主平台库**（限写三表的专用账号）；`/api/ingest/*` 四端点＝主平台**调数据面 HTTP API 拉投影**（零共享库）；新鲜度唯一真源＝dp2 FreshnessRegistry。影响面：99 §6-1 收口、98 §1 注记、D6 册接线语义（合同端点形状不动）。
16. **语言与工程＝Python 3.12＋uv**。主平台＝98 分层即**模块化单体**的分层（明示）。影响面：工程脚手架批。

## 拍板与现册的出入登记

1. **身份解析函数命名**：拍板稿称 `security.resolve_actor()`；98 冻结卡 3.13 公开签名＝`security.authenticate(request) -> Actor`——同位同义（同一条身份解析缝）。本批不改 98 冻结签名，00/99 注记以「身份解析 seam」表述并双注两名；若 Owner 意在改名，走 98 变更记录单独一批。
2. **D6 四表去留**：`/api/ingest/*` 四端点改为数据面投影拉取（零共享库）后，99 §2.12 `ingest_*` 四注册表降级为可选缓存投影或透传——表去留挂数据面 v2 接线批（本批不删表，仅注记）。
3. **D5 健康四灯**：中间件扩至五件（PG/Redis/MinIO/Neo4j/Langfuse）后，Neo4j/Langfuse 是否入健康带为新增探活位——合同四灯值不动，扩展挂实施批。

## 遗留验证项

1. **金仓向量插件**：pgvector 等价插件在金仓交付期的可用性与性能验证（裁决 1——降级为交付批验证项，不阻塞开发）。
2. **内网多模态模型可用性**：B1 图片说明块 LLM 视觉理解的前置依赖（裁决 9）。
3. **模型价格表**：LiteLLM spend 计算依赖的价格数据——待 Owner 提供（裁决 13）。
4. **PyMuPDF 试装**：解析质量与国产化环境适配试装验证（裁决 9——试后可换）。
5. **Petro-72B协议 OpenAI 兼容确认**：LiteLLM 接入Petro-72B 线路的前提确认（裁决 13）。
