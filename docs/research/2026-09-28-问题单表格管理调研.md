# 问题单表格管理调研（轻量 · 2026-09-28）

> 服务于问题单呈现从看板泳道改为表格管理。前一报告（同日数据质量闭环调研）已覆盖 Soda/Metaplane incident 模型，本篇只补"呈现形态"一手依据。

## 一手来源

1. **Soda Cloud Incidents（官方文档）** — https://docs.soda.io/manage-issues/incidents.md
   - 组织级中心视图：顶导航「Incidents」，**筛选（lead / status / reporter / severity）+ 标题搜索**；数据集级另有「Incidents tab」。
   - **Lead 必填**（负责人）；resolve 强制 **resolution note**；失败检查结果可**挂到既有 incident**（linked check results）。
   - AI **Root cause analysis agent** 可把归因结论发布到 incident 上（对应我们的"诊断说明"）。
2. **Jira Issue Navigator（Atlassian 官方文档）** — https://confluence.atlassian.com/spaces/ADMINJIRASERVER112/pages/1688896644/
   - Issue 管理的业界默认形态 = **表格（List view）**：可配置列、按列排序、筛选器、保存视图；看板只是同一批 issue 的另一种视图。
   - 管理者查"谁手上有什么、卡在哪"用的是筛选+表格，不是泳道。

## 结论 → 设计映射

| 业界形态 | 本页落法 |
|---|---|
| 状态筛选（Soda status / Jira status 列） | 状态页签：全部 / 分发 / 认领 / 整改 / 复核 / 关闭，计数联动 |
| Lead 筛选 | 责任岗下拉（作业区资料员 / 小李） |
| 标题搜索 | 关键字搜索（标题 / 描述） |
| 表格列=身份+分类+人+状态+量化 | 列：问题单 / 规则 / 责任岗 / 当前环节 / 命中（挂单次数）/ 隔离行 / 复验 / 操作（流转） |
| Linked check results（挂单） | hit_count 列 >1 即"同类失败挂同单" |
| 详情/解决流程 | 行点击开详情抽屉（隔离明细 / AI 诊断 / 整改复验 / 处理链路五步）——不变 |

五态状态机、复验关闭语义、自动建单——全部不变，**只换呈现**。
