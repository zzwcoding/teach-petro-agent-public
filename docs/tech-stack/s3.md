## 使用场景

### S3 是什么：对象存储协议的事实标准

- **"S3 兼容"是数据基础设施的世界语**：2006 年 S3 把"桶 + key + HTTP API"这套接口做成了事实标准，此后整个数据基础设施都讲这门语言——Cloudflare R2 官方原话 "R2 implements the S3 API to allow users and their applications to migrate with ease"（[R2 S3 API](https://developers.cloudflare.com/r2/api/s3/api/)）；阿里云 OSS 直接设了 "Amazon S3-compatible API" 专页（[OSS 文档](https://www.alibabacloud.com/help/en/oss/user-guide/amazon-s3-compatible-api)）；MinIO 产品页口号 "Full S3 Compatibility. AI frameworks and modern applications run unchanged."（[min.io](https://min.io/product/overview)）；华为 OBS、腾讯 COS、Hadoop 生态的 Apache Ozone（S3 gateway）同理。**会一门 S3 API = 通吃所有这些存储**。
- **S3 本身已从"一个服务"长成"一个家族"**：AWS 文档现把桶分四类——general purpose bucket（`s3` 命名空间）、directory bucket（`s3express`，S3 Express One Zone）、table bucket（`s3tables`，S3 Tables）、vector bucket（`s3vectors`，"purpose-built to store and query vectors"，面向 AI 负载）（[S3 User Guide Welcome](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.md)）。

### 为什么 DataAgent 需要它（全文重点）

Agent 的数据面天然是"两半世界"：结构化数据走 SQL/湖仓（Iceberg 那条线，见 minio-iceberg.md），**非结构化资产必须有地方放**——S3 就是这另一半的统一接口：

- **① Agent 的文件面统一接口**：报告 PDF、图表截图、测井曲线文件、原始导出 CSV、RAG 语料原文——都以对象落桶，元数据（索引/向量/任务号）留在 Postgres/向量库；同一套 boto3/minio-py 代码在公有云与油田内网 MinIO 之间只需换 `endpoint`。
- **② 预签名 URL = 文件流不过应用进程**：Agent 生成的报告由后端 put 落桶，再把带签名的 GET URL 发给前端直接下载——FastAPI 进程只发签名不转发字节。官方明确 SDK 侧有效期上限 7 天（SigV4），且警告 "presigned URLs are bearer tokens"；URL 在到期前可重复使用（[Using presigned URLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)）。
- **③ 事件通知 = 数据面进料口**：对象落桶即触发解析/入库管线——S3 可把事件发到 SNS/SQS/Lambda；开启 EventBridge 后"不用选事件类型，全部事件都发过去"，由规则路由（[EventBridge 集成页](https://docs.aws.amazon.com/AmazonS3/latest/userguide/EventBridge.html)、[Welcome](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.md)）。
- **④ 版本控制 + 强一致读 + 不可变对象 = 产物可审计**：2020-12-01 起 S3 全面强一致——"all S3 GET, PUT, and LIST operations, as well as operations that change object tags, ACLs, or metadata, are now strongly consistent"（[AWS News Blog](https://aws.amazon.com/blogs/aws/amazon-s3-update-strong-read-after-write-consistency/)）；MFA delete 给"永久删除对象版本"再加一道因子（[配置页](https://docs.aws.amazon.com/AmazonS3/latest/userguide/MultiFactorAuthenticationDelete.html)）；Object Lock 提供 WORM 保留（[Welcome](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.md)）。
- **⑤ 分层存储/生命周期控制成本**：历史报告转低频/归档、过期自动删、未完成 multipart 自动 abort，全靠 Lifecycle 规则（[对象生命周期管理](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lifecycle-mgmt.html)）。
- **⑥ 权限模型划边界**：IAM policy / bucket policy / Block Public Access（桶级默认开启）——Agent 的桶不暴露公网，唯一出口是短时效预签名（[Welcome](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.md)、[using-presigned-url](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)）。
- **反模式提醒**：S3 不是数据库——对象不可随机改写、原生不支持 SQL 查询（S3 Select 已停新客，见下），"查对象里的表数据"要交给湖仓表格式层（Iceberg）解决，这正是 minio-iceberg.md 那条线的存在理由；对象存储里放的是"文件面"，表语义放"表桶/湖仓面"，两条线在 Agent 工具层汇合。

## 核心能力面

### 协议关键语义（逐条注源）

- **bucket/key 扁平命名空间**：对象地址 = bucket + key + version；key 形似路径但本质是字符串映射，"目录"只是前缀约定（general purpose 桶；directory 桶才有真层级目录）（[Welcome](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.md)）。
- **强一致性（2020-12-01 起全部操作）**："After a successful write of a new object, or an overwrite or delete of an existing object, any subsequent read request immediately receives the latest version of the object"——自动、无额外配置、无性能代价（[consistency 页](https://aws.amazon.com/s3/consistency/)、[FAQ](https://aws.amazon.com/s3/faqs/)）。**注意 2020 年前的"最终一致"说法已过时**。
- **版本控制 + MFA delete**：MFA delete 保护两个操作——永久删除对象版本、改桶版本状态；只有桶 owner（root）能开，且**不能在控制台开、只能 CLI/API**，且不能与生命周期配置同用（[MultiFactorAuthenticationDelete](https://docs.aws.amazon.com/AmazonS3/latest/userguide/MultiFactorAuthenticationDelete.html)）。
- **multipart upload**：分片号 1–10,000，可乱序传、可重传单片；"It's a best practice to use multipart upload for objects that are 100 MB or larger"；单 PUT 最大 5 GB；对象尺寸上限现为 **50 TB**（旧资料的 5 TB 已过时）；未 complete/abort 的分片一直计费，可配生命周期规则自动 abort（[multipart 概览](https://docs.aws.amazon.com/AmazonS3/latest/dev/mpuoverview.html)、[FAQ](https://aws.amazon.com/s3/faqs/)、[CreateMultipartUpload API](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CreateMultipartUpload.html)）。
- **预签名（SigV4）**：长期 IAM 凭证签名最长 **7 天**（"the expiration time can be set as high as 7 days"）；临时凭证（角色/STS）签的 URL 随凭证一起过期，写再长也没用（[using-presigned-url](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)）。
- **服务端加密三档**：SSE-S3 / SSE-KMS / SSE-C；**2023-01-05 起所有新对象自动以 SSE-S3 加密为基线**，SSE-C 不能做桶默认加密（[default-bucket-encryption](https://docs.aws.amazon.com/AmazonS3/latest/userguide/default-bucket-encryption.html)）。
- **事件通知类型**：原生目的地 SNS/SQS/Lambda；EventBridge 是第四路——开启后收全量事件（Object Created/Deleted、Restore 三态、Storage Class Changed、ACL/Tags/Annotation/Retention 更新等），"you don't need to select which event types you want to deliver"（[EventBridge.html](https://docs.aws.amazon.com/AmazonS3/latest/userguide/EventBridge.html)）。
- **生命周期规则**：按前缀/标签过滤 + 三类动作（转存储类、过期删除、abort 未完成 multipart）；注意 directory 桶不支持 S3 Lifecycle（[对象生命周期管理](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lifecycle-mgmt.html)、[CreateMultipartUpload API](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CreateMultipartUpload.html)）。

### boto3 S3 API 形状（1.43.100）

来源：[boto3 File transfer configuration 指南](https://docs.aws.amazon.com/boto3/latest/guide/s3.html)、[Presigned URLs 指南](https://docs.aws.amazon.com/boto3/latest/guide/s3-presigned-urls.html)、[client 参考](https://docs.aws.amazon.com/boto3/latest/reference/services/s3/client/put_object.html)

- **托管传输**："the AWS SDK for Python automatically manages retries and multipart and non-multipart transfers"——`upload_file` / `download_file` 超过 `multipart_threshold` 自动走 multipart，线程并发 `max_concurrency` 默认 10，`use_threads=False` 可关；配置对象 `boto3.s3.transfer.TransferConfig`。
- **单请求 API**：`put_object(Bucket, Key, Body, ContentType=..., Metadata=...)`、`get_object`（返回 StreamingBody，支持 Range）、`list_objects_v2`（分页）、`head_object`、`delete_object`（方法页见 client 参考链接）。边界：单次 PUT 上限 5 GB（[FAQ](https://aws.amazon.com/s3/faqs/)），更大必须 `upload_file`/multipart。
- **预签名对**：`generate_presigned_url('get_object', Params={'Bucket':..., 'Key':...}, ExpiresIn=...)`（也可对 put_object 等）与 `generate_presigned_post(bucket, key, Fields=..., Conditions=..., ExpiresIn=...)`（表单直传，可带条件约束）；官方示例 `expiration=3600` 默认 1 小时。
- **与 minio-py 分工一句话**：boto3 面向 AWS 全家桶、生态最大；minio-py 对 MinIO 私有部署特性（如 `listen_bucket_notification`）支持更完整——两者都能指任意 S3 兼容端点（详见 redis-minio.md）。

### AWS 原生新件（时效敏感，旧资料的重灾区）

- **S3 Tables（2024-12-03 发布）**："S3 storage that's optimized for analytics workloads"——table bucket 以 **Apache Iceberg 格式**存表，自动 compaction/snapshot 管理/未引用文件清理，独立 `s3tables` 权限命名空间，Block Public Access 永久开启；每账号每区域最多 10 个 table bucket、每桶 1 万张表（[S3 Tables 文档](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-tables.html)、[Welcome](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.md)；发布日期见信源列表新闻稿条目）。
- **S3 Metadata（2025-01-27 GA）**：对象进桶自动捕获元数据（系统元数据+自定义标签），"queryable in a read-only table" 且近实时更新——**GA 版元数据表直接存在 S3 Tables 里**，经 Glue Data Catalog 供 Athena/Redshift 等查询（[GA 公告](https://aws.amazon.com/about-aws/whats-new/2025/01/amazon-s3-metadata-generally-available/)）。
- **S3 Express One Zone（2023-11-28 GA）**：单 AZ 存储，"single-digit millisecond data access"，官方宣称比 S3 Standard 快至 10 倍、请求费低 80%；用 directory bucket + Zonal endpoint + `CreateSession` 会话鉴权（[Welcome](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.md)、[CreateMultipartUpload API](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CreateMultipartUpload.html)；GA 日期见信源列表新闻稿条目）。
- **S3 Select（已停新客——很多旧资料还当它活着）**：官方 Important 框原话 "Amazon S3 Select is no longer available to new customers. Existing customers ... can continue to use the feature as usual"——2024-07-25 生效，官方替代建议是 Athena 或"下载后客户端过滤（Pandas/PyArrow）"，**没有公开的整体停服日期**（[S3 Select 文档](https://docs.aws.amazon.com/AmazonS3/latest/userguide/selecting-content-from-objects.html)、[Storage Blog](https://aws.amazon.com/blogs/storage/how-to-optimize-querying-your-data-in-amazon-s3/)）。
- **S3 Vectors（面向 AI 的新成员）**：vector bucket "purpose-built to store and query vectors"，独立 `s3vectors` 命名空间——对象存储家族直接长出了向量这一层，Agent 的"文件面"与"向量面"可以同属一个 API 生态（[Welcome](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.md)；本仓库不展开，向量库选型另议）。

## 典型用例模式

### 模式 1：Agent 产报告 → put_object 落桶 → presigned_get 给前端

```python
# 伪代码形状（来源：boto3 Presigned URLs 指南 + client 参考）
import boto3

s3 = boto3.client("s3")        # 内网 MinIO/OSS：加 endpoint_url=... 指向任意 S3 兼容端点
key = f"reports/{task_id}/daily-{dt}.pdf"

s3.put_object(Bucket="petro-agent-artifacts", Key=key, Body=pdf_bytes,
              ContentType="application/pdf",
              Metadata={"task_id": task_id, "produced_by": "agent"})   # 元数据随对象落桶，可审计

url = s3.generate_presigned_url(
    "get_object",
    Params={"Bucket": "petro-agent-artifacts", "Key": key},
    ExpiresIn=3600,                # 官方示例默认 1h；SDK+长期凭证上限 7 天
)
# 前端拿 url 直接 <a href> 下载——文件字节不经过 FastAPI 进程
```

生产要点：桶开 Block Public Access，预签名是唯一出口；URL 是 bearer token 防外泄；大文件改 `upload_file`（自动 multipart）；报告不可篡改诉求 → 桶开版本控制 + Object Lock。

### 模式 2：对象落桶事件 → 触发解析 → 写湖（事件驱动入湖链路）

```text
测井曲线 / 日报 CSV 落桶（put_object / upload_file）
      │  s3:ObjectCreated:*（桶通知）
      ├─→ SQS/SNS ──→ 解析 worker：抽取、校验、脱敏（消费端须幂等，防重复投递重放）
      └─→ EventBridge ──→ 规则路由 → Lambda/计算任务
                    │
                    ▼
        PyIceberg append 写湖表（minio-iceberg.md 模式 2）── 表元数据进 catalog
```

要点：这条链是 Agent 数据面的"进料口"——对象一落桶，结构化世界（湖仓）自动得到新数据；解析失败的重试与死信与 redis-minio.md 模式 3 的 Streams 消费组同构。

## 选型差异（一句话版）

- **S3 协议 vs POSIX 文件系统 vs HDFS**：S3 是 HTTP API + 扁平 key + 不可变对象（改=换版本），适合"写一次读多次"的资产与湖仓底座；POSIX 有目录树/随机写/锁，适合进程本地与共享文件语义；HDFS 是私有协议的机器 Room 级文件系统——云上数据湖的主流做法已是"S3 兼容对象存储 + 开放表格式"（后者展开见 minio-iceberg.md）。
- **AWS S3 vs MinIO vs 国产 OSS/OBS/COS**：接口都讲 S3 协议；差异在部署形态与增值层——AWS 原生件最多（Tables/Metadata/Express/Vectors），MinIO 胜在油田内网私有部署（redis-minio.md），R2 主打零出口流量费，国产云主打合规与本地化（[R2 S3 API](https://developers.cloudflare.com/r2/api/s3/api/)、[min.io](https://min.io/product/overview)、[OSS S3-compatible API](https://www.alibabacloud.com/help/en/oss/user-guide/amazon-s3-compatible-api)）。
- **S3 Tables vs 自管 Iceberg on S3**：S3 Tables = 托管 table bucket + 自动表维护 + 独立权限面，代价是绑 AWS 且内网私有化不可得；自管 Iceberg on MinIO/通用桶 = 引擎自由 + 可进内网，代价是 compaction/孤儿文件清理自己扛（minio-iceberg.md 已展开）。
