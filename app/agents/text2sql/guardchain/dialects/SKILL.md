# 金仓/达梦方言技能包（m17）

> **红线（先读，任何条目都不例外）**
> 1. **近似 ≠ 支持。** sqlglot 官方方言表（34 种）不含金仓/达梦，社区亦无可核实的方言包（2026-09-14 实查）；本技能包的全部内容都建立在"金仓≈postgres、达梦≈oracle 的**近似解析**"上，只用于执行前拦截结构失配语句。文档与产品话术**不得出现"支持金仓/达梦"**。
> 2. **近似解析不替代真实库试跑/EXPLAIN 终验。** 近似通过≠目标库原语义；终验永远在真实库上（执行腿 + 结果校验）。
> 3. **只拦不修。** 语法闸与校验脚本都不自动改写 SQL（只给 fix_hint 建议文本）；方言自动改写需官方迁移工具背书的确定性规则集，当前不存在。

## 使用前提：方言映射与兼容模式对账

执行前闸按部署配置 `text2sql.dialect_map` 折算近似方言；本清单只在映射登记成立时有效：

| 库类型 | 近似方言（read=） | 成立前提 |
|---|---|---|
| kingbase | postgres | **金仓以 PG 兼容模式部署**（兼容模式 initdb 期固化，四选一，不可运行时切换） |
| dm | oracle | 达梦 DM8 以 Oracle 兼容为卖点，整体近似 oracle |
| postgres | postgres | 原生 PG，直通，无近似标注 |

金仓若以 Oracle/MySQL/SQL Server 兼容模式部署，`read` 必须改登对应近似方言并重新过对账——模式与登记不符=映射失效（对应差异清单第 8 条）。

## 差异清单（文档真源，10 条）

> 各条"闸的行为"列是差异扫描投影的依据：**结构失配**条目在近似解析失败时可被扫描命中并折入 fix_hint；**语义漂移**条目近似解析拦不住，靠校验脚本离线扫描 + 真实库终验兜底。每条改法是建议文本（fix_hint 原料），不是自动改写。

| # | 差异点 | 金仓 / 达梦侧表现 | postgres / oracle 近似下的行为 | 闸的行为 | 建议改法（fix_hint 原料） |
|---|---|---|---|---|---|
| 1 | **分页语法** | Oracle 家族用 `ROWNUM` 伪列分页（金仓 Oracle 兼容模式提供 ROWNUM/ROWID）；达梦同族 | `WHERE ROWNUM <= 10` 在 postgres 近似下被当作普通列标识符——**解析通过，语义错** | 放行+近似标注；拦不住 | 改 `LIMIT n`（postgres 近似）；扫描脚本按条目 1 离线命中提醒 |
| 2 | **空串语义** | Oracle 兼容侧 `''` 即 NULL（金仓 Oracle 模式 `ora_input_emptystr_isnull` 达梦同族行为） | `WHERE col <> ''` 语法合法，语义漂移（PG 中 `''` 非 NULL） | 放行+近似标注；拦不住 | 空判改用 `col IS NULL / IS NOT NULL` 并核对口径；清单条目供脚本命中 |
| 3 | **类型映射** | Oracle 家族 `VARCHAR2/NUMBER/DATE`（精度语义不同）；金仓 PG 模式则用 PG 类型 | 未知类型名多数解析为通用类型节点——**解析通过，映射失真** | 放行+近似标注；拦不住 | 建表/转型语句核对目标类型表；转型改 `CAST(col AS text/numeric)`（PG 模式） |
| 4 | **函数名** | Oracle 家族 `NVL/NVL2/DECODE/SYSDATE/TO_CHAR 格式元素` | sqlglot 对未知函数解析为匿名节点不报错——**解析通过** | 放行+近似标注；拦不住 | `NVL→COALESCE`、`DECODE→CASE WHEN`、`SYSDATE→CURRENT_TIMESTAMP`（PG 模式）；脚本按条目 4 命中 |
| 5 | **日期格式** | `TO_CHAR/TO_DATE` 格式元素家族差异（RR 年份、IW 周、NLS 依赖）；日期字面量写法差异 | 格式串为字符串字面量，解析一律通过 | 放行+近似标注；拦不住 | 格式元素对照 Oracle/PG 官方表核对；涉及周/年的口径必须试跑终验 |
| 6 | **绑定占位符**（驱动层，闸看不到） | 达梦 dmPython 占位符 `?`；金仓 ksycopg2/psycopg2 为 `%s` | 语句文本中的字面 `?` 行为随 sqlglot 版本而异（占位符节点或解析失败） | 版本相关；解析失败则拦 | 占位符属执行层参数化协议，不该出现在生成语句文本里；脚本按条目 6 离线命中 |
| 7 | **模式寻址** | 达梦/Oracle 风格 `模式名.表名`（如 `PRODUCTION.CATEGORY`）；PG 靠 search_path 隐式解析 | 达梦风格前缀在 oracle 近似下解析通过，postgres 近似下视作 schema 限定 | 放行（前缀随引用表提取） | 统一按部署 search_path/schema 约定写全或写省；引用表对账以实际前缀为准 |
| 8 | **兼容模式部署前提** | 金仓兼容模式 initdb 期固化（PG/Oracle/MySQL/SQL Server），决定整套语法语义 | 映射表条目与实际兼容模式错配 → 近似方言选错 → 拦截潮或错放行 | 错配属部署错误；闸按登记执行 | 适配对账：initdb 模式 ↔ dialect_map `依据` 字段逐条核对（对应主干一） |
| 9 | **层级/外连接等家族语法结构** | Oracle 家族 `START WITH…CONNECT BY PRIOR` 层级查询、`(+)` 外连接（达梦存量报表常见） | postgres 近似**解析失败**（非 PG 语法结构）——**拦得住的一族** | reject(dialect_parse_fail) + fix_hint | 层级改 `WITH RECURSIVE` 递归 CTE；`(+)` 改显式 `LEFT/RIGHT JOIN` |
| 10 | **生态工具边界** | sqlglot 34 方言、sqlfluff 28 方言（含 Greenplum）均**无金仓/达梦**；社区方言包不可核实 | 近似路线没有官方方言兜底——清单与脚本即全部二次校验 | —（认知条目） | **不得把 Greenplum 方言冒用为金仓近似**（Greenplum≠金仓）；新增差异先入本清单再进扫描投影 |

## 确定性校验脚本（说明——本仓库只收设计文档，不交付脚本本体）

Agent Skills 惯例是技能包内附脚本供酌情执行（确定性计算优于 token 生成）；本包的伴随脚本 `check_dialect`（建议落点 `dialects/check_dialect.py`）的**形状与判定规则**如下：

- **职责**：对给定 SQL 文本做差异清单的**离线确定性扫描**——逐条目按触发形状（token 级：`ROWNUM`/`CONNECT BY`/`START WITH`/`(+)`/字面 `?`/`''` 比较/`NVL(`/`DECODE(`/`SYSDATE`/`VARCHAR2`/`NUMBER(`……）做命中检测，不做语义判断、不做改写。
- **输入/输出**：输入 `(sql_text, db_type)`；输出命中列表 `[{条目号, 差异点, 位置(行,列), 建议改法（引自上表末列）}]`，无命中输出空表。退出码：有结构族命中（第 9 条）非零，供跑批断言。
- **与闸的分工**：语法闸只拦"近似方言解析失败"（执行前、在线、结构族）；脚本扫"解析得过去但语义漂移"的条目（离线、评估跑批/适配自查）。两者**同源同清单**——本文件是文档真源。
- **对账义务（单一真源）**：语法闸运行时只读"差异扫描投影"（清单触发形状的确定性投影，构建期生成注入）；本清单每次修改后须重建投影并跑脚本对账——清单与投影不同步属配置错误。
- **用法**：① 评估跑批对 golden SQL 集合全量扫描出差异命中报告；② 国产化适配时对存量报表 SQL 自查；③ 方言失配被闸拦截后，人工复核 fix_hint 时对照本清单原文。

## 渐进披露说明

本包三段式即 Agent Skills 渐进披露的落地：frontmatter 的 name/description 常驻可发现（含"何时用+反例"）；差异清单正文按需加载——方言失配被拦后复核 fix_hint、或国产化适配对账时才读；校验脚本不载入上下文即可离线执行。方言知识**不全量写进生成系统提示**：多数查询无方言差异，全量常驻既费 token 又破坏 KV Cache 冻结前缀契约（F12 三铁律）。
