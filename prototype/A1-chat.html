思考过程问数据时展示 · 点任意处开始/重跑
六站固定顺序＋一条"改错回流"：错了自动改，最多 3 次，改不动就明说转人工。
听懂问题
意图＝查数据排名 · 指标＝日产油量 · 时间＝上个月（2026-08-01 → 2026-09-01）· 条数＝前 3。含糊问法会先反问（例：「那口井怎么样了」→ 反问哪口井、哪个月）。
查哪些表
全库 200 张表先检索裁剪到 5 张，命中 2 张：日产计量表（井号 / 日期 / 日产油…）＋井档案表（井号 / 井名…）。表说明书带业务注释才能被问句命中。
写出查询（第 1 次）
SELECT well_name, oil_rate
FROM oil_production_daily JOIN well_info USING (well_id)
WHERE prod_date >= '2026-08-01' AND prod_date < '2026-09-01'
ORDER BY oil_rate DESC LIMIT 3
埋伏：oil_rate 是编出来的列名，真列叫 oil_prod——要到执行才炸。例题固定不变、按固定顺序生成（省算力、可复现）。
安全检查
只放行查看语句 ✓ · 单条语句 ✓ · 表在白名单 ✓ · 条数强制限量 ✓ → 放行。查询安全检查=五道安检（m17）；规则在代码里执行，不靠嘴上叮嘱。
执行查询（第 1 次）
数据库亲自报错：Unknown column 'oil_rate' in 'field list'。真正碰数据库的只有查询执行器（只读）。
核对结果（第 1 次）
判定：失败。处理：把报错原文＋可用表结构回灌给「写出查询」，试错计数 +1（最多 3 次；改不动就明说，不硬编一个答案）。
自动改错（第 2 次生成）
例题与表结构照旧、报错垫在末尾——助手读着报错自己改列名：ORDER BY oil_prod DESC。反思回边=核对失败 → 退回生成节点重来（m7 状态机 · W-F7-5/6）。
再过安检并执行（第 2 次）
改过的查询不豁免：同一道安全检查再过一遍 ✓ → 执行成功，返回 3 行。
核对结果（第 2 次 · 通过）
判定通过后，答案＋出处＋图表建议在左侧问答区点亮。
