修改审批台C 区 · 指标与术语 · Owner / 治理领导组审批 · 阿强组织评审

🔍 搜井号 / 报告 / 指标… 当前角色：Owner / 治理领导组（审批角色 · 本区默认阿强） 演示环境

平台（智能助手）发现的每个问题，都变成一张"修改建议"统一进这个池子：给证据、给可信度、给优先级。谁都不能直接改正式定义——过安检、人批准，才生效，而且随时能退回来。

指标与术语库 修改审批台 发布前安检 指标口径详情
铁律（永不违反 · 置顶展示）
1. 不直接改主干
建议先进池子；正式定义谁也不能伸手就改。
2. 只提建议不自己合并
平台只能提，合不合并必须人点批准。
3. 不改自动生成的文件
百科页、索引这类自动产物不手改——要改就改源头定义，自动产物随后自己刷新。
4. 大改动必须人工批
产量口径这类高影响变更，必须 Owner / 治理领导组签字。
这四条的技术叫法
技术叫法：只提合并请求、四条红线（F25 · W-F25-1/2）；"主干 / 派生物"的人话＝正式定义 / 自动生成的文件。
一张建议的流转路线
提案进池（三个来源统一收口）→ 过安检（发布前安检 · 五道检查）→ 负责人批准 🛡（人工点）→ 生效（版本 +1，正式定义更新）→ 发现不对？随时可回滚
自动化与责任的边界
自动化止于提案，责任归于 Owner——平台不替人做决定（F25）。
提案池（按来源筛）
全部来源 考核没通过 自动体检发现 用户反馈
三种来源怎么分流
三种来源同一张表、同一套字段，进同一个池子再分流（W-F24-1）。技术叫法：考核源 / 体检源 / 运行信号源。
提案（改什么 · 为什么）来源证据可信度优先级状态操作

提案字段与体检说明
每条提案的统一字段：来源 / 证据 / 可信度 / 优先级 / 状态（本页表格的列就是这套字段 · F24 配置项"提案统一字段"）。体检源的体检＝给业务对象打四维分：资料全不全 / 逻辑顺不顺 / 数据覆盖够不够 / 关系健全不健全，附补全建议，建议经确认才合并（W-F24-2）→ 考核与质量区的考核失败也会自动登记到这里。
