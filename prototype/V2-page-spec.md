## A1 问一问（A1-chat）

**本页功能**：油田技术人员的统一提问入口——问报告（找材料）、问数据（查生产数）、做汇报（出成品），问数据时能看到平台查证的全过程，答案带出处。

**功能清单**：F1 三种问法切换 · F2 问数据全过程（示例驱动）· F3 答案与出处 · F4 生成文件（PPT/图/语音）· F5 断线与语音输入 · F6 问报告（术语/指标问答+专业计算工具）· F7 做汇报

### F1 三种问法切换
- 操作：点击页签切换提问模式。
- 交互类型：Tab 切换。
- 步骤与变化：点"问报告/问数据/做汇报"→ 内容区整组切换，页签下划线高亮当前。
- 静态数据：三个页签名。

### F2 问数据全过程
- 操作：点"试试示例"按钮（或语音/输入框提问）。
- 交互类型：按钮触发 + 右侧步骤条逐步点亮（定时顺序执行）。
- 步骤与变化：
  1. 点按钮 → 提问气泡出现；右侧"思考过程"步骤条从灰态开始逐节点点亮（约 0.7s/节点）。
  2. 节点"核对结果（第 1 次）"点亮为**红色失败态** → 展开失败说明（数据库报错原文）。
  3. 节点"自动改错（第 2 次生成）"点亮 → 展示改正后的 SQL 片段。
  4. 节点"再过安检并执行（第 2 次）""核对结果（第 2 次·通过）"点亮 → 左侧答案卡出现。
  5. 再点步骤条任意处 → 全流程复位重跑。
- 静态数据：九节点名称与说明文案；SQL 两段（第 1 次 `ORDER BY oil_rate`（错列名）；第 2 次 `ORDER BY oil_prod DESC`）；报错文本 `Unknown column 'oil_rate' in 'field list'`；意图卡文本（指标=日产油量·时间=上个月·条数=前 3）；选表说明（命中 2 张：日产计量表+井档案表）。

### F3 答案与出处
- 操作：阅读答案；点出处行展开明细。
- 交互类型：逐字输出（打字机效果，点答案跳全文）+ Collapse 展开。
- 步骤与变化：答案句逐字出现 → 表格随答案卡呈现 → 点出处 1/2/3 展开各自明细（样本行/换算规则/可组合表）。
- 静态数据：答案句"上个月产量最高的三口井如下（按日产油量排名，已剔除同班次重复行并统一单位）"；表格 3 行（N-02 渤中28-1-N2｜渤南/CEP-A｜48.60｜样本日 2026-09-14；N-11｜渤中/CEP-B｜≈11.04（12.40"方"×0.89 折算）｜单位误录已折算；第 3 名 —）；表脚注"数据来源：生产日报系统 · 上月月度聚合"；出处 1 样本行三段（含 A/B 班重复行、方误录行）；出处 2 密度表（渤南 0.86/渤中 0.89/渤西 0.91，吨↔方=质量÷密度）；出处 3 组合规则（日产计量表⋈井档案表 ✓；日产量直连注水量 ✗ 须经受效关系）。

### F4 生成文件
- 操作：点"做成 PPT / 配张图 / 出段语音"。
- 交互类型：按钮触发 + 横向任务进度四步点亮 + 生成文件卡出现 + 下载按钮假下载提示。
- 步骤与变化：点按钮 → 进度条"受理回执→生成中→存入文件库→生成下载直链"依次点亮 → 文件卡出现（文件名/格式/直链有效期）→ 点"一键下载"出提示文案；再点进度区重跑。
- 静态数据：三种产物映射——PPT《上月产量 Top3 · 汇报页.pptx》/图《三口井产量对比 · 示意图.png》/语音《上月产量解读 · 语音.mp3》；下载提示"已开始下载「…」——下载直链 24 小时内有效"。

### F5 断线与语音输入
- 操作：点"模拟断线"看恢复提示；点"语音提问"体验语音转文字。
- 交互类型：Alert 横幅出现；按钮填充问句并触发 F2 流程。
- 步骤与变化：点断线 → 琥珀色 Alert"网络断开了 3 秒……已自动重连：回答从断点继续、已经出来的内容不丢"；点语音 → 输入框填入"上个月产量最高的三口井"并跑 F2。
- 静态数据：Alert 文案；语音问句文本。

### F6 问报告（术语/指标问答 + 专业计算）
- 操作：阅读两组问答；点"试试示例：岩性"看专业工具调用过程。
- 交互类型：对话气泡 + 工具调用链横向流程 + 结果延迟出现。
- 步骤与变化：展示"躺井"问答（出处：业务术语台账+检泵周期指标卡）→"产量完成率"问答（含禁用词提示：问到"老完成率"给"已废弃，请用产量完成率"提示）→ 点岩性示例 → 用户气泡+助手"调用测井岩性识别模型"+五步调用链（自主选工具→填参数→权限检查→模型返回→解读）→ 延迟出现识别结论（砂岩为主、泥岩夹层，约七成）。
- 静态数据：躺井答句与两条出处；产量完成率公式（Σ实际产油÷Σ计划配产×100%）；老完成率提示文案；岩性示例问句（N-02 井 2500–2600 米）；调用链 5 节点；识别结论文案。

### F7 做汇报
- 操作：阅读助手对汇报请求的响应；下载汇报页文件。
- 交互类型：对话气泡 + 文件卡 + 假下载。
- 步骤与变化：语音转文字气泡（"把上个月完成率情况做成汇报"）→ 助手应答（口径=产量完成率+两点提醒：禁用词提醒、一数四源按审定口径出数）→ 文件卡《8 月产量完成率 · 汇报页.pptx》+下载。
- 静态数据：应答文案两段；文件名与下载行为同 F4。

### 导览弹窗步骤（A1）
1. 点"试试示例"——右侧思考过程开始逐步跑。
2. 看第 1 次核对变红——平台查错后自动改（最多 3 次）。
3. 答案逐字出现——表格+出处都可展开核对。
4. 点任意出处——看原始数据长什么样。
5. 点"做成 PPT"——任务进队列，进度走完出下载。
6. 点"模拟断线"——断网重连回答不丢。
7. 切到"问报告/做汇报"——术语问答与汇报成品各看一条。

### F2 处理进度管线
- 操作：上传后观察处理进度；点管线任意处可重新跑一遍。
- 交互类型：横向步骤条逐步点亮（约 0.65s/步，data-runflow），每步点亮后展开对应说明卡。
- 步骤与变化：1) 触发（上传或点管线任意处）→ 五步从左到右依次点亮，每亮一步其下方说明卡出现；2) 五步全部走完 → 末步展开 F3 的两件产物卡；3) 点管线任意处 → 全流程复位重跑。
- 静态数据：
  - 五步节点名：解析（读出文字和图）→ 切段 → 向量化 → 建索引 → 索引期加法（摘要＋问题）
  - 管线区提示：点"上传报告"开跑；点管线任意处可重跑。关掉的索引支路直接跳过、不跑不花钱。
  - 步 1 说明卡：读出正文和插图；报告原文原样存进文件库（桶：报告原文），一个字不动——以后任何引用都能翻回原文。
  - 步 2 说明卡（随切段方式联动）：切段方式：智能切段——按章节和语义边界切，一段 256–1024 字，相邻段重叠 10–20%。想看三种切法的对照，用下面"切段方式"现场切换。（切到其他方式时前半句替换为 F5 对应文案）
  - 步 3 说明卡：把每段换成一串"语义坐标"：意思相近的段坐标就相近——问句换个说法也能搜到，靠的就是它。
  - 步 4 说明卡（随四开关实时联动）：按四开关写入索引：语义 ✓ · 关键词 ✓ · 百科页 ✓ · 关系图谱 ✗。关掉的支路不跑、不产生抽取费用。（✓/✗ 与 F4 四个开关当前状态一致）

**本页功能**：平台背后的大模型在这里配——主用哪家、坏了自动切谁、重试几次，每次调用花多少钱都有账可查；配好即对全平台生效，问数的人不用管。

### F1 模型清单（主用＋备用）
- 操作：查看当前主用/备用模型及其状态；点击链接跳往使用方页面。
- 交互类型：静态双卡片展示 + 页内链接跳转。
- 步骤与变化：无状态变化；左卡"Petro-72B"带绿色"使用中"徽标，右卡"DeepSeek"带灰色"备用"徽标。

  - 备卡："备用：DeepSeek"＋徽标"备用"＋说明"主用故障时自动顶上，用户无感知；主用冷却期满自动切回。"

### F2 切换与重试参数
- 操作：修改四个参数输入框，点保存。

- 静态数据：四个参数项——"连续失败几次判为故障"=2；"故障后冷却多少秒不用主用"=60；"失败自动重试几次"=3；"单次调用最多等多久（秒）"=30。按钮文案"保存设置"。

### F3 配置文件预览
- 操作：查看与表单对应的配置文件全文；可直接编辑文本。
- 交互类型：可编辑代码块（contenteditable）。
- 步骤与变化：无联动；文本可改但不保存。上方说明"下面这份就是本页表单对应的真实配置文件内容（演示预填）；改表单＝改这份文件的对应字段。"
- 静态数据：配置文件全文（照抄，含注释与字段对齐）：

```yaml
# 文件：app/gateway/config.yaml（演示预填；字段＝网关配置契约，一条不多不少）
model_list:                          # 模型清单：主用 + 备用
  - model_name: petro-llm            #   主用别名「petro-llm」＝Petro-72B（业务代码只认别名）
    litellm_params:
      model: openai/petro-72b          #   Petro-72B 主模型，OpenAI 兼容接口（换模型只改这一处）
      api_base: ${PETRO72B_BASE_URL}  #   内网地址外置，不写死在代码里
  - model_name: deepseek-backup      #   备用：DeepSeek
    litellm_params:
      model: openai/deepseek         #   同为 OpenAI 兼容形状
      api_base: ${DEEPSEEK_BASE_URL}
fallbacks:                           # 主用故障 → 自动切备用（点「故障演练」验的就是这行）
  - petro-llm: [deepseek-backup]
num_retries: 3                       # 重试只走网关层；软件侧 max_retries=0 防重试套娃
allowed_fails: 2                     # 连续失败满 2 次 → 判定故障
cooldown_time: 60                    # 故障冷却 60 秒，期内不再选主用
request_timeout: 30                  # 单次调用超时（秒）
```

## D2 搜索与回答（D2-retrieval）

**本页功能**：平台怎么找资料、怎么组织答案，在这里定规矩——先查什么后查什么、每步拿几条、结果怎么排、引用长什么样、实在搜不到怎么说。

**功能清单**：F1 检索顺序（逐级升级）· F2 每路条数与合并方式 · F3 精排三选一 · F4 引用格式二选一 · F5 搜不到时的兜底话术 · F6 逐级检索演示 · F7 规矩的影响范围

### F1 检索顺序（逐级升级）
- 操作：查看三级检索次序表，逐级开关。
- 交互类型：开关 toggle（三行各一个）+ 固定文案展示。
- 步骤与变化：点任一行开关 → 开/关切换（默认全开）。表下方两个固定项不可开关："命中即停：开"开关可切；旁注"上级查到就不往下查，省时省钱"；另一条纯文案"两个答案拿不准时：宁可不答、反问澄清，不瞎猜（这是固定铁律，不设开关）"。
- 静态数据：表头"次序 / 这一步查什么 / 开关 / 说明"。3 行：
  1. **精确点名**（@指标 / @井号 直接点名）｜说明：问法里带了「@产量完成率」「@N-02」这类点名，直接命中，不走后面的模糊搜索
  2. **确定性查表**（台账完全一致才命中）｜说明：同义词、别名在账上完全对上才命中——宁可查不到，不给"差不多"的结果
  3. **语义搜索＋关键词搜索，两路一起查**｜说明：一路按意思找（换了说法也能命中），一路按字面找（专有名词一个字都不差）

### F2 每路条数与合并方式
- 操作：修改每路取数条数、合并方式下拉、送精排条数，点保存。
- 交互类型：输入框 + 下拉框 + 按钮假保存。
- 步骤与变化：点"保存设置"→ 出现提示"已保存（演示）——真实实现写回检索配置并热加载。"

### F3 精排三选一
- 操作：点三个档位页签，看各档的算法说明、优缺点与适用场景。
- 交互类型：Tab 切换（三选一）。
- 步骤与变化：点页签 → 说明面板整组切换，页签高亮当前档。默认选中"模型精排（快）"。
- 静态数据：三页签名"模型精排（快） / 大模型逐个打分（准但贵） / 复合分＋多样性（防同质）"。三面板内容：
  - 档①："怎么算：用一个小而快的排序模型，把两路合并的候选一次性重新打分排队。"｜优点/代价："一次调用排完一批，延迟低、花费小"｜适用场景："日常问答——界面响应要快，问题以「查报告找说法」为主"
  - 档②："怎么算：用主力大模型对前 N 条候选**逐条**打分——打 20 条就是 20 次模型调用，一条都不能少。"｜优点/代价："判断最准；但每条都花一次调用，慢且贵"｜适用场景："重要汇报材料、口径核对——宁可慢点贵点也要准"｜脚注"打分解析失败时按原顺序放行，不炸整条链路。"
  - 档③："怎么算：复合分＝0.6×模型分 ＋ 0.3×检索基础分 ＋ 0.1×来源分，每条候选的得分都能拆开看；再按多样性参数（λ=0.7）挑选，避免前几名全是同一份报告的近重复段落。"｜优点/代价："结果覆盖面广、来源多样，得分可解释"｜适用场景："「各区块产量对比」这类要覆盖面的汇总问题——防止答案全从同一篇报告抄近重复段"

## D3 安全与权限（D3-security）

**本页功能**：两条底线在这里配——查数据的每一步都要过安全检查（少一件不放行）；谁能看到什么由权限矩阵说了算（没配的权限，界面上根本没有那个入口）。
