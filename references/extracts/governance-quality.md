## 一、治理组织与角色清单

### 1.1 某头部海上油公司"五位一体"管理组织（孙福街，五层主干）

组织模式选型：某头部海上油公司采用**联邦组织模式**（DAMA 组织模式中的联邦式，"通过设置不同的层次来协调数据管理组织、业务线及 IT 三者关系，更适用于大型企业以及复杂业务场景"）。

| 层 | 角色/机构（原文表述） | 职责（原文转述） |
|---|---|---|
| 1 | 数据治理领导组 | 统筹协调 |
| 2 | 总部各专业部门 | 业务驱动 |
| 3 | 各分子公司 | 具体落实 |
| 4 | 研究中心 | 总体技术支持 |
| 5 | 各内部服务单位 | 重点支持 |

原文：'采用联邦组织模式,形成由数据治理领导组统筹协调、总部各专业部门业务驱动、各分子公司具体落实、研究中心总体技术支持、各内部服务单位重点支持的"五位一体"管理组织'——孙福街。

### 1.2 数据湖平台治理体系中的五类干系人（陈绍凯，与 1.1 同构、职责更细）

"构建'五位一体'组织保障。明确公司领导层、数据管理部门（信息中心）、业务部门（勘探、开发、工程等）、数据所有者（业务专家）、技术支持团队（平台运维与工具开发）在数据治理中的职责与协同机制。"——陈绍凯。

- **公司领导层**：决策与统筹；
- **数据管理部门（信息中心）**：数据入湖环节"由数据资源中心或分公司数字化室，利用工具配置入湖强制规则（如完整性、命名规范）进行自动化批量检查，工具自动生成入湖合规性报告并作为数据移交和考核依据"（陈绍凯）；
- **业务部门（勘探、开发、工程等）**：业务驱动、提出数据需求；
- **数据所有者（业务专家）**：数据认责、定义质量规则的业务口径；
- **技术支持团队（平台运维与工具开发）**：平台运维、治理工具开发。

### 1.3 质检业务流中的操作角色（陈绍凯 图 6 三级质控体系）

- **数据采集管理人员**：数据采集、采集数据、数据入湖管理、数据清单维护；
- **分公司数字化室**：调用质检任务、数据质检、对待核验数据核验（入湖质控执行者）；
- **数据质量管理人员**：发现问题、配置质检任务、确认整改、复检、出具质检报告；
- **数据使用者**：问题数据反馈、评价反馈；
- **工具（数据湖平台）**：提供质检任务 API、问题数据整改、API 服务商店。

### 1.4 矩阵式项目管理角色分工（李帆，全文细读）

- **勘探开发数据治理项目组**："成立勘探开发数据治理项目组，深度融合 IT 与业务，协调联动各专业业务部门、信息部门和职能部门。项目组承担数据治理的技术支持和技术管理职责，全力推动公司数据治理工作"（李帆）；
- **横向——各专业数据治理课题组**："横向维度根据不同的业务类型设置不同专业的数据治理任务，成立各专业的数据治理课题组，负责各专业的数据采集、迁移、质量控制、平台建设和优化工作"。横向按照"勘探开发、钻采、工程、规划等专业"组织（李帆）；
- **纵向——各子项目组**："纵向维度则根据数据治理'采、存、管、用'四个环节，开展多专业协同，明确各专业部门的工作界面，设置相应的子项目，实现子项目与课题的有效衔接"；"纵向上由各子项目组统筹各专业统一要求，开展治理任务；横向上由各专业课题组按照要求执行本专业各项数据治理任务"（李帆）；
- **公司领导/有关职能部门**：项目组每周"及时向公司领导报告相关情况，推动问题的协调解决"；"针对项目组内部无法解决的问题，进行升级管理，反馈至公司有关职能部门协调解决"（李帆）；
- **协调推进机制**（李帆）：项目周例会、周报、会议纪要通报机制；年度整体计划+季度详细计划，"细化到周，责任落实到人，实施挂图作战"；项目计划含"主数据管理、数据湖平台建设、数据质量管控等六大类 110 余项任务，涉及公司 11 个业务部门和二级单位"，依托信息化手段线上管理；
- **问题管理机制**（李帆）：反馈端"以源头采集、数据应用和数据管理的维度进行问题分类管理"；解决端"以数据治理业务问题、数据湖平台问题、专业采集工具问题、数据管理问题等维度进行分类管理"。

### 1.5 其他论文中出现的治理角色/机构

- **数据治理委员会**（孙华）："设置数据治理委员会等岗位"，"数据治理委员会立即牵头修订了《数据采集管理规范》……并安排了为期两周的专项培训"（OCR 受限，语义确定）；职责：明确数据责任归属、构建决策流程、牵头标准修订。
- **数据治理专职专家 / 数据管家角色**（孙华）："并设置数据治理专职专家负责管理"；概念模型支撑层要素含"数据管家角色"（OCR 受限）。
- **"三权分立"治理组织搭建要点**（孙华）："治理组织搭建要点……可依据'三权分立'"（OCR 受限，原文即为分权制衡思路，具体三权名称无法逐字核对）。
- **数字化筹备小组、数据维护小组、数据分析小组**（张新）：油田推进数字化建设时出现的组织架构，"数字化筹备小组、数据维护小组、数据分析小组等众多组织架构的出现导致原有的生产运作流程产生较大变化"。
- **数据保护官（DPO）**（李颜）："油田还可以设立专门的数据保护官（Data Protection Officer, DPO），负责监督数据治理政策的执行情况"。
- **跨部门联合工作组**（李颜）：定期召开跨部门会议、设立联合工作组促进信息共享和协同工作。

### 1.6 映射要点（供业务设定书参考）

- "五层五角色"可直接映射为项目设定的五级组织：领导组（决策）→专业部门（定标）→分子公司（执行采集）→研究中心（技术支持）→服务单位（运营保障）。
- 质检门禁的执行主体在原文中有明确分工：源头质控=业务系统+采集管理人员；入湖质控=数据资源中心/分公司数字化室；湖内质控=数据质量管理人员；整改=问题责任人；复核=自动+人工（陈绍凯）。
- 矩阵式组织回答了"跨 6 大专业如何协同"：专业维度（横向）保个性，环节维度（纵向，采/存/管/用）保统一（李帆）。

## 二、数据资产目录与标准体系

### 2.1 资产目录 L1–L5（孙福街）

- 构建方法："通过深入调研华为等企业数据的树形五层资产目录构建方法，从某头部海上油公司集团公司业务线出发，发布《集团公司数据资产目录方法论》，形成树形五层资产目录结构"——孙福街。
- 层级含义（原文明示的只有两端）：
  - **L1 = 主题域分组**："全面盘点了从 L1(主题域分组)到 L5 级(属性级)的勘探开发数据资产清单"——孙福街。
  - **L5 = 属性级**（同上引文）。
  - **L2/L3/L4：原文未逐层给出定义**，设定书如需中间层名称（主题域/业务对象/逻辑实体等），须另行参照华为方法论或标注为"推断"，不得引本组论文为据。
- 覆盖范围："构建 6 大业务域 5 级数据资产目录，覆盖了勘探开发所有核心业务环节"（孙福街）；"梳理核心端到端流程"（孙福街）。
- 目录的应用形态："编制了企业级勘探开发数据资产目录，充分厘清数据情况……逐步形成了数据资产视图、统计指标报表和安全分类分级等多个数据资产应用"（孙福街）。
- 工具化生成路径（陈绍凯 图 2）：抽取标准表、数据项形成资产目录 L4–L5 → 维护数据资产目录 → 形成数据资产目录（L1–L5）；资产目录与元数据、标准元数据、模型元数据联动。
- 目录维度（陈绍凯）："构建基于业务域（勘探、开发、生产、钻井、工程等）、数据类型、数据来源等多维度的数据资源目录，实现资产可视化管理"。
- 李帆文的盘点成果（可作目录规模示例）："全面盘点石油公司上游业务应用系统中的历史数据，梳理应用系统两百余个，源头数据库八十余个"；"经过去重归并，共梳理出上亿条结构化数据和非结构化数据。建立了涵盖物化探、井筒工程、综合研究、分析化验、油气田生产与海洋及地面工程等六大业务域、五类数据类型的数据资源目录"。

### 2.2 六大专业与 40 余册数据标准

- 专业划分（孙福街）：海上油气上游"勘探、开发、生产、海洋工程、钻完井、储量 6 大专业，细分业务活动上千项"。
- 标准规模："某头部海上油公司先后发布了涵盖勘探、开发、储量、生产、钻完井、海洋工程 6 大专业的 40 余册数据标准，建立了上游勘探开发统一数据标准体系，实现了从数据源到数据应用的全面标准化管理"——孙福街。
- **册目名称：原文未列出**。可核对的只有六大专业名；陈绍凯文另给出六大核心专业口径："完成物探、钻井、录井、测井、测试、开发生产六大核心专业领域的结构化数据标准制定、发布与在线管理"（陈绍凯）。设定书如需册目清单，须引李为冲等《勘探开发数据标准建设方法与实践》（陈绍凯文参考文献[19]），本组论文未含。
- 规模佐证（孙福街）："形成了 9000 多个数据集的关联互通"。

### 2.3 数据标准的内容构成

- 孙福街（最完整口径）："这些标准不仅规范了数据的定义、格式等基础属性，还明确了数据的采集规范、管理责任及质量控制要求，为数据质量的提升提供了有力保障。"→ 标准五要素：**定义、格式、采集规范、管理责任、质量控制要求**。
- 孙华（补充）："数据标准与规范包括数据定义、格式、编码规则及参考数据管理等具体内容"；指标类标准示例："某油田针对'油井产量'这一指标，明确定义其计算口径……以吨为计量单位，也规定了统计周期与计算方法等"（OCR 受限，要素确定：计算口径/计量单位/统计周期/计算方法）。
- 标准管理在线化（陈绍凯）：数据标准管理模块"以标准结构化管理为核心……通过标准审批实现标准结构化内容在线修订管理；通过比对数据模型、数据质量、数据安全等模块的信息，形成标准与各模块的差异评估，实现标准贯标管理"；关键技术点为"标准内容结构化存储于平台关系型数据库；利用平台 API 服务提供标准查询接口；通过与元数据管理工具集成自动比对数据模型与标准的差异（贯标率分析）"。
- 标准一致性技术（孙福街）："在数据标准制定过程中，采用知识图谱一致性判别技术和业务活动五维度描述方法，实现了多专业融合的标准一致性检查，建立了某头部海上油公司全专业贯通一致的数据标准"。

### 2.4 POSC 建模与维度/关系建模融合（孙福街）

原文："在数据建模方面，借鉴 POSC 标准建模方法，基于多对象关系提取数据属性，创新维度建模和关系建模的融合优化技术，有效提升了数据模型的一致性和易用性。"
配套背景（孙福街引言）：国际上游数据模型源流为石油技术开放标准联盟（POSC）与公共石油数据模型协会（PPDM）；中国石油 1989—1991 年制定钻探、物探、测井、分析化验等 9 大类数据统一标准，形成 EPDM 模型。

### 2.5 数据安全分类分级（孙福街，资产目录的延伸应用）

- 制度：《勘探开发数据安全管理办法》《勘探开发数据分类分级管理细则》《勘探开发数据权限管理办法》；
- 分级依据："依据《中华人民共和国数据安全法》、工业和信息化部《工业数据分类分级指南(试行)》《商业数据分级保护目录》《工作事项清单》等权威文件，对勘探开发数据湖内存储的各类数据进行了分类分级，并将其纳入数据标准管理体系，实现'业务定义安全'"；
- 权限模型："综合基于角色的访问控制（RBAC）和基于属性的访问控制（ABAC）两种权限管理模型的优点，搭建了具有某头部海上油公司特色的数据权限管理体系，在油气勘探开发领域首次实现了对行级数据的加密和动态脱敏"；
- 工具能力："敏感数据识别、分类分级管理、数据脱敏加密、安全策略配置、数据审计"；
- 对照（李颜）：主数据示例为"设备编号、井位坐标等"；生命周期四阶段"数据采集、数据存储、数据使用和数据销毁"。

### 3.4 质量报告与闭环管理流程

**闭环机制（孙福街）**：围绕源头数据、数据入湖和湖内数据开展质量检查，"形成'问题发现、问题分析、问题整改、重点监控'闭环管理机制"；"通过数据治理平台，智能配置质量稽核模型，主动预警潜在问题，定期自动化生成详尽质量报告，通过数据质量闭环管理机制，实现数据质量持续提升"。

**三级质控"点、线、面"（陈绍凯）**：
- "点"：以规则库（点）和问题数据（点）为精准发力点，工具自动化、大规模扫描精准定位问题；
- "线"：过程贯通——"通过源头拦截进行数据采集质控，通过入口把关实施入湖质控，通过持续监控进行湖内常态化质检，3 条线贯穿数据生命周期关键节点"；
- "面"：覆盖勘探、开发、钻井等全业务域。

**事前/事中/事后（陈绍凯）**：①事前在工具中维护和发布质量规则库；②事中开展数据采集质控、入湖质控、湖内常态化质检 3 部分工作（采集质控=业务系统导入时调用质检 API 实时/准实时校验、即时反馈、源头拦截；入湖质控=数据资源中心或分公司数字化室配置入湖强制规则、生成入湖合规性报告作为移交和考核依据；湖内质检=按日/周/月计划执行全量或增量质检）；③事后由工具自动生成问题单并分发，责任人整改反馈，"工具支持整改结果自动/人工复核"，质量 KPI（数据项合格率、问题整改率）实时可视。

**问题单流转（陈绍凯）**："问题数据记录关联责任人及角色。基于平台工作流引擎（或自定义状态机）实现问题单的'分发->认领->整改->复核->关闭'全流程线上跟踪。自动比对同一目标前后两次质检结果差异，动态更新问题状态。其效率提升体现为问题闭环管理周期平均缩短 50%。"

**8 步质量管理流程（陈绍凯 图 5）**：①提出数据质量管理需求（理解目标、数据分析、转化要求）→②识别关键数据（依据要求、识别关键、确定数据）→③定义数据质量规则（制定规则、审核规则、批准规则）→④实施数据质量规则（维护规则、配置参数、工具实施）→⑤数据质量评估（检测数据、处理异常、明确问题）→⑥识别数据质量问题程度（监控问题、评估问题、确定优先）→⑦问题整改（分析根源、制定计划、执行补救、处理问题）→⑧质量规则改善（完善规则、维护变更、持续优化、反馈优化）。

**多级闭环质控（刘珊珊 表 2）**：事前质控提醒（动态/校验/技术逻辑规则）→事中质控提醒（全过程/分析/复杂规则指标+实时数据质控规则+自动填充缺失值）→事后质控评价（智能化/评价/结构化数据规范化标准化有效性校验+非结构化文本自然语言处理）→质控（评价）指标（自动化质控得分、人工质控得分、不同级别部门按业务域评价指标质控合格率、不同维度多项质控指标统计分析）；反馈机制"形成得分问题明细及处理反馈机制，其中，处理类型包括整改和补录问题数据"；上报流程为"填报提醒、审核反馈、修正错误重新填报、审核通过的全闭环上报流程"。

**五级质检门禁的映射建议**（依据上文归纳，非原文）：源头采集质控（点·拦截）→入湖质控（点·强制规则+合规性报告）→湖内常态质检（点·日/周/月）→专项场景质检（储量/钻井/注采，线）→考核与评估（面·KPI+记分卡）。

### 4.3 数据质量管理工具详述（陈绍凯 4.2，重点）

功能模块（图 4）：质量规则管理（规则导入导出、智能创建规则、手动维护规则、批量创建规则、规则查询、规则 API 发布）、质量检测任务（质检任务、任务运维、监测报警）、数据质量发布（质检结果发布、质量报告模板、质量报告）、质检结果处理（问题数据查询、数据质量整改、数据质量跟踪、数据质量考核）、质量检测分析（综合性分析、统计分析、质量检测报告、缺失数据查询）。

技术实现：

- 结果存储与发布：质检结果持久化到分析型数据库（ClickHouse/Greenplum）；Web 可视化报表（按部门、数据类型、规则类型、时间维度统计问题分布、趋势、TOP N 问题项）+订阅推送；提供质量 KPI（数据项合格率、问题整改率）实时监控与考核依据；
