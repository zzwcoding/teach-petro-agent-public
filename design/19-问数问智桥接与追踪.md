| 图事件（stream_events 分类判据） | 会话帧 | data 要点 |

| 节点结束 | `node_progress` | phase="end"；attrs 同步充进 span（主干 D） |
| 模型流增量（锚官方"增量输出"） | `token` | 设计稿 14 交付为非流式调用——分支占位待节点改流式，桥接零改动接住 |

| 节点异常上抛 | `error` | 码随异常族：gateway_error 可重试 / schema_store_empty 装配缺失；关流前异常收口 |

## 关键判断的取舍记录

1. **图内部事件翻译成稳定帧型，不把 LangGraph 原生事件透传给前端。** 备选：前端直接消费 stream_events 的原生事件流（省一层翻译）。不选：①SSE 帧协议是设计稿 01 锁死的跨设计稿契约（agent/token/tool_call/done/error+设计稿 13 增项），前端都按它写，透传等于把客户端契约焊死在框架版本上——docs/tech-stack/langgraph.md 记录旧文档站整站 404、流式 API 形状随版本演进，原生事件枚举是最不稳的接口面；②透传会漏"该拦的翻译活"——节点名要翻成中文环节名、中断载荷要翻成审批卡片、图终态 result 要按 kind 分流出帧（主干 A 帧分类表），这些是"事件语义接缝"的本职（卡 m13 Seam 行：下游只产事件，帧形状由 m13 桥接）。对策是把版本脆弱性收进一张映射表（_NODE_SPAN+分类判据只有"节点名/中断标记"两类），框架形状变化只改表不改协议。代价：多一层翻译代码（约 40 行伪代码）。换边条件：前端直接嵌 LangGraph SDK 做专属调试面板时，可并行开一条透传旁路——主协议不动。
2. **审批恢复复用 dispatch 同口，图用进程内单例；run_id 随审批载荷往返。** 备选一：给 m13 加 resume_text2sql() 新公开签名、审批走独立端点。不选：卡 m13 公开接口五签名封顶，"零发明卡外公开接口"是登记纪律；挂起是 thread 级事实，Command(resume) 本就是官方规定的 invoke 输入形状（官方能力面表），决定载荷与新提问在 dispatch 入口按形状分流即可，恢复段与首段共用同一套事件分类器/帧出口/打点（零第二份副本）。配套决定：_问数图() 进程内单例——checkpointer 随图实例存在，每次 build_graph() 重建 InMemorySaver 等于审批挂起全丢；run_id 随决定载荷往返让 span 树跨两段 HTTP 续接同一棵树。代价：单例态与开发级 InMemorySaver 绑定（进程重启挂起即丢，设计稿 15 已声明开发语义可接受）；生产 AsyncPostgresSaver 才有跨进程恢复，追踪跨进程续接随之列为换边条件。
3. **问数链会话上下文"只登记、不并图"：历史用于收尾双写，State 零并历史。** 备选：桥接把最近问答摘录并进 question 文本（指代消解）或给 State 加历史字段。不选：State 七字段是卡 m7 登记的公共契约（设计稿 14 主干一），"一问一生、一图一轨迹"是设计稿 14 定形的图语义；把上下文并进提问会改变 W-F7-1 的判定基础——"那口井怎么样了"的信息不足闸就该在**裸提问**上触发（该问指代三口井，并入上下文反而制造伪消解）。问数链对会话上下文的正确义务是**登记**：反问轮与终态轮都收尾双写进会话历史（设计稿 18 同型接线），指代语境自然沉淀在史里，供下一问任何链路的模型调用消费。换边条件：产品明确要"追问免重述"（指代消解入图）时，给 m7 卡加输入字段，桥接侧只多一个装配段。
4. **打点收在桥接一处、树账分离：span 树记"哪一环慢"，成本按 call_id 对账不重记钱。** 备选一：m7 节点/m8 执行器各自打点（工具调用、网关调用的原生位置）。不选：m7/m8 的依赖行都没有 m12——各模块打点的前提是依赖边存在，强行打=改卡；而 m13 依赖行明列 m12，且桥接是唯一同时看得到运行全局（run_id）与事件流（节点起止/节点输出）的层——设计稿 06 示例树的六节点名词表本就按"运行时打点方"的视角画的。树里不重复记每笔钱的理由：节点内网关调用号只有收尾事件携带（有则填 attrs.call_id/cost，无则留空位），逐调用成本的真源在 m2 记账（设计稿 07 record_spend/审计表）——树账按 call_id 对上（设计稿 06 原文"attrs.call_id 对上 Metrics 的逐调用账目"），宁缺毋假。挂起等待计入节点墙钟同理：如实记录优于美化口径。换边条件：m7/m8 卡增补 m12 依赖（改卡）时，打点前移到原生位置，桥接只留运行根与 trace_run。

## 锚点对照精要

**docs/tech-stack/langgraph.md · 流式行：stream_events/增量输出与中断事件**（设计范围框架红线锚；卡 `m13` 锚点 K-A/K-E/K-H）
文：能力面表流式行 `graph.stream_events(input, config, version="v3")` 配 `stream_mode="values"/"updates"` 与 `output_keys`，给"增量输出与中断事件"；编译后的图是标准 Runnable，可在 FastAPI 内 `await graph.ainvoke(...)`（文档选型与版本节）。落点：主干 A 的调用序列逐字按此形状——`stream_events(图输入, config, version="v3")` 做节点级事件桥接、入口分流用 `Command(resume=决定)` 作 invoke 输入（官方：resume 是唯一可作为输入的 Command 模式）；官方事件枚举版本脆弱处收进 _NODE_SPAN 映射表（取舍 1），ainvoke 形状保留在设计稿 14 主干二（本节恢复段同为 invoke 族输入）。

**docs/tech-stack/langgraph.md · interrupt 与 checkpointer 的运行时前提**（同锚；设计稿 15 框架红线的接线半程）
文：`interrupt(payload)` 暂停+`Command(resume=value)` 恢复、恢复值即 interrupt() 返回值，必须配合 checkpointer；线程经 `configurable.thread_id` 定位，无 checkpointer 则无法 interrupt/恢复。落点：主干 B 的两段 HTTP 语义（挂起关流→决定载荷回流恢复）完全站在这套前提上——桥接新增的只有"载荷→帧"与"决定→resume 输入"两个翻译；进程内图单例（取舍 2）是 InMemorySaver 语义的运行时配套，生产 PostgresSaver 换边收在 compile 参数（金仓适配无公开文档，设计稿 14/15 遗留沿用）。

**原书第二章 §Agent如何调用大模型 · 无状态与消息结构**（卡 `m13` 锚点）
书：API 每次调用无状态，模型不记忆历史，每次把完整消息列表送回；上下文=静态前缀+轨迹。落点：主干 A 第 4 段收尾双写让问数轮（含反问轮）进会话历史——"刚才查过什么"的记忆不在图 State（一问一生）也不在模型里，在会话历史与检查点两处；下一问任何链路的模型调用全量携带该历史，跨链路（qa/问数）共享同一份 `{role, content}` 形状的轨迹。

**原书第二章 §KV Cache友好的上下文设计**（卡 `m13` 锚点；主干 E 机制源）
书：前缀匹配是逐字节的，命中部分读价约首次计算的 1/10；系统提示词与工具定义冻结、动态信息只追加末尾。落点：generate_sql 的 few-shot 冻结前缀使反思回边第二轮只付新增 token 的钱（主干 E 推演账）；桥接侧的对应纪律是"历史只追加、零改写"——问数轮收尾 append 进史，不改中间，跨轮前缀字节稳定。

**原书第一章 §编排模式（工作流 vs 自主）**（卡 `m13` 锚点）
书：工作流执行路径确定，提示注入或模型犯错的影响面封在当前节点；自主 Agent 需要明确停止条件。落点：run_text2sql 是纯工作流粘合层——分流/翻译/登记/打点全是确定性代码，零业务判断；判断全部住在图节点里（信息不足闸、AST 闸、审批、熔断）或官方机制里（resume、recursion_limit 兜底）。运行时与图的分工即"编排模式"的落形：**决策进图、搬运归运行时**。
