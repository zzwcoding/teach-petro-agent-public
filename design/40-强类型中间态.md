### 第 0 步：分工矩阵——谁产出/谁消费（本设计稿灵魂）

> DataBuddy §五段行的原文是分工宣言："**模型：理解与提出计划；语义编译器 + Harness：验证、授权、执行、审计与失败关闭**"。五段不是五个数据桶，是**把这条分工线切成五段各管一截**——每段的产出方与消费方就是矩阵的两列，走查时逐段对号。

| 段 | 装什么（设计范围 What 行） | 谁产出 | 谁消费 | 分工线判词 |
|---|---|---|---|---|
| IntentSpec | 意图/对象/任务类型/快照状态 | **模型**（理解：抽槽、判充分——clarify_intent 既有逻辑）+ **协议**（快照状态：生效清单快照号，瀑布 S0 四要素同源） | 瀑布（S0–S7 的输入）、意图闸 | 模型出理解，协议出边界——谁在问、问的是哪一版口径的事 |
| SemanticContext | 候选实体/指标/关系/规则/可信样例 | **协议**（瀑布单出口，设计稿 39——S7 回读核验通过才算产出，非缓存残影） | **模型**（提出计划的全部材料） | 检索是协议不是搜索——模型只见材料不见存储（边界规则 v3 行） |
| SemanticPlan | 指标/维度/过滤/时间/粒度/关系路径 | **模型**（提出计划：读 SemanticContext 提结构化提案） | **协议**（裁决：join 白名单/粒度对齐；违反即失败关闭） | ★ 全链分工线本体：模型在这里只有提案权，裁决权为零 |
| ExecutionPlan | 确定性 SQL/Function/Tool | **协议**（语义编译：裁决通过才编译——verified 模板参数化，设计稿 22 既有公开面） | **Harness**（语句期校验链 m17、工具执行器 m8） | 模型拿不到执行权——SQL 是编译产物不是模型产物 |
| EvidencePack | 结果/口径/版本/血缘/验证状态 | **协议+Harness**（执行结果 m8、血缘注记 m17、口径快照 m16、审计落 m3/m12 既有面） | 用户（出图——载荷折装归设计稿 19）与评估（只读回读，设计稿 23） | 执行后留证——结果可核验、动作可回放（DataBuddy §受控执行行："执行后留证"） |

**读法**：从上往下，模型的份额递减（段一产出、段二消费、段三产出、段四段五零参与）——"提出计划"是模型在主链上**最后一次**握笔的位置；从段四起全部是协议与 Harness 的确定性世界。这就是"中间态 + Harness"（DataBuddy §中间态Harness行）的字面形状。

### 主干一：TypedState.assemble——段序闸与失败关闭（卡 m21 注释的落形）

```text
伪代码 — app/agents/text2sql/typedstate.py:TypedState.assemble（m21；签名=卡 m21 逐字）

class TypedState:
    _段序 = ["intent_spec", "semantic_context", "semantic_plan", "execution_plan", "evidence_pack"]
        # 段是链条不是跳棋——顺序即 DataBuddy §五段行的顺序，段序闸见 R1

    @staticmethod
    def assemble(stage, payload) -> 五段强类型:
        # ── R1 段序闸（捣乱输入的拦截位）：段四之前必须有已裁决的段三凭据 ──
        if stage == "execution_plan":
            plan = 状态中取段三 or payload.plan_ref 对不上段三指纹
            if plan is None or 指纹(payload.plan_ref) != 指纹(plan):
                raise PlanRejected(stage="sequence", reason="未裁决的计划——模型只能提计划，不能自证执行",
                                   fix_hint="先提 SemanticPlan（指标/维度/过滤/时间/粒度/关系路径）过协议裁决")
            #   ★ plan_ref 是装配时按段三内容重算的指纹：可验、不可造——伪造凭据在比对处现形
        # ── R2 计划裁决（W-F22-2 本体）：计划违反本体约束即失败关闭 ──
        if stage == "execution_plan":
            for 表对 in 按 join 树逐边拆(plan.join_path):        # m16 公开面只裁一对表（设计稿 36 语义沿用）
                if OntologyRegistry.joins_allowed(表对) is False:
                    raise PlanRejected(stage="ontology", reason=f"白名单外 join：{表对}",
                                       fix_hint=joins_allowed 返回的合法路径)   # 默认拒绝并给合法路径——设计稿 36 语义
            if plan.grain 与 marts 模型物 GrainSpec 不对齐:
                raise PlanRejected(stage="grain", ...)          # 粒度协议沿用（设计稿 33——声明先于聚合）
        # ── R3 类型化装配：五段各归其位，键集固定缺键即错（形状契约）──
        match stage:
            "intent_spec"       → IntentSpec(**payload)
            "semantic_context"  → SemanticContext(**payload)     # 设计稿 39 瀑布出口整体类型化（零字段废弃）
            "semantic_plan"     → SemanticPlan(**payload)        # 模型提案——只装形状，不裁决
            "execution_plan"    → ExecutionPlan(**payload, plan_ref=指纹(plan))   # 走完 R1/R2 才到这
            "evidence_pack"     → EvidencePack(**payload)        # 凭据链四环校验见主干四末段
        # 异常去向三层（伪代码通用约定）：PlanRejected 属第一层"可纠正"——结构化回灌模型重提计划
        #   （error 格承载，既有反思回边回 generate）；连续拒绝由 attempts≥3 既有熔断兜底（第三层）；
        #   "失败关闭"的语义=未裁决的执行计划永不产出——Executor 拿不到调用，生产库零执行
```

**为什么裁决放在装配处，而不是等到执行前校验链**：语句期闸（设计稿 24 GuardChain）拦的是"**裁决过的**语句长歪了"；装配裁决拦的是"**没裁决就想执行**"——计划期拒绝发生在 SQL 生成之前，省一整轮生成与校验的成本；两层闸各管一条绕过路径（对照设计稿 12 权限闸"可见性+复核"双闸论），纵深从一层变两层（设计稿 15 主干八"闸前移"同款先例）。**设计稿 36 闸语义零回退**：joins_allowed 还是那个公开面、还是"只裁一对表、默认拒绝并给全部合法路径"——变化只有调用时机从语句期前移到计划期（反断言见越界自查）。

    trusted_samples: list        # 可信样例：verified 模板（设计稿 22 template_for）+ golden few-shot
                                 #   （设计稿 23 sample_fewshot 只读取样——既有注入边，冻结前缀纪律不变）

class SemanticPlan(TypedDict):                 # 段三：指标/维度/过滤/时间/粒度/关系路径（设计范围六项，模型提案）

    grain: str                   # 粒度声明："月×油田"——对齐指标卡粒度（设定书 §3 指标 1"月/区块·油田"；

    join_path: list              # 关系路径：[oil_production_daily⋈well_info, oil_production_daily⋈date_dim]

## 关键判断的取舍记录

1. **TypedDict 承载五段，不上 pydantic**。备选：Pydantic BaseModel 换运行时字段校验。不选：设计范围"不做什么"行明文排除；LangGraph 官方三形状里 TypedDict 是 reducer（`Annotated[list, add]`）的原生挂载点（锚 LangGraph 能力面表），形状契约靠"键集固定+装配即校验"在 assemble 一处静态成立，不需要运行时反射；代价是类型本身不拦运行期错键——由 R3 装配校验补位。换边条件：段字段数量膨胀到装配校验写不动时，再评估 input/output schema（LangGraph 图构建行的官方参数）做边界收窄。
2. **旧格作视图别名，不删格不大爆炸迁移**。备选：一次删九格、六节点全部改读写五段。不选：卡 `m7` Seam 明文"节点函数体逻辑不变"；设计稿 14/22/24 的既有消费方（回灌读 error、熔断读 attempts、血缘读 explanation）一行不改才叫升级零惊扰——别名把代价收敛到五处装配调用。真成本：State 键数 9→14；设计演绎以"别名只读、写只在装配处"封死双写不一致。换边条件：五段形状稳定一个版本周期后，后续新设计稿只读写段、别名格冻结不再增。
3. **计划裁决放装配处（计划期），与语句期校验链构成纵深两层，不互相替代**。备选：裁决只留在设计稿 24 语句期（少一处闸）。不选：计划期拒绝发生在 SQL 生成之前，白名单外意图在花生成成本之前就被打回；设计稿 36 `joins_allowed` 公开面、只裁一对表、默认拒绝给合法路径——三条语义逐字沿用（函数体零改动，变化的只是调用时机前移），语句期闸继续拦"语句与裁决不符/方言失配/越权注入"——两层各管一段（设计稿 15 主干八"闸前移、防御纵深一层变两层"的同款论证）。换边条件：若语句期闸演进到能完全反推计划意图（当前不能），再评估合并。
4. **分工矩阵显式成表，不散落各段注释**。本设计稿的灵魂不是五段字段清单（设计范围 What 行已给），是"模型提出计划，协议决定执行"这条**分工线**（DataBuddy §五段行原文是分工宣言）；散注释会让主线被字段淹没，成表让每段的产出方/消费方可指名、走查可对号（主干四逐段点名对照）。代价：一张表要随段字段演进维护。换边条件：无——这张表就是设计范围"伪代码梳理范围"第一条的交付物本体。

## 锚点对照精要

**DataBuddy §五段行（AE 前沿方案报告 "强类型中间态五段"行）**：原文——"IntentSpec → SemanticContext → SemanticPlan → ExecutionPlan → EvidencePack——'模型：理解与提出计划；语义编译器 + Harness：验证、授权、执行、审计与失败关闭'"。落点：段序与第 0 步矩阵逐行对应；差异一处并声明——DataBuddy 的"语义编译器"在设计版=verified 模板参数化（设计稿 22 既有公开面）+段四裁决（本设计稿），不上 SemQL（DataBuddy §演绎边界行："语义编译以'语义计划→确定性 SQL'伪代码呈现，≈B6 强类型中间态"——本设计稿即 B6 该呈现）。
