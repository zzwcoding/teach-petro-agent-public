### 主干一：受限容器与沙箱档案——设计演绎的资源清单、限额字段与生命周期（卡 m8 v3.1）

```text
伪代码 — app/agents/tools/sandbox.py:SandboxProfile / SandboxRun（m8；受限容器设计演绎——不真建容器）

class SandboxProfile:                # 限额档案（三闸之二"资源限额"与闸三"超时"的声明形状；部署参数环境注入）
    max_input_rows: int              # 读入行数上限（如 50_000 行——数据装载位斩断，不等算完）
    max_memory_mb: int               # 容器内存上限（如 512 MB——派生计算驻留数据量封顶）
    max_seconds: int                 # 墙钟时长上限（如 60 秒——超时闸判据源）
    preview_rows: int = 5            # 预览行数（协议常数——官方账"agent sees five rows instead of 10,000"）
    preview_cell_chars: int = 24     # 预览单元格截断宽（防宽列把预览本身撑成上下文炸弹）

class SandboxRun:                    # 受限容器生命周期（设计演绎五拍：创建→装载→执行→收集→销毁）
    创建(profile):                   # 容器按限额档案拉起——资源清单只有两样：
        #   ① 调用方喂入的查询结果流（数据面）② 派生计算脚本（计算面）。
        #   无网络出口、无生产库凭据——容器只管算，不管连库（数据拉取在箱外走 m3 公开面，
        #   装载后喂入：容器被攻破也拿不到库凭据，只读断言多一层物理底）
    装载(job):                       # 语句与脚本入箱——入箱前过闸一只读断言（先验，主干二）
    执行():                          # 计时起跑——闸二行数/内存水位、闸三墙钟在此生效（执行中）
    收集():                          # 仅成功到达：结果行集 + 确定性统计摘要（行数/列名/数值列极值均值）
    销毁():                          # 成败都销毁——中间结果不出执行环境
                                     #   （"intermediate results stay in the execution environment"）；
                                     #   三闸触发的终止也是销毁——部分结果随容器一起没了，绝不回灌
# 生命周期纪律：收集是唯一出口（成功且有界），销毁是必然归宿（成败与超限一视同仁）——
# "结果不回灌"（W-F27-2）不是事后丢弃，是结构上无路可出
```

### 主干二：call_sandboxed 姊妹五步与三闸 fail-closed（W-F27-2）

```text
伪代码 — app/agents/tools/sandbox.py:Executor.call_sandboxed（m8；签名=卡 m8 v3.1 注释逐字；
         姊妹形状=设计稿 12 主干三：五步纪律沿用，第⑤步换装——executor.py 零改动）

SANDBOX_JOB_SPEC = ToolSpec(         # 沙箱作业规格常量（本文件内）——不经 Registry 注册：
    name="sandboxed_detail_query",   #   作业不是模型选项（结构性保证①的主半边，主干四）；
    description="适用：剧本步骤声明的大结果明细拉取与派生计算（环比/异常检测/递减口径计算）。"
                "不要用：自由对话取数（普通查库工具的行数收口已够用）；写库改库（本作业只读）。",
    parameters={"type":"object",
                "properties":{
                    "sql":{"type":"string","description":"明细查询，单条 SELECT，必须带 ORDER BY"
                          "（预览排序协议的前提——无序结果集取'首 5 行'无意义）"},
                    "script":{"type":"string","description":"派生计算脚本，只读行集变换"}},
                "required":["sql","script"]},
    permission_level="readonly",
    func=容器内执行)                  # func 只被本文件第⑤步调用于箱内——普通五步永远走不到它

async def call_sandboxed(self, tool_call, user, limits: SandboxProfile) -> ToolResult:
    call_id = tool_call.id
    # ── 第①步 作业规格：取本文件常量（不是 Registry.lookup——无导出面即无自由调用）──
    spec = SANDBOX_JOB_SPEC
    # ── 第②③④步 与 Executor.call 逐字同纪律（私有件复用零复制，本设计稿不重写设计稿 12 主干三）──
    #   ② json.loads(arguments)（非法即回灌）③ schema 校验（sql/script 形状不合即回灌，工具零执行）
    #   ④ assert_allowed(user, spec)——剧本授权不豁免用户权限，只读角色照常过闸
    # ── 第⑤步 沙箱执行：三闸 fail-closed，任一触发即终止、结果不回灌、拒绝入轨迹 ──
    run = SandboxRun.创建(limits)
    try:
        # ── 闸一 只读断言（先验，装载前）——语句半边+脚本半边逐段过 ──
        断言 = 只读断言(tool_call 参数)
        #   判据：sql 首词必须是 SELECT（设计稿 15 只读闸首段语义同源——工具箱内侧末闸，
        #         执行前校验链 m17 的完整裁决在调用方既有路径，两道闸各管各的）；
        #         script 文本扫描写动词（UPDATE/DELETE/INSERT/DROP/ALTER/TRUNCATE/GRANT…）
        #         与库连接写调用；解析不了的不猜——按最严拒绝（fail-closed 的字面，取舍 3）
        if 断言.拒绝:
            return 沙箱拒绝回灌(call_id, 闸="只读断言", 触发=断言.触发点)
        run.装载(tool_call 参数)                      # 闸一过了才进箱
        结果 = run.执行()                              # 闸二/闸三在执行中生效（容器侧终止）：
        #   行数斩：m3 只读拉数（get_session_factory 公开面，m8 既有依赖边）的结果流在读入
        #   max_input_rows 时断路；内存水位触顶即停；墙钟 max_seconds 到点即停
        return 大结果协议(call_id, 结果, limits)        # 主干三
    finally:
        run.销毁()                                    # 成败都销毁——中间结果不出执行环境
```

## 关键判断的取舍记录

1. **沙箱是执行模式不是新工具——`Executor.call` 零改动，`call_sandboxed` 是驱动方编排入口。** 备选：把沙箱能力注册成 ToolSpec 让模型自由选用。否决：模型可自选=资源密集模式失去治理授权（谁都能拉全油田明细算到天荒地老），且普通五步若为沙箱改道就违反"Executor.call 零改动"的边界红线。卡 m8 v3.1 注释的签名（`call_sandboxed(tool_call, user, limits)`）本身就是模式语义：limits 是调用方给的部署档案，不是模型参数。代价：该能力对自由对话不可见——但这是特性：要大结果计算请走剧本（Owner 审批过的任务声明），治理收在声明侧。换边条件：出现"免剧本的受控分析"需求时，以独立 ToolSpec+专用权限级扩卡，本节不预支。
2. **三闸失败统一归设计稿 12 错误三分法"权限拒"族，错误码 `sandbox_denied` 单列。** 判据：三闸与 assert_allowed 同族——都是政策裁决（"不允许以这种方式执行"）而非可用性故障（"外部世界暂时不行"）；处置三连逐字吻合权限拒语义：零执行（或零结果外泄）、理由入轨迹、无重试指引。不归①参数错：可纠正回灌+重试指引=给逃逸尝试发攻略（"把 UPDATE 藏进注释再试试"），"试到过闸为止"的循环比一次失败更糟；不归③下游错：副作用"先查询后重试"的语义在这里无物可查（写语句根本没执行）。码值单列 sandbox_denied（带 闸/触发/处置 三字段）只为排障定位——家族归属看处置语义，不看码值字面。换边条件：无（fail-closed 的可观察面就是"拒绝入轨迹"，W-F27-2 字面）。
3. **先验闸在前、执行中闸在后，判据不确定时一律按触发处理——fail-closed 的字面兑现。** 只读断言放装载前：写语句根本不进容器（比"进容器后被拦"少一层暴露）；资源限额与超时在执行中：行数斩在数据装载位、内存/时长水位在计算位。三处判据不确定时（脚本解析失败、水位读不到）一律按触发处理——与设计稿 15"解析失败按最严拒绝"同源：fail-closed 不是姿态，是判据的兜底方向。代价：误杀率换漏网率——本项目库取"宁可误杀"边（生产库零执行是硬底线）。换边条件：误杀真实任务时按闸名回溯、以声明内白名单放行，不放松兜底方向。
4. **预览协议四个确定性决定：排序必须声明、截断必须带尾标、总行数必须声明、统计摘要箱内算。** 排序：无序结果集取"首 5 行"是随机样本，模型会把它当全貌——作业 schema 要求明细查询带 ORDER BY，预览才有"前 5"的语义；截断：宽列（如井档案 remarks，附录 A.1 有注入前科的字段）不截则预览本身变上下文炸弹，24 字符+"…"尾标让模型知道被截；总行数：不给总数模型会把 5 行当全部（编造"共 5 条"），给了它才知道证据在箱外、追问要下载；统计摘要：极值/均值类追问用箱内确定性聚合先答掉（几十 token），多数任务不必走到下载——预览+摘要是为了"省下载"，不是为了"哄模型"。换边条件：需要分页浏览时句柄扩 offset 参数（备案一行），协议四字段不撤。
5. **分岔接线以占位声明——本节不改 m7，紧枚举扩容记遗留。** 分岔判据（步骤.tools 含"沙箱查库"）消费的是 PlaybookDef 只读字段（设计稿 37 公开面），两出口行为全程在 m8 侧走查；驱动方执行腿的 if 分岔落位在设计稿 37 主干五 _执行步骤 的一处——m7 不在设计范围 Touches，接线归装配侧统一排程（设计稿 12"调用方（设计稿 17 接线）"占位同纪律）。**附带遗留（备案，不阻塞收尾）**：设计稿 37 装载闸的公开面紧枚举 {指标模板, 选表, 生成, 只读查库} 需增"沙箱查库"一值（卡 m16 装载闸一行扩容）——m16 是本节只读消费面，设计稿 29 零改动；枚举落卡后剧本资产即可声明沙箱腿，本设计稿走查以"判据已声明"为前提成立（W-F27-3 的机制半边不受影响）。换边条件：无。
6. **token 账只算账不测账——量级注源、对照官方数字，不发明测量值。** 数据量级：3,600 行=120 井（设定书 §1）×30 天（剧本缺参默认——设定书 §7），行形状=附录 A.2 九字段；单行 token 给区间（裸行 20–40 / JSON 40–80）与保守取值，并标注"≈是量级估算不是测量值"；官方对照全部注源：15 万→2 千/98.7%（references/data-agent-research.md §4.9）、多智能体 ≈15×（references/data-agent-research.md §4.4）、产品级 25×25 裁剪（references/data-agent-frontier.md §2.3）。工程立场：会算量级账是工程能力，冒充实测是造假——设计稿示范前者。换边条件：需要实测账时，用假 usage 网关（设计稿 07 Echo 形状）实测计入演示场景，设计稿不预支。
