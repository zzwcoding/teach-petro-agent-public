### 主干二：逐对取数——管道三连调用与"跳过计数"（W-F6-6 主循环；卡 m6 公开接口）

```text
伪代码 — app/rag/evaluator.py:Evaluator.run（m6；签名按卡逐字：run(qa_pairs) -> Metrics）

# 模块级私有配置：
#   _MIN_SAMPLES = 20          # W-F6-6 数量口径：少于 20 条的均值无意义，结构化报错拒评
#   _TOP_K = 10 / _TOP_N = 5   # 管道旋钮与设计稿 10 同值——报告的调参建议就落在这对参数与拒答阈值上
async def run(qa_pairs) -> Metrics:
    # 主干判断①输入闸：数量闸 + 必填字段闸（question/ground_truth/kind 缺一即结构化报错——
    #   宁可拒评，不可带病出报告）；qa_id 缺失自动补编号
    逐样本行表 = []
    # 主干判断②逐对循环（设计范围异常去向：单对评估失败→跳过并计数，不中断整批）：
    for 样本 in qa_pairs:
        try:
            candidates = await Retriever.search(样本.question, top_k=_TOP_K)    # m6 公开接口（设计稿 10 真身）
            ranked = Ranker.rerank(样本.question, candidates, top_n=_TOP_N)     # m6 公开接口
            if 样本.injected_answer 存在:
                # 坏例注入口：不跑生成，但判分材料仍是当前检回真块——编造回答要对真块才见血（捣乱输入主干）
                answer = Answer(文本=样本.injected_answer, citations=[], 拒答=False)
            else:
                answer = await Generator.answer(样本.question, ranked)          # m6 公开接口（内部经 m2 流式）
                # 流式 token 帧在此就地消费、不入事件通道——评估是批处理，只取流末 Answer（设计稿 10 契约）；
                # 预期拒答样本走到拒答闸时零模型调用零记账（设计稿 10 闸位在生成之前）
        except 管道异常 as e:
            逐样本行表 += {qa_id, 管道失败原因=e.原因}; 管道失败计数 += 1; continue   # 跳过不中断——设计范围口径
        # 数据变形：管道产物收拢为判分输入（检回上下文=精排后块原文，带 [报告名 p.页码] 标头）
        判分输入 = {question, ground_truth,
                   contexts=[c.原文 for c in ranked.候选], 块标头=[(c.report_name, c.page)],
                   answer=answer.文本, 拒答=answer.拒答}
        # 主干判断③拒答口径分流：实际拒答 与 样本.kind=="预期拒答" 比对——
        #   预期内→走布尔口径单列（主干五）；预期外→坏例清单（"库里明明有据却拒答"是检索侧事故）
        行 = {qa_id, kind, 实际拒答, 首名精排分=(ranked.候选空 ? null : ranked.候选[0].rerank_score),
              faithfulness=await _score_faithfulness(判分输入),
              answer_relevancy=await _score_relevancy(判分输入),
              context_precision=await _score_context_precision(判分输入)}
        逐样本行表 += 行        # 判分失败在判分件内部记账（主干三），不拖垮其他指标与样本
    return 汇总(逐样本行表)     # 主干五
    # 边界对账：只调 search/rerank/answer 三个读路径——Indexer/VectorStore.upsert/Bm25Index.build
    #   零出现：评估只读管道产物，不反写索引（设计范围边界红线）
```

### 主干三：判分公共件——judge 走 m2 网关的调用契约（边界规则第 1 行）

```text
伪代码 — app/rag/evaluator.py:Evaluator._call_judge（m6 私有件；全部判分调用的唯一出口）

# 模块级私有配置：
#   _JUDGE_ALIAS = "deepseek-backup"   # config.yaml 已登记的备用模型组直指作别名（设计稿 07 契约）——
#                                      #   与被评模型异源：判分官与考生不同家族（取舍 3，书口径多源评判）
#   _JUDGE_RETRIES = 1                 # JSON 解析失败重试次数；用尽记"判分失败"，不上抛不中断
async def _call_judge(系统判分词, 用户判分词) -> 判分JSON:
    # 主干判断①判分调用：非流式——判分要整段 JSON，不要逐帧（Gateway.chat 承设计稿 07 契约形状）
    result = await Gateway.chat(
        messages=[{"role": "system", "content": 系统判分词},
                  {"role": "user", "content": 用户判分词}],
        model_alias=_JUDGE_ALIAS, stream=False)
    # 数据变形：应答文本 → JSON 解析（判分官按系统词契约只回 JSON、不带围栏）
    try:
        return json_loads(result.文本)
    except 解析失败:
        重试 _JUDGE_RETRIES 次；用尽 → 抛 判分失败异常   # 样本循环内被记为该指标"判分失败"，不摊薄均值
    # 异常去向：GatewayError（设计稿 07：router 重试与 fallback 跑完仍败）原样上抛——本层不吞错不再重试，
    #   该样本跳过计数（同主干二口径）
    # 记账事实：判分调用同过网关 spend 双写（设计稿 07）——一轮全量 22 样本 × 3 指标 ≈ 66 次判分调用，
    #   账逐调用可查；评估是有成本的，报告口径栏如实带"判分调用次数"
```

### 主干四：三指标判分件各走一条（W-F6-6 三指标；判分 prompt 形状）

```text
伪代码 — app/rag/evaluator.py:Evaluator._score_faithfulness（m6 私有件；指标一：忠实度）

# 口径：回答里的每句论断能否被本次检回块支撑——判"说出来的有没有据"，与是否切题无关
async def _score_faithfulness(判分输入) -> score ∈ [0,1] | "无论断":
    if 判分输入.拒答: return "无论断"      # 拒答话术零论断——单列计数不入均值（主干五口径，防正确行为被罚分）
    # 数据变形①论断拆分（确定性切分，零模型调用）：按句界切回答——设计稿 10 生成纪律"每句论断末尾标注
    #   [报告名 p.页码]"恰好把句界送到眼前；引用标注随句携带进论断
    论断清单 = _split_claims(判分输入.answer)
    if 论断清单为空: return "无论断"
    # 主干判断②逐论断判支撑（清单批量一次调用）：材料=带标头的全部检回块原文 + 论断清单
    判分JSON = await _call_judge(
        系统判分词=忠实度判分官（骨架纪律一~四 + 本次档位）,
        用户判分词=f"报告块：\n{判分输入.contexts}\n\n论断清单：\n{论断清单}")
    #   档位（对每条论断二值裁决，输出 verdicts 数组）：
    #     supported    = 某块原文能推出该论断——数值/井号/结论逐项一致；
    #     unsupported  = 块推不出、与块矛盾、或引用指向不在材料中的报告页——块外领域知识不得计入支撑
    # 数据变形③计分：score = supported 数 / 论断总数
    return supported数 / len(论断清单)
    # 对照说明（非调用）：RAGAS 官方 faithfulness 用 LLM 抽论断再逐条裁决——本设计稿改确定性切句（少一次
    #   模型调用，句界由设计稿 10 生成纪律保证）；判分口径同族：逐论断能否被 contexts 支持
```

```text
伪代码 — app/rag/evaluator.py:Evaluator._score_relevancy（m6 私有件；指标二：答案相关性）

# 口径：回答对问题的贴合度——判"答的是不是所问的"，与有没有据无关
#   （编造但切题的回答这里得高分——单指标盲区，捣乱输入主干 t5 演示为何三指标并存）
async def _score_relevancy(判分输入) -> score ∈ [0,1] | "无论断":
    if 判分输入.拒答: return "无论断"
    判分JSON = await _call_judge(
        系统判分词=贴合度判分官（骨架纪律一~四 + 本次档位）,
        用户判分词=f"问题：{判分输入.question}\n\n回答：{判分输入.answer}")
    #   档位（0~1，一档一判据，输出 {score, reason}）：
    #     1.0 = 逐要点正面作答；0.7 = 答了核心但漏次要点；0.4 = 沾边但大半在答别的；0 = 答非所问/泛泛而谈。
    #     要点点数从问题里数出来（井名+属性+时间范围各算一件），问几件核几件
    return 判分JSON.score          # reason 随逐样本行落账——坏例清单要证据不是裸数字
    # 对照说明（非调用）：RAGAS 官方 answer relevancy 从答案反生成候选问题、与原问题算嵌入相似度取均值——
    #   本设计稿直接判贴合（取舍 4：少一次生成+嵌入调用，小集方差更小，且档位理由可进坏例清单）；
    #   口径不同，数值不与外部互比
```

```text
伪代码 — app/rag/evaluator.py:Evaluator._score_context_precision（m6 私有件；指标三：上下文精确度）

# 口径：检回块里相关块的排名质量——判"检回来的东西排得靠不靠前"，生成不进场（纯检索侧指标）
async def _score_context_precision(判分输入) -> score ∈ [0,1]:
    if 判分输入.contexts 为空: return 0.0     # 双路零召回的样本——检回质量如实记 0，不伪装不跳过
    # 主干判断①逐块判相关（带名次清单批量一次调用）：材料=问题 + 按精排名次排列的块原文
    判分JSON = await _call_judge(
        系统判分词=相关性判分官（骨架纪律一~四 + 本次档位）,
        用户判分词=f"问题：{判分输入.question}\n\n候选块（按名次）：\n{带名次块清单}")
    #   档位（每块二值，输出 verdicts 数组）：v=1 该块含回答本问题需要的信息（直接答案块/必要背景块）；
    #     v=0 同族话题但答不了本问——边缘裁决判据："缺了它，答案缺不缺东西"（如问完井方式、块讲井身结构）
    # 数据变形②排名折损计分：p@i = 前 i 名中相关块数 / i；score = Σ(v_i × p@i) / Σ v_i
    #   ——相关块排得越靠前分越高；Σv=0（全不相关）直接记 0，不除零
    return 折损计分(判分JSON.verdicts)
    # 对照说明（非调用）：RAGAS 同名指标同形（排名折损平均）；思想与书表 3-3 的 MRR/nDCG 同源
    #   （"找到得够不够靠前"），差别只在"相关与否"由判分官语义裁决、不吃人工标注
```

## 关键判断的取舍记录

1. **judge 只出报告不进门禁——评估分数不当上线闸门**。备选：faithfulness 低于阈值就挡发布、或挡回答出流。不选：判分官同输入多次评判也有波动、且有长度偏差这类系统性偏好（书口径明列的局限），拿易漂移的判分当硬闸等于把评估噪声接进服务链路；22 条的小评估集均值置信度低，更撑不起闸。筛出线（0.6/0.5/0.4）只给坏例清单排序用——报告给人，决定由人。换边条件：评估集扩到百级、判分与人工标注的一致率先行标定，且要门禁的检查能写成确定性断言时——书口径：确定性检查才适合当回归门禁，届时优先落机械指标而非 judge 判分。
2. **小评估集口径如实声明：只做同集前后对照，不做绝对宣判**。报告口径栏写明"22 条、每问题单次采样"——没有 k 次采样就没有 Pass@k/Pass^k 语义（书口径：评估报告必须写清 k 次尝试的口径）。备选：每问题跑 k 次取均值降噪。不选：判分成本随 k 线性涨（一轮已约 66 次判分调用；书口径提醒完整评估动辄数千美元 token，当前规模同样怕重复判分）。付出：单次采样的分数波动无法与真实能力变化完全区分——所以报告只回答"改参后同一集上是涨是跌"，不回答"系统绝对几分"。换边条件：评估集与预算扩容后补 k 次采样口径，Metrics 口径栏加字段区分。
3. **判分官与考生异源：judge 别名直指备用模型组**。备选：judge 与生成同走主模型别名（少维护一个部署）。不选：被评与判分同源时 faithfulness 有"自家人高抬"的系统性风险——书口径：同源模型会被学会钻偏好盲点（古德哈特定律：度量变成优化目标就不再是好度量），缓解是多源异构评判（不同家族偏见正交）。备用组本就在 config 契约里（设计稿 07 fallbacks 登记），直指作 judge 别名零新增配置。换边条件：备用组不可用（故障冷却期）时 judge 临时回落主模型，但口径栏必须标"同源评判"——降级留痕，同设计稿 07 回退痕迹纪律。
4. **answer relevancy 直接判贴合，不搬 RAGAS 的"反推问题算相似度"**。RAGAS 官方口径：从答案反生成若干候选问题、与原问题算嵌入相似度取均值。不选：多一次生成调用加 k 次相似度计算，小评估集上方差更大；且相似度分数给不出"漏了哪个要点"的理由——坏例清单要的是证据不是裸数字。直接判贴合把"是否答所问"变成一次可复核的判分决定，理由随分落账。付出：与 RAGAS 原版数值不可直接互比——本设计稿三指标只与自己的历史报告比（取舍 2 的口径纪律）。换边条件：需要与外部基准对齐时补原版实现，Metrics 口径栏加"口径版本"字段区分。

## 锚点对照精要

> 卡 `m6` 知识点锚点 K-B 三项：嵌入文档侧锚点（官方 hybrid+rerank 管线、bge-m3/bge-reranker 调用形状）已在设计稿 09/10 落；本设计稿锚点集中在评估口径侧——原书评估指标口径与 LLM-as-a-Judge 章节，另附检索三指标对照。

**评估指标：成功的定义**（卡 `m6` 锚点"评估指标口径"）
书：仅凭一个通过率数字无法判断系统可用——0.8 对退款客服意味着五分之一用户没拿到退款，对漏洞挖掘 Agent 已属可观，判读取决于业务对成功率的要求；Pass@k（k 次至少一次过，能力上限）与 Pass^k（连续 k 次全过，业务可靠性）相差悬殊，p=0.6、k=5 时约 99.0% 对 7.8%；评估报告必须写清 k 次尝试的口径。落点：Metrics 口径栏照此三件套落（样本数/采样口径/判分模型），三均值只做同集对照、不做绝对宣判（取舍 2）。

**LLM-as-a-Judge：自动化评估的核心**（同锚点）
书：开放式任务无标准答案可自动对比，LLM-as-a-Judge 让模型按专家定义的 Rubric 评判，在自动化规模与人类专业判断间取平衡；已知局限是评判模型自有偏见（最典型长度偏差——偏爱更长更详尽的回复）与同输入多次评判的波动，防范手段有 Rubric 显式惩罚冗长、配对评审前对齐长度、定期审计评分与长度的相关性。Rubric 四准则：基于专家指导、全面覆盖（含陷阱项）、按重要性加权（幻觉是一票否决维度）、评价标准自包含（写可验证行为，不写"展示深刻理解"）。落点：判分官系统提示词四纪律（主干三骨架）是四准则的设计收窄；"幻觉一票否决"在本设计稿的对应物是 faithfulness 把矛盾论断逐条记 unsupported、坏例清单强制带证据。

**同源模型问题与多源评判**（同锚点）
书：Agent 与评判模型同一家族时，Agent 可能学会利用评判模型的偏好和盲点——古德哈特定律：当一个度量指标变成优化目标时就不再是好度量；缓解是多源异构评判（不同家族的偏见正交，难以同时被"骗"），部署期可用单一模型快速评估但应定期用完整多源评判做质量审计。落点：judge 别名直指备用模型组与被评异源（主干三），回落同源时口径栏留痕（取舍 3）。

**RAG基础·检索质量三指标（表 3-3）**（卡 `m6` 锚点 K-B 第三项，对照用）
书：recall@k（书注：此处口径实为命中率 hit rate，与学术 recall@k 在多相关文档时不等）/ MRR（首个相关文档排名倒数的平均）/ nDCG（归一化折损累积增益）三指标在带标注测试查询集上机械计算，分别回答"该找的找到了吗 / 找到得够不够靠前 / 整个排序列表质量如何"。落点对照：本设计稿三指标是生成+检索的端到端判分指标——context precision 的排名折损与 MRR/nDCG 思想同源，但"相关与否"由判分官语义裁决、不吃人工标注；两套口径互补不互替（检索调参的机械验收归机械指标，端到端质量的语义体检归本设计稿 judge 判分）。
