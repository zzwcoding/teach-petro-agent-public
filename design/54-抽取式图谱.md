## 关键判断的取舍记录

1. **类型闸落闸上不落 prompt 自觉——WeKnora 调用位被注释的漂移不进本设计稿。** 备选 A"照抄 WeKnora 现状：类型约束全在 prompt（类型严格从清单选+拿不准跳过），闸层不设过滤"：否决——W-F40-2 断言字面"清单外类型/编造关系**被类型闸拦下**"（期望是可观察的拦截行为不是 prompt 恳求）；且 WeKnora 实测 RemoveUnknownRelation 函数在场调用位被注释（漂移备案②）——"函数写了没接线"是演进中间态不是设计终态。备选 B"闸只做类型过滤，文本显式存在判定留 prompt"：否决——断言给定的另一路"文本里不存在的关系"同样要"被类型闸拦下"，纯 prompt 判定无观察点。落定：主干二判④⑤——实体侧清单白名单+关系侧三重判定（端点封闭/文本显式/标签白名单）落闸，prompt 六档标准与"拿不准跳过"合同照留（劝跳+兜漏网双保险不是复读：prompt 降低发生率、闸保证零漏网）。换边条件：无——断言合同优先，WeKnora 中间态如实备案不改判。
2. **强度参与权重按卡面合同落边权——WeKnora"prompt 产强度、落库丢强度"不照抄。** 备选"忠实 WeKnora：强度只在抽取 prompt 出现，GraphRelation 三字段不带强度、检索权重不含强度"：否决——卡 m25 两处合同（公开签名注释"强度参与权重"+职责行"strength 5–10"）与 W-F40-5 期望"强度 5–10 参与权重可解释"都要求强度活到查询半场；照抄 WeKnora 现状=幽灵断言。落定：主干三判③强度落边权+主干四判②③权重归一注记；WeKnora 现状如实备案（漂移备案①）——本设计稿是"卡面合同的正确实现"，不是"WeKnora 的逐行复刻"（伪代码红线的卡面优先序，设计稿 53 取舍 5 同款纪律）。换边条件：无——W-ID 期望是合同。
3. **图路是第三条并行路，不进 RRF 融合池不抢精排位。** 备选 A"图证据块并入 m6 候选参与 RRF 融合+精排统一排序"：否决——图路证据的权重语义是关系强度（六档判据表可指认），RRF 是排名融合（m6 既有语义）——两种权重语义混进一个池子=谁也不可解释；且 m6 管道是设计稿 08/48 交付物，改融合池=越界动既有票。备选 B"图路独立串行在检索之后"：否决——卡面字面"**并行**汇入"。落定：主干四——图路与向量/BM25 并行发起（WeKnora RunParallel 同构），汇入在 m13 装配处去重合并带来源标，图证据块权重=强度归一注记可解释，精排池零触碰；图链边集随 Context 附带供生成端引用。换边条件：设计稿 69 三接入点若设计图精排联动，走新票不在本节扩权。
4. **五操作 D 派分流逐操作对号——本节给缝装 D 派机制，不改缝面。** 卡 m23 五操作注释的 D 派分流（"D 派=ExtractConfig"/"D 派=类型闸"/"D 派=图存储 namespace=库+文档"/"D 派=改配置重抽"）与本节四件套的对号：define_schema→for_kb（宪法包组装）、extract→Extractor.extract（逐块抽取——注意缝的 extract 入参是 corpus、D 派实现把它离散成逐 chunk 循环，一次一调）、validate→主干二类型闸（闸在 extract 内联+调用方可见的 ValidationReport 形状=丢弃日志聚合——形状合同零改动）、store→GraphStore.add、evolve→改配置重抽（捣乱 A 路 1 修法字面）。落定原因：缝面签名与 DraftGraph/ValidationReport 形状是设计稿 52 交付物（消费方只认形状——双引擎根基），D 派机制装在实现位不动缝；validate 内联还是独立步的分歧按缝面合同办（报告形状可观察即可，判级"类型闸"字面已在卡 m23 注释）。换边条件：无——缝面合同。
5. **11 类清单是"未配置库"的默认档，不是"永远在场"的底座。** 备选"11 类永远在场、KB tags 只做追加（油田六类+通用十一类并存）"：否决——W-F40-1 期望字面"默认 11 类通用实体清单生效；KB 级 tags…**可覆盖**"——"覆盖"是替换语义；且 WeKnora 实物 Tags 整组进模板（extract.go "Tags: extractCfg.Tags"）无追加语义；通用类与领域类并存会让 LLM 把"井"硬塞进 Resource/Category（清单越长选择越难压缩幻觉——笔记一"选择空间被压缩"的反向失效）。落定：主干一判③逐项 or-默认——未配项落默认档、配了项以库为准；乙库六类替身下 11 类零在场（走查推演 1 t2），甲库未配下 11 类逐字生效（t1）——断言两半各得其所。换边条件：无。
6. **namespace=库+文档双标签——生死粒度与合并范围同源一处。** 备选 A"namespace 只有库级（合并范围大、查询聚合简单）"：否决——删除粒度跟着爆炸：删一份文档会级联删掉同库其他文档的同名节点（走查推演 3 t4 对照——v3 的同名词被误删）；WeKnora 合并键 {name, kg} 的 kg=文档号实测为证。备选 B"namespace 只有文档级（删除最干净）"：否决——跨文档聚合查询（"全库哪些井有受效边"）要扫全部文档桶，库标签的聚合语义没了。落定：双标签——库标签管聚合查询、文档标签管生死删除，合并键=双标签（同名合并不跨文档）；同名合并的跨文档风险（同名不同物在不同文档被分开=消歧缺失的另一面）如实归"消歧讲策略不实现"。换边条件：无。
7. **同名合并的软肋（异名分家+同名混物）如实讲透不装闸——消歧生产实现是"明确不讲的"。** 备选"本设计稿加一个简易别名归一闸（N-6→N-06 正则归一）"：否决——设计范围字面"同名合并（消歧讲策略不实现）"与 PRD F40"不做实体消歧生产实现（同名合并讲策略）"；正则归一看着解气，实为发明了"井号写法规则"这条业务事实（旧写法全集不止 N2/N-6 两形——附录 A 只举了例），取材锁违反+假闸误导（以为消歧便宜）。落定：主干三判②策略注记（同名收敛、异名不收敛）+捣乱 C 路 1 软肋讲透（旧写法分家的后果与缓解=KB 自定义指令压写法+人审重抽）——示例价值恰恰在"按名合并便宜但糙"的边界上；真消歧（别名表+人审+嵌入聚类）归设计稿 69 之外的后续。换边条件：无——设计范围红线。
8. **空产合法不重试——与设计稿 50"空产不建块"同族语义，跨票对账。** 一块抽不出实体（低质块/纯公式块）是语料的属性不是模型的故障——WeKnora 空数组条款（实体区与关系区各一条"If no … found, return an empty array []"）把空产定为合法产出；重试到出活=对无源之水反复计费（捣乱 B 路 2）。落定：主干二判③空图不报错不重试照销账；与设计稿 46"失败也是终态"计数收敛、设计稿 50"空产不建块"三处同族——多模态/图谱两路的空产纪律对齐，跨票对账不留两套"空"的语义。换边条件：无。
