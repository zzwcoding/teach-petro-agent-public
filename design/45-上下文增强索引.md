### 主干一：面包屑构造——井号+章节路径，与标题段合成 PRD 面包屑（W-F31-1 的输入半边）

```text
def _breadcrumb(块, 登记信息) -> str:
    # 主干判断①报告名不在本件：组装的标题段（主干三第一段）已承载报告名——

    #   mergeBreadcrumbs"去重防嵌入上下文冗余"是同一纪律的块间版）
    # 主干判断②井号：登记信息扩字段（数据面扩展——取舍 3），报告级属性全块共享；
    #   井号缺登记 → 该段留空如实缺位（不猜不抽——正文抽井号是质检地盘，取舍 3）
    # 主干判断③章节路径：设计稿 44 章节聚合的副产物——父块半程按章节标题边界聚合时
    #   记录的标题链（sec14="完井方式"），子块半程递归切分遇次级标题顺带续链
    #   （"投产与初期产能"）；WeKnora 同构：子块在父块内容上重跑标题检测、面包屑
    #   合并去重（strategy.go:180 mergeBreadcrumbs——锚点对照 1 ⑥）
    return 井号 + " > " + " > ".join(章节标题链)

    #   PRD F31 口径"面包屑=报告名+井号+章节路径"落在组装前两段的合并视野：
```

**为什么面包屑不走 LLM**：面包屑的原料（井号、章节标题链）全部是登记与切分期的**结构化副产物**——它们已经确定存在，让 LLM 复述一遍只引入措辞漂移与计费，不引入信息。LLM 只花在真正缺信息的段上：正文只说"本井"时，结构化原料也补不出的那句"这个块在讲什么"（前缀摘要，主干二）。WeKnora 的同构印证：ContextHeader 是纯结构化面包屑、无 LLM 参与（锚点对照 1 ⑤——它因此不需要"复算"问题），本节在其上叠 Anthropic 式 LLM 摘要段，两代技术各治各的病灶（取舍 2）。

### 主干二：前缀摘要生成——一次生成，入库定型（W-F31-3 的生成半边）

```text

async def _context_prefix(块, 登记信息) -> str | None:
```

**"入库定型"为什么是可复算性的根基**：LLM 生成不确定——同一块两次生成措辞必不同。把生成**固定在首入库一次**、产物落账本，重建就退化成"读存件+纯函数组装"（主干三/走查推演 3）：同输入同输出、逐字可对账、零重复计费。反例（前缀只存索引内，推演 3 t2）：重建=412 次重生成——计费翻倍且两次重建的索引措辞漂移，"同一块两次重建检索行为不同"，可复算性破。WeKnora 同构印证（实测勘误）：WeKnora 的 ContextHeader 带 `gorm:"type:text"` 列标签随 chunk 行落库（chunk.go:177）——调研报告"内存态不落库"说法与实测不符，以实测为准；WeKnora 落库的是结构化面包屑，本节落库的是"面包屑+LLM 摘要"两员投影字段，落库位置同构（取舍 1）。

### 主干三：build_index_content 组装——索引投影的纯函数（W-F31-1 的本体）

```text
伪代码 — app/rag/indexer.py:Indexer.build_index_content（m6 公开签名按卡逐字：
         build_index_content(chunk) -> str；
         🛡️ 卡面注释"嵌入/倒排输入=标题+面包屑+LLM 前缀摘要+正文（F31；原文不动，
            前缀只是索引投影）"是本函数的结构合同）

def build_index_content(self, chunk) -> str:
    # 主干判断①组装顺序：从最稳定到最变化——标题（文档级）→ 面包屑（章节级）
    #   → 前缀摘要（块级身份）→ 正文（块级内容）；语义梯度从外到内，
    #   与嵌入"整段一个向量"的稀释代价对齐：身份词在前，正文在后
    段 = [chunk.登记.报告名, chunk.投影.索引面包屑]
    if chunk.投影.前缀摘要 is not None:      # 降级位：摘要缺失（主干二③）跳过该段
        段.append("[" + chunk.投影.前缀摘要 + "]")   # 不占位不造句——结构化段仍在
    段.append(chunk.原文)                    # ★ 尾段=块原文逐字——只读表达式，无写路径
    return "\n".join(段)
    # 主干判断②纯函数合同：输出只是字符串表达式；chunk.原文/投影字段在函数内
    #   零赋值零旁路——"不回写 chunk 原文"的机器判据（捣乱输入 A 路 1 的暴露位）
    # 主干判断③产出去向：返回值只作为 _embed_batch 与 _tokenize 的**输入实参**
    #   （主干四⑤）——m14 双写收到的 documents/corpus 是索引内容，
```

## 关键判断的取舍记录

1. **前缀摘要"入库定型"落 m3 投影字段族，不为它发明 Repository 新签名。** 备选一"只存索引内"（前缀只活在 m14 的 documents/语料里，重建时重调 LLM 重生成）：否决理由——LLM 非确定，重建措辞漂移导致索引不可对账（"同一块两次重建检索行为不同"），且 412 块×重建次数的重复计费（书 §3.5 费用量级）；备选二"为前缀立专签名"（`save_context_prefix` 之类）：否决理由——卡 m3 公开接口未扩投影方法，伪代码红线"公开签名逐字取自模块卡，不许自造"；`save_chunk_meta` 的 meta 形状恰好覆盖（设计稿 44 parent_id/chunk_type 行族超集字段同款先例）。落定：投影字段族（索引面包屑+前缀摘要）随子块行族入 m3，块原文字段照旧装原文——字段分离使"原文两版逐字相同"成为可 diff 的验收观察位（走查推演 1 t3）。WeKnora 同构：ContextHeader 带 `gorm:"type:text"` 列标签随 chunk 行落库（chunk.go:177 实测）——落库位置同构，本节多落一员 LLM 摘要。换边条件：后续扩卡为投影字段立专签名/专表时，改动收在 `_breadcrumb`/`_context_prefix` 与组装段三处内（m14/检索侧零感知）。
2. **前缀两段式：面包屑结构化（零 LLM）+ 摘要 LLM 生成——不合并成单段也不单用其一段。** 备选一"只留结构化面包屑"（WeKnora 形状）：否决理由——正文只说"本井"且章节头也不含议题细节时，结构化原料补不出"这个块在讲什么"（W-F31-2 的病灶句还要摘要段补语义锚——本节主角块若只有面包屑，"投产与初期产能"章节词救得了词面、救不满语义近邻）；备选二"只留 LLM 摘要"（Anthropic 纯形状）：否决理由——把报告名/井号/章节路径也让 LLM 复述，纯付措辞漂移与计费买零信息（原料已结构化在案）；落定两段式：结构化段零费用逐字确定（重建可复算的半边根基），LLM 段一次生成入库定型（另半边）。两代技术的分工：WeKnora 证结构化面包屑够用（其索引输入无 LLM 段——knowledge_index_content.go:9"adds only the document title"+面包屑），书/Anthropic 证 LLM 摘要段把失败率再往下压（§3.5 −49%/−67% 是"LLM 前缀"实验口径）——本设计稿两段都要，代价是一次生成费与一个降级闸。换边条件：纯制度文件库（章节头即议题）可关摘要段省费——档位归四开关枢纽（设计稿 46）的地盘，本节不预支。
3. **井号来源落登记元数据扩字段，不做正文抽取。** 备选"从报告正文首页/章节头正则抽井号"：否决理由——正文井号写法五花八门（设定书附录 A.1：well_id 规范形 N-02、旧写法 N2/N-2 并存正是明文的脏特征），抽取规则是设计稿 34/38 质检与归一化的地盘，索引期做归一化=越权且引入静默改写风险；登记一次人工录入（报告关于哪口井是登记事实），全块共享零误差。落定：登记信息 {报告号, 报告名}（设计稿 09 形状）扩井号字段——数据面扩展，零新签名；井号缺登记时面包屑该段留空如实缺位（不猜）。换边条件：报告批量入库无人工登记位时，井号抽取归设计稿 34/38 的质检产物回流——索引期仍是消费者。
4. **组装顺序"标题→面包屑→前缀摘要→正文"，不按"摘要→正文→元数据"或倒序。** 依据三条：卡面注释顺序即合同（"标题+面包屑+LLM 前缀摘要+正文"——签名行逐字）；语义梯度从最稳定到最变化（文档级→章节级→块级身份→块级内容），嵌入整段一个向量时身份词不被长尾正文稀释（WeKnora 同款注释"The document title sits outermost"——锚点对照 1 ①）；生成侧 prompt 同构（主干二稳定段在前）让 KV Cache 注记在组装与生成两处成立同一纪律。换边条件：无（卡面合同+结构判断，不随规模变）。
5. **A/B 对照的查询侧口径：指代补全当给定输入，不发明会话改写模块。** 备选"本节内实现指代消解"（把'它'在查询侧解析成 N-2 井）：否决理由——会话层指代补全是问答链上游的职责（卡 m6"Agentic RAG 追问支线只讲设计"——m6 卡面对追问支线的既定档位），检索稿越权实现=框架面越界；且对照实验的变量冻结原则要求查询侧两库同串（书实验 3-10 同款：同一查询两库并排检索）。落定：对照查询串固定"N-2 井的日产油量"（补全后形态当给定输入），病灶叙事明确在块侧（PRD F31 业务逻辑要点原话）。换边条件：无（设计范围边界框架内无第二条路；指代补全机制若后续立项，归 m13/问答链）。
6. **生成失败降级为"无摘要段组装"，不整批失败回滚。** 备选"摘要生成失败→整报告入库失败回滚"：否决理由——离线管道可用性被 LLM 故障绑死（网关抖动=报告进不了库），且索引质量降档（少一段摘要）与入库失败（零索引）不是一个量级的损害；重试到死则把网关既有重试面（卡 m2 num_retries/冷却）架空。落定：降级闸（主干二③）+组装降级位（主干三①）+账本 None 注记（重建/重算可补）——降档不失败，"无据不答"式的硬闸留给生成侧（设计稿 10），索引期的闸原则是"如实降档"。换边条件：无。
