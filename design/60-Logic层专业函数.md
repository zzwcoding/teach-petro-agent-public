### 主干二：calculate_decline_risk 函数体——三路会诊（W-F46-1 核心）

笔记一 §9.6 开场与五步链原文（引用主位——逐字）：

> Agent 查到对象、拿到信息后，很多场景还需要**调用封装好的业务逻辑**——为什么不让 LLM 自己算？例：客户问延误风险等级，没有 Function 时 LLM 只能说"看起来有风险"——这不是企业用户能接受的答案。
>
> 有了 Function，Agent 调用 calculateDelayRisk 这类函数计算影响范围：查过去 90 天同路线延误数据 → 读承运商履约评分 → 调天气 API 看目的地未来 24 小时有没有暴雨等恶劣天气 → 运行延误概率预测模型 → 综合打分输出 high/medium/low——一个结构化的结果，而不是"某某原数据"。

正文解释：三路会诊就是 笔记一 calculateDelayRisk 五步链的油田版——但对照的重点不在"像"，在**每一路的输入都是治理过的数据源**（A.2 核心事实源/A.5 措施台账/A.2+A.6 双源含水），每一路的公式与口径都是设定书既有的（指标 3 公式逐字/事故 7 注记/指标 5 争议），函数没有发明任何业务事实，它做的事是**把散在三张表里的证据按写死的规则会诊成一个结论**。这就是"专业判断归函数"的实质：判断不是模型的联想能力，是**公式+规则表+口径注记**三件套；换一个模型来调这个函数，结论一个字不变——结论的稳定性来自函数体，不来自模型的发挥。依据列表的四件套（路名/表源/数值/口径）让老王可以逐条对账：D 值去 A.2 重算、措施行去 A.5 查、含水去 A.2/A.6 核——"结论+依据"的合同形状（W-F46-2 期望栏）从这里长出来。

## 关键判断的取舍记录

1. **定级数字全部替身化：机制真实，数字演示。** 备选"给出'行业通行'的递减率阈值与真实 D 值区间增强实操感"：否决——零代码设计稿无实测口径，编造阈值与 D 值=发明业务事实的近亲（设计稿 58/59 取舍 6 同款纪律对数字生效）；阈值取多少是平台运营配置（跟区块开发政策走），不是本设计稿能钦定的。落定：D=0.18、阈值三档、含水 60% 线、12 个月窗全部标注替身（主角数据④⑤），机制（三路会诊+规则表+口径注记）真实可走查——且**公式不是替身**：指标 3 年化指数拟合 q(t)=q_i·e^{−Dt} 是设定书 §3 逐字既有，读者拿走的是闸与公式的形状，不是数。换边条件：无。
