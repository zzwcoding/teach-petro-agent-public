### 主干一：Generator.answer_or_fallback——分岔判据与兜底两态（W-F33-3 的本体）

def answer_or_fallback(self, query, ranked) -> Answer:
    # 主干判断①分岔判据=设计稿 10 既有判据零改动（候选空或精排全低分——W-F6-5 同一判据；
    #   本节不改判据只接分岔：判据为假 → 原路走既有 answer 带引用生成）：
    if not 候选空(ranked) and not 全低分(ranked):
        return self.answer(query, ranked)          # 既有签名按字引用（设计稿 10 地盘，零改动）
    # 主干判断②分岔到兜底两态（按库配置二选一——CONTEXT.md"兜底策略"词条：
    #   "固定文案或自由回答+明确标注，二选一按库配置"）：
    if self.兜底策略 == "固定文案":
        #   固定文案态=设计稿 10 无据拒答闸收编：固定话术原样出、零生成调用零记账——
        #   反断言：本态行为与设计稿 10 升级前逐字一致（取舍 4）
        return 固定话术应答(固定文案)               # 不报错不编造：话术即答案，无模型调用
    # 主干判断③自由回答态：检索无据→换提示词走一次生成调用（生成调用≠编造——
    #   提示词合同两件事：①不用带引用系统提示词（"仅依据检索内容作答"与兜底目的
    #   正面冲突，WeKnora 同判——引用块下）；②回答必须带"未依据报告库"标注；
    #   ③数据边界提示词与问答主链共用一份（m19 会师的 WeKnora 侧——主干三判断②））
    回答 = await 流式生成(兜底提示词(query), 系统提示词=兜底合同)
    return Answer(内容=回答, 标注="未依据报告库")   # 标注是合同不是装饰——漏标注=冒充检索依据

### 主干三：RefExpander.expand——流式展开状态机（W-F33-1 前半句 + W-F33-2 的本体）

```text
伪代码 — app/rag/references.py:RefExpander.expand（卡 m6 公开签名逐字：
         expand(stream) -> stream；卡面注释"cN 引用别名流式展开成带 chunk_id 的公开引用；
         未知别名 fail-closed 直接删除（F33）"是本函数的结构合同）

def expand(self, stream) -> stream:
    # 流式状态机：逐帧喂入、按帧出料；半截标签扣在 pending 里不上线（W-F33-1"流式展开"）
    for 帧 in stream:
        缓冲 = self.pending + 帧; self.pending = ""
        while 缓冲:
            idx = 缓冲.find("<")
            if idx < 0:
                出料(缓冲); break                     # 无标签纯文本直通（保住普通流的边打边出）
            出料(缓冲[:idx]); 缓冲 = 缓冲[idx:]
            if 是引用标签开头(缓冲) and ">" not in 缓冲:
                self.pending = 缓冲; break            # 半截标签：扣住等下一帧（不上线不猜内容）
            if 是引用标签(缓冲):
                end = 缓冲.find(">"); 标签 = 缓冲[:end+1]; 缓冲 = 缓冲[end+1:]
                出料(self.展开单个(标签)); continue    # 完整标签交展开闸（下面）
            if 是模型直写公开标签(缓冲):               # <kb>/<web> 是系统专属输出——模型直写即删
                缓冲 = 缓冲[缓冲.find(">")+1:]; continue
            出料("<"); 缓冲 = 缓冲[1:]                 # 普通小于号照常出（数学/比较不受影响）
    # 流末排水：pending 里若还是半截引用标签 → 丢弃（流中断也不让半截标签上线）
    尾料 = self.pending; self.pending = ""
    出料(尾料 if not 是引用标签开头(尾料) else "")
    # —— 出料() 的唯一出口在装配后的出站侧单点（取舍 6）：公开引用形状一处可查 ——

def 展开单个(self, 标签) -> str:                       # 展开闸：fail-closed 的所在（W-F33-2）
    代号 = 提取 id(标签)
    # 主干判断①授权闸（先于查表）：代号不在可引用集 → 返回空串——整段删除不渲染
    if 代号 not in self.可引用集:
        return ""                                     # fail-closed：删，不是报错不是占位（取舍 1）
    # 主干判断②查表展开：合法代号 → 带块号与报告名的公开引用（报告名=登记时的文档标题；
    #   属性转义防注入——报告名里若藏引号，转义后原样展示不越属性边界）
    块号, 报告名 = self.别名表.查(代号)
    return f'<公开引用 doc="{转义(报告名)}" chunk_id="{转义(块号)}" />'
```

闸在哪：①登记闸（主干二①——别名表只吃当次检索结果集，模型不可见 ID 不入表，设计范围边界红线）；②授权闸（主干三展开闸①——表里有 ≠ 可引用，可引用集只认本轮检索证据，历史代号与目录代号照样删）；③fail-closed 删除闸（主干三展开闸——未知代号/模型直写公开标签/引用协议关闭三个出口全部删除，W-F33-2 本体）；④半截标签线闸（主干三 pending 位——半截引用标签不上线，流末排水不丢明文）；⑤引用先行时序闸（主干四——引用事件先于答案推送，次序错=引用送达不了，WeKnora 历史 bug 教训）；⑥兜底不报错闸（主干一——检索空/全低分走两态兜底，信号不是故障；停止先判防覆盖；标注合同防冒充，W-F33-3 本体）；⑦网关既有面（自由回答态的生成调用沿 m2 重试/冷却/记账契约——本节零新增异常类型零新增网关能力）。拦完数据去哪：未知代号=整段删除零痕迹（不报错不占位——伪造引用不值得一个解释位）；半截标签=扣留等拼帧或排水丢弃（不出残迹）；检索空=固定话术或标注过的自由回答（不冒充不编造）；投毒诱导=入站被降权+出站被删除（两层各记各的账）。

## 关键判断的取舍记录

1. **fail-closed 是删除不是占位，占位是给伪造者的一个显示器。** 备选一"删除引用标记、保留正文原样"：否决理由——引用标签本就是句内证据绑定标记，正文不含标签（本设计稿与 WeKnora 同形：`<ref>` 是自闭合标签不是包裹标签，"删除整段标签"与"保留正文"天然不冲突；真要做"包裹正文引用"，删除才面临丢正文问题，WeKnora 为此把引用设计成自闭合——标签粒度本身就是取舍的一部分）；备选二"未知代号渲染成『引用失效』占位"：否决理由——占位给伪造引用一个可观测的 UI 效果，投毒者只要塞一行"引用 c99"就能让任意答案上出现自己设计的显示痕迹（可点击性、样式、文案都成了攻击面）；删除让伪造在输出层**零副作用**——不可见、不可点、不进引用列表，伪造行为的全部收益归零。落定：授权闸查无此号返回空串整段消失（主干三①；WeKnora 同判——"Unknown handles fail closed and disappear"）。误删的代价核算：合法代号只会因表生命周期错位而查无（请求级新建表+当次登记，正常流不会发生），损失上限是"少一条引用"而不是"错一条引用"——宁可少引用不可错引用，与设计稿 10"宁可拒答不可虚构引用"同一偏置方向。
2. **别名表=当次检索结果集+请求级生命周期，不做全库长表。** 备选"全库预分配长表"（每块入库时领终身代号，模型可引用全库）：否决理由——①表大了模型没见过几行，"引用没发过的代号"与伪造无从区分，授权闸形同虚设；②终身代号把内部块号映射固化成一个可被投毒内容猜测枚举的命名空间（低熵代号的"低熵"前提是**表小**）；③跨轮续用让历史会话的代号成为永久攻击词汇。落定：一次回答一张表、从 c1 顺序发号、只登记当次候选集、跨轮不续用（主干二①；WeKnora 同构——"Handles are never persisted or accepted across requests"）。多轮对话的正确姿势：上一轮答案里的公开引用已经带块号（展开后落库的是公开形状），历史轮复述在新表里查无旧号照删——用户看到的历史引用是**已展开的公开引用**，不需要旧代号活着。
3. **引用事件先行是管道时序义务，不是前端补拉能补救的风格问题。** 备选"管道返回后前端刷新时再拉引用列表"：否决理由——WeKnora 实测这是一次真实事故的修法（引用事件排在管道返回后，`complete` 已关流，"frontend only saw citations on refresh"——用户只在刷新后才看到引用面板）；流式会话的时序合同里"连接还开着"是事件可达性的前提，不是可以事后补救的排序偏好。落定：推送引用事件编排在答案流启动之前（主干四★；兜底链同次序——兜底答案也要先发引用事件，空列表也发，UI 语义一致）。配套判断：引用列表（检索结果 UI）与内联引用（答案内展开标签）是两个通道两件东西（WeKnora 引用块下"remain available even when inline citations are disabled"）——先行的是列表通道，展开的是内联通道，W-F33-1 两半句各归各的通道。
4. **兜底两态按库配置，拒答闸收编为固定态——设计稿 10 零改动是反断言不是巧合。** 备选一"兜底只有一个固定话术态"（设计稿 10 原样）：否决理由——检索空≠用户问题不合法，"附近有什么好吃的"类闲聊问题固定话术体验差，自由回答+标注是产品面上真实存在的第二态（WeKnora 两态枚举与逐层降级实测）；备选二"自由回答态也走 answer 的带引用提示词"：否决理由——带引用提示词合同是"仅依据检索内容作答"，与兜底目的正面冲突（WeKnora 注释原话 "directly contradicts the fallback's purpose"），硬套会让模型在"无据"与"必须作答"之间打架，输出要么拒答循环要么幻觉引用。落定：`answer_or_fallback` 函数体内三分支（原路/固定态/自由态），固定态=设计稿 10 闸零改动收编（反断言：配置固定态时行为与升级前逐字一致），自由态=换提示词+标注合同（主干一③）。默认档如实备案：WeKnora 会话链缺省 fixed（`session_knowledge_qa.go:87-90` 实测）、Agent 配置缺省 model（`custom_agent.go:586-587` 实测）——本设计稿按库配置不设全局默认（CONTEXT.md 词条"二选一按库配置"），走查推演 3 以固定态为缺省样例（保守档与设计稿 10 行为连续）。
5. **res:// 资源句柄别名只讲设计一句带过——它和 cN 是一对背向设计，对偶讲清即止。** 设计范围"明确不讲的"：不做 res:// 全套。落定的一句设计：高熵存储句柄（`res://0001`）与低熵引用代号（cN）是同一注册表机制的两个背向应用——cN 要"低熵"好让模型轻量引用、防的是**伪造**（表小、当次、fail-closed）；res:// 要"高熵"防模型**复述篡改**（把对象存储 URL 抄错抄漏导致引用失效，用短句柄代替长 URL 让模型无从篡改）。本设计稿只在取舍里留这一句对偶，展开闸的 res:// 孤儿过滤（WeKnora stream.go 的 orphanResourceStreamFilter）零展开——全套归平台后续稿（若立项）。
6. **展开器收在出站侧单点，公开引用形状一处可查。** 备选"生成侧直接约束"（提示词管住模型只发合法代号，出站不设闸）：否决理由——提示词是软闸可被诱导顶掉（设计稿 15"代码即规则"同一教训：提示词写着只能 SELECT，模型仍可能给 DELETE），出站闸才是"做不了"；且"公开引用形状"（什么算一条合法引用）必须只有一个定义点，散在多处洗白等于没有形状。落定：装配后的出站侧单点过闸（主干三出料唯一出口），入站侧的信任打标（设计稿 25）与出站侧的 fail-closed 删除各守一个方向——装配打标管"进去的东西怎么被对待"，展开闸管"出来的东西怎么被信任"，两侧合起来才是完整防线（取舍 1/主干三判断②的同构总结）。
