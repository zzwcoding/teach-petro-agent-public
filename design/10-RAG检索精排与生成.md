**为什么"只看排名"反而稳**（事实对照）：两路原始分都没有跨路可比性——向量路 score=1−distance 可为负、跨查询不可比、无"及格线"含义（设计稿 08 主干一口径注释原文）；BM25 是无界正分，分值随语料统计漂移。任何"先归一化再加权"的方案都要对两路分数的分布形状做假设（min-max 假设线性、z-score 假设正态，且分布逐查询漂移）；RRF 只消费两路都可靠的那一个信息——**谁排在前面**，把这些假设整个去掉。代价是丢掉原始分里的相关性强度信号（书口径明说"RRF 简单稳健但只利用了排名"），这个信号由下一站精排用更强的匹配范式补回。

### 主干三：bge-reranker 精排——跨编码器逐对打分的代价与收益（W-F6-3；FakeReranker 换真身）

```text
伪代码 — app/rag/ranker.py:Ranker.rerank（m6；签名按卡逐字：rerank(query, candidates, top_n) -> Ranked）

# 模块级惰性单例——官方构造形状（官方文档）：use_fp16 提速（轻微降质）；CPU 部署走 fp32 属部署参数非形状差异
_reranker = FlagReranker('BAAI/bge-reranker-v2-m3', use_fp16=True)

def rerank(query, candidates, top_n) -> Ranked:
    if candidates.候选为空:
        return Ranked(候选=[])               # 上游已短路，防御位照写——闸的入口形态保持单一
    # 主干判断①问段配对：查询与每个候选块原文拼成一对——跨编码器把问段拼成一段完整输入逐词比对
    #   （书口径），不像双编码器各编各的向量；精度换时延，代价 ∝ 候选数（每对一次完整前向）
    对 = [[query, c.原文] for c in candidates.候选]
    # ★ 设计范围红线调用形状（官方文档）：批量 compute_score，normalize=True 经 sigmoid 映射到 [0,1]
    scores = _reranker.compute_score(对, normalize=True)
    # 官方口径注释：返回 logit 经 sigmoid 的 [0,1] 分——全管线唯一跨查询可比的刻度
    #   （向量 1−distance 与 BM25 分都没有"绝对高低"含义）——拒答阈值因此只能收在这之后（取舍 2）
    # 窗口事实（官方文档）：transformers 等价用法 tokenizer max_length=512——块预算 1024（设计稿 09）超窗部分
    #   被截断，精排看的是块头部；切片取最大分是备选招（捣乱 B 取舍表），当前规模默认接受截断
    # 数据变形：候选按精排分降序稳定排序 → 截取前 top_n（默认 5）
    排定 = sort_stable_desc(candidates.候选, key=scores)[:top_n]
    return Ranked(候选=[Candidate + {rerank_score}, ...])
    # 异常去向：模型加载失败/推理异常 → 结构化精排异常上抛，本层不静默返回原序——
    #   "精排失败当没发生"会让融合序冒充精排序（取舍 4：fail-loud）
```

**双编码器 vs 跨编码器，代价差在哪**（书口径事实对照）：

| | 双编码器（bge-m3 稠密路，召回层） | 跨编码器（bge-reranker-v2-m3，精排层） |
|---|---|---|
| 输入 | 问与段各自独立编码成向量 | 问段拼成一段完整输入 |
| 在线算什么 | 段向量离线算好，在线一次近邻查询 | 每对一次完整前向，逐词交叉比对 |
| 快慢 | 快——在线代价与库规模对数相关 | 慢——代价 ∝ 候选数，**无法离线预计算** |
| 准度 | 抓不住问段深层匹配（各编各的） | 高——逐词斟酌，能识别"N-7 对不上 N-2" |
| 本管线职责 | 千级块里海选 top-k | 融合候选池（几十块）里定序 top-n |

**拒答话术而非硬编——边界条件的写法**：两个反面各是什么——（a）检索层把空候选伪装成命中让模型硬答（设计稿 08 红线原文："任何一层不许把空库伪装成命中"）；（b）生成层不设据的边界，把模型自由发挥当回答。正路是**双闸**：硬闸在代码里判分（空候选/全低分两个判据，拒答时根本不起模型调用，话术由代码直接产出）；软闸在系统提示词里（给了块但块撑不起答案时，模型按纪律三自陈"报告库没有依据"）。两层各拦各的：硬闸拦"检索层面无据"，软闸拦"候选在场但撑不住"——后者如"图 3 的孔隙度分布"（设计稿 09 取舍 4 的伏笔：图题块被召回、块内只有标题没有数据），生成层无据可引时软闸兜底，其细粒度质量判定归设计稿 11 的 faithfulness 指标。

## 关键判断的取舍记录

1. **融合只用 RRF，不做"分数归一化加权"**——备选：两路分数 min-max/z-score 归一化后加权求和，保住原始分里的相关性强度信号。不选：归一化要对分数分布形状做假设（线性/正态），而分布逐查询漂移——"含水率"这类查询与"N-2"这类查询的两路分数分布完全不同形，一套静态权重顾此失彼；RRF 只消费排名这一两路都可靠的信息，假设为零（书口径明说其"简单且稳健"）。付出：强度信号丢失。换边条件：两路分数可标定（如向量路换 cosine 空间加温度标定、BM25 换归一化变体）且设计稿 11 评估证明加权融合对 nDCG 有显著增益时，在 `_fuse_rrf` 内换策略——Candidates 形状与签名不动。
2. **拒答阈值收在精排之后，不在召回层**——全管线只有 normalize=True 的 sigmoid 分跨查询可比（官方文档：映射到 [0,1]）；向量路 1−distance 可为负且"没有及格线含义"（设计稿 08 口径注释原文）、BM25 无界分随语料漂移——在召回层设阈值等于给没有刻度的尺子刻刻度。卡面"Retriever.search 低分/空候选返回空"的机械半边由上游兑现（BM25 零分已在 m14 滤除、双空在融合段短路），语义级"全低分"判分落在 Generator 闸——W-F6-5"返回空/低分→拒答分支"两个分支都兑现，且捣乱 C 证明只有跨编码器分能识别"语义近但井号失配"这种该拒的情形。换边条件：查询嵌入件换到可标定模型（校准集就位）时，召回层预警阈值可作为降级快捷道补入，判据主位不变。
3. **候选充实走 m3 账本批查，不扩 m14 的 Hits**——备选：Hits 加 text/metadata 字段（向量路 query 的 include 本就取回了 documents/metadatas）。不选：改 m14 六函数接缝属扩卡修订；且 Hits 是两路共同形状——BM25 语料只有 tokens 无原文，扩字段后两路填充不对称，反而破坏设计稿 08 立下的"同形状"契约。m3 账本是块元数据的唯一落点（设计稿 09 主干四），融合后按块号批查一次带回原文+报告名+页码，上下文装配与引用校验共用。付出：融合后一次批量账本查询（当前规模毫秒级）。换边条件：账本查询成为延迟瓶颈，或块原文需要多版本共存回溯时，随后续扩卡定形一并扩（签名缺口声明的同一裁定点）。
4. **精排失败 fail-loud，不让融合序冒充精排序**——备选：精排异常时降级返回融合序（管道不断服）。不选：设计范围承诺"排得准"（W-F6-3 验收语义），静默降级让融合序顶替精排序——排序质量问题以"答案看似正常但引用次序不对"的形态潜伏，比故障更难查；结构化上抛后调用方折错误帧，用户看到"检索服务暂时不可用"而不是不可信的答案。换边条件：可用性压倒精确性（现场演示模式）时，降级返回融合序并显式标注"未经精排"——语义透明是底线。

## 锚点对照精要

**RAG基础·混合检索三阶段**（卡 `m6` 锚点 K-B 第一项）
书：典型混合检索流水线三阶段——并行检索（稠密/稀疏两引擎各自召回一部分候选）、结果融合（两路得分尺度与分布不同、不可直接比较，常用 RRF）、神经重排序（跨编码器对融合候选池排名靠前的 N 个候选逐一精确打分）；重排序不是为了"补救 RRF 丢掉的得分"才存在，它换用了更强的匹配范式，且不替代融合——融合负责产统一候选池、重排序负责在池上精排。落点：三阶段各落本设计稿一站（主干一/二/三），设计稿 08 已交第一阶段的两只引擎与同形状 Hits。

**RAG基础·RRF（倒数排名融合）**（同锚点）
书：RRF 完全抛开原始得分、只看排名，文档综合得分 = Σ 1/(k + rank)，k 是平滑常数（常取 60），用于压低排名最靠前几个位置之间的得分差距；RRF 简单且稳健，代价是只利用排名信息、丢失原始得分中的相关性信号。落点：主干二逐条照写（k=60、rank 从 1 起）；丢掉的强度信号由精排位用 cross-encoder 补——与书"重排序不为补救 RRF"的判断一致，本设计稿精排有独立理由（问段深层匹配）。

**RAG基础·双编码器 vs 跨编码器**（同锚点）
书：双编码器为查询和文档独立生成向量、靠向量运算比相似度，速度极快但抓不住深层匹配，适合海量初筛；跨编码器把查询与候选文档拼接成一段完整文字送入模型逐词比对、输出一个综合相关性分，慢得多但更准；BAAI/bge-reranker-v2-m3 即跨编码器架构。落点：本管线召回层是双编码器（bge-m3 稠密路，段向量离线预计算）、精排层是跨编码器（FlagReranker 逐对前向）——"可否离线预计算"是两者职责分工的硬边界（主干三对照表），也是精排只能用在少量候选上的原因。

**RAG基础·检索质量三指标（表 3-3）**（同锚点）
书：recall@k（前 k 结果含正确答案的查询比例——书注：此处口径实为命中率 hit rate，与学术 recall@k 在多相关文档时不等）、MRR（首个相关文档排名倒数的平均——"找到得够不够靠前"）、nDCG（归一化折损累积增益——"整个排序列表的质量"）；工业界另有"检索失败率"（正确信息不在 top-20 的查询比例）。落点：本设计稿的 top_k/top_n 参数就是这三指标的旋钮；调优判据归设计稿 11（RAGAS 评估入口），本设计稿只把参数位留出并把口径接稳。

**docs/tech-stack/openai-embedding.md · 官方 hybrid+rerank 管线与 bge-m3 查询侧**（卡 `m6` 锚点 K-B RAG 全流程→嵌入文档）
该文档：官方建议管线即 hybrid retrieval（embedding + sparse/BM25 类词项权重）+ re-ranking；bge-m3 查询时不需要加 instruction（与 bge-v1.5 系列不同），稠密相似度用内积。落点：主干一查询侧只取稠密位、零 instruction；"bge-m3 稠密输出 + rank_bm25 分词倒排 + FlagReranker 精排"即该管线的设计落地形态（设计稿 09 交燃料、本设计稿交在线半程）。

**docs/tech-stack/openai-embedding.md · bge-reranker-v2-m3 的官方调用形状**（设计范围框架红线锚）
