> **红线声明**：本设计稿零真实可运行代码。全部代码块均为**伪代码**（块首标注"伪代码 — 文件:函数"或"伪代码（时序推演，非代码）"）——例外仅 WeKnora 生产代码**原注释引用块**（逐字照抄英文注释原文，块首注文件行号与 commit 号，解释全在正文不混进引用块；块内"…"为行省略号，省略行不参与断言）。公开签名取自模块卡逐字：`SummaryGen.run(doc) -> SummaryChunk` 与 `QuestionGen.run(chunks, batch=20) -> [QuestionChunk]`（卡 `m22`——本节就是这两员的机制本体，卡面注释"全文档摘要×1，入索引带 chunk_type=summary（F37）"/"每 20 块一批生成'可能被问的问题'，入索引带 chunk_type=question（F37）"是两件的结构合同）；`PostProcess.dispatch(doc_id, strategy) -> None` 与 `ChunkPicker.pick(chunks, purpose) -> [Chunk]`（卡 `m22`，设计稿 46 地盘——本节只兑现既有发车位的函数本体，枢纽零换构零触碰）；`IndexingStrategy.for_kb(kb_id) -> Strategy` 与派生判定 `needs_embedding`（卡 `m22`，设计稿 46 既有面——扇出判据沿设计稿 46 取舍 1 落定）；`VectorStore.upsert(ids, embeddings, documents, metadatas) -> None` / `Bm25Index.build(chunk_ids, tokens) -> None` / `Bm25Index.save_snapshot() -> None` 等**六函数**（卡 `m14`，设计稿 08 地盘——卡面扩容注释"FAQ 块/摘要块/问题块/图片子块（image_caption/image_ocr）复用同一六函数双写，metadatas 带 chunk_type 区分——检索侧可按类型过滤或加权；删除按知识 ID 级联（先清后写守幂等）"是本节索引侧与删除侧合同）；`Gateway.chat(messages, model_alias, stream=False, tools=None)`（卡 `m2`——摘要与问题生成走网关既有 chat 面，零新增网关能力）；`Repository.save_chunk_meta(meta) -> None` / `Repository.list_chunk_meta(doc_id) -> list[ChunkMeta]`（卡 `m3`）。**框架红线：无新增**（设计范围声明——替身沿卡 `m22` FakePostProcess（固定扇出轨迹）与卡 `m14` FakeIndex 既有形状，零新替身）。
> **加法家族归位声明（"索引期做加法 vs 运行期做减法"区分在案——W-F37-3 后半句的合同位）**：**索引期做加法**=入库时往索引里加"检索替身"——面包屑与前缀摘要（设计稿 45，块级加法）、FAQ 问答块（设计稿 49，策展加法）、caption/ocr 子块（设计稿 50，图面加法）、**摘要块+问题块（本节，文档级概括加法+块级问法加法）**——加法花**离线预算**买命中率；**运行期做减法**=查询时从候选池里裁——RRF 融合与精排（设计稿 10）、检索降级（设计稿 46）、复合重排（设计稿 48）——减法花**在线预算**买精确度。两族动作方向相反、预算科目不同、调参互不冒充：命中率不够先查加法（该生成的替身生成了没有），精确度不够先查减法（该裁的裁了没有）。本节两员是线 A 加法家族的最后两名成员。
> **产物块形状声明（chunk 行族成员扩展，取舍 1）**：摘要块与问题块是 chunk 行族新成员——`chunk_type="summary"/"question"`（卡 m14 扩容注释点名"摘要块/问题块"）。**摘要块=文档级块**：一份报告恰一条（块号=文档号+`#summary`），`parent_id=None`——它没有宿主章节，设计稿 44 的孤儿降级通道对它如实走（"parent_id 空或父块行查无 → 子块独立出，不报错"——孤儿降级是"如实"不是"兜底"，设计稿 44 既有面）；WeKnora 实测摘要块挂首个正文块 ID（`ParentChunkID: textChunks[0].ID`，:1491）——其块族无父子分家，挂首块是"给检索扩写一个抓手"；本设计稿两级行族下挂首块会错挂"第一章"，置空更诚实（取舍 1）。**问题块=逐问成块**：一个问句一块，`parent_id=来源正文子块的章节父块号`——命中问题块回读的父块与命中来源正文子块回读的父块是**同一行**（回捞会师：`ParentStore.fetch_parents` 既有面零改动）；`page` 随来源子块落账（引用回链原文位置的锚——问题块自身无页码，它只是问法投影）。WeKnora 实测问题**不是独立 chunk**（问句存来源块元数据+每问一条索引条目、`ChunkID` 指回来源块）——本设计稿按卡面合同独立成块，差异取舍 1 备案不洗白。
> **批形状声明（工单形状不是调用形状，取舍 2）**："每 20 块一批"的精确读法：**批是工单/重试/取消/整批入索引的粒度，不是 LLM 调用粒度**——一批 20 块在批内**逐块各调一次**模型（每块带着前后文生成自己的问句），批收尾整批一次嵌入写入。WeKnora 注释原文同构（"one subtask per window … so a huge document doesn't spawn thousands of tiny tasks"+批任务"do one embedding BatchIndex over the whole batch"——:236-241/:593-598 实测）；计数口径随之分家：40 块文档=**2 张工单+40 次调用+120 个问题块**（每块缺省 3 问——WeKnora 问句数夹取缺省 3 上限 10 的设计演绎取缺省值，:2121-2126 实测）。
> **接线边界**（对既有设计稿只调用不重讲）：对设计稿 46 **只兑现不换构**——dispatch 内 `SummaryGen.run(doc_id)` 与 `for 批 in 分批(问题名单, 20): QuestionGen.run(批, batch=20)` 两处发车位是设计稿 46 设计稿注记"设计稿 51 地盘"的兑现位，本节落定两员函数本体，dispatch 既有行（块清单/名单先行/开关闸/计数收敛/多模态路）照抄零触碰；**挑选闸零触碰**——问题名单=`ChunkPicker.pick(子块清单, purpose="问题生成")` 既有面，本节只消费名单（WeKnora 注释同构："Link-only text chunks … are skipped: the LLM has nothing to ask about and tends to echo the few-shot example"——:216-224，设计稿 46 主干三已引，本节不重复引用块）；对设计稿 44 **行族只加成员不换规则**——产物块全是子块层新成员，"父块不索引"INV 照守（父块照旧只入 m3），孤儿降级通道零改动（摘要块 parent_id=None 如实走）；对设计稿 45 **零触碰**——产物块的索引输入**不经**索引投影组装（面包屑/前缀摘要是正文子块的加法，产物块自身就是加法，不再叠加法——取舍 5），正文子块的索引输入组装照旧；对设计稿 10/47/48 **零改动**——产物块与正文块同池同闸同引用登记面，设计稿 48 复合重排的 chunk_type 判定位本节仍不启用；对设计稿 49 **家族对照不接线**——FAQ 是人工策展的问答对（问与答成对入册）、问题块是自动生成的问法投影（只有问没有答，答案在原文里）——同族不同源，仅锚点对照；对设计稿 50 **零接触**——caption/ocr 子块不进问题名单（挑选闸既有分流：设计稿 46 主干三"caption 丢弃"），摘要的图片信息增强是 WeKnora 的加固件（本设计稿一句留痕零展开，锚点 ⑨）。

## 关键判断的取舍记录

1. **产物块形状：问题块独立成块（逐问一块）、摘要块文档级 parent_id=None——卡面合同优先，WeKnora"元数据+索引条目"形状如实备案差异。** 备选"照 WeKnora 形状"（问题不建独立块：问句存来源块的元数据列表+每问一条索引条目、`ChunkID` 指回来源块，命中直接落来源块实体）：否决理由——卡 m22 公开签名 `QuestionGen.run(chunks, batch=20) -> [QuestionChunk]` 明文返回 QuestionChunk、卡 m14 扩容注释明文"FAQ 块/摘要块/问题块/图片子块复用同一六函数双写，metadatas 带 chunk_type 区分"——问题块是 chunk 家族成员是卡面合同；WeKnora 不建块是其"chunk 平族+元数据随带"架构的产物，W-F37-3 的观察位"问题块命中排名"在两种形状下观察等价（WeKnora 是问题条目命中带出来源块、本设计稿是问题块命中），但块形状不同。落定：逐问成块（WeKnora 每问一条索引条目、复合 SourceID 同构——检索粒度=问句，多问挤一块会让向量被问组稀释，精度受损）；问题块 parent_id=来源子块的章节父块号（回捞会师——命中问题块与命中来源子块回读同一父块行）；摘要块 parent_id=None（文档级——WeKnora 挂首块 ID 的形状在设计稿 44 两级行族下会错挂"第一章"，孤儿降级如实走比错挂诚实）；差异如实备案不洗白。换边条件：设计稿 44 行族引入"块级元数据随带"检索通道时复评（WeKnora 形状的接入成本收在主干四判④一处）。
2. **批形状=工单形状不是 LLM 调用形状——批管重试/取消/整批入索引，批内逐块调用。** 备选"一批一次调用"（20 块拼一个提示词一次生成 60 问——调用费省 20 倍）：否决理由——拼批调用把 20 块内容塞进一个上下文，每块问句的块归属与前后文边界全糊（问句要带着**它自己的**前后文才问得准——WeKnora `generateQuestionsWithContext` 每块带 prev/next 的形状就是为此）；且一批失败=20 块全重做，块级失败隔离没了（WeKnora 批内单块失败计数留痕继续 ：2219-2224 实测）。落定：主干四判③批内逐块调用（每块 1 次带前后文）；批的三个收益照单全收——任务数有界（WeKnora 注释"5k-chunk doc becomes ~250 tasks instead of 5k"）、批级重试/取消粒度、整批一次 BatchIndex（:593-598 注释原文，主干一引用块）；计数口径随之分家：40 块=2 工单+40 调用+117–120 问题块（走查推演 2 的三本账）。换边条件：无——这是 WeKnora 与卡面一致的形状，不存在另一边。
3. **摘要输入截断=头中尾采样不是硬截断。** 备选"砍尾保头"（超出上限直接截前 8K 字符）：否决理由——报告的结论常在尾部（完井结论/测试产量段），砍尾=摘要系统性丢结论，而摘要块恰恰是"这份报告说了什么"的第一入口；WeKnora `sampleLongContent` 实测头 60%+居中段+尾 20% 三段采样、省略段打 `[...content omitted...]` 标记（:1122-1161）——保两头弃中段，因为头是"是什么"、尾是"结论是什么"、中段是过程性内容。落定：主干二判③头中尾采样（上限 8192 字符——`defaultMaxInputChars` :794 同构设计演绎）。换边条件：无——纯费用换质量的旋钮，设计演绎取 WeKnora 同款。
4. **内容充分闸判据=剥图片标记后真文本字数，失败不回退首块。** 备选一"块数>0 就调 LLM"（分块成功即有内容）：否决理由——纯图片占位文档块数再多也是空气（设计稿 46 挑选闸"防复读"病灶在摘要路的变体——无正文调模型只会得到模型的想象）；WeKnora `checkSufficientSummaryContent` 同构（真文本不足 `minTextContentRunes=10` 字拒调，`wiki_ingest.go:2972` 实测）。备选二"LLM 拒调后回退首块当摘要"（库概览总得有东西显示）：WeKnora 明文否决——"we deliberately do NOT fall back to the first chunk's raw content, since that chunk is typically just a bare markdown image reference and surfacing it in the description is misleading"（:1406-1409 实测）；本设计稿沿判：摘要失败留痕，零块合法交付（设计稿 46/50 终态口径同源）。配套纪律：空白回复判失败不落空串（`validateSummaryOutput` :880 同构——"persisting description=\"\" as completed"是把失败装完成）；WeKnora 的终态兜底（重试耗尽后首块按 rune 截 500 字符——`firstTextChunkSummaryFallback` :894，中文不被拦腰切断）如实记为其库概览半边的加固件（本设计稿一句留痕零展开——库概览本就不是本节检索块半边）。
5. **产物块索引输入两员分治：问题块=报告名+问句、摘要块=摘要文直用；都不走设计稿 45 投影装配面。** 备选"统一都叠设计稿 45 面包屑+前缀摘要"（索引输入组装既有面复用，一套装配通吃）：否决理由——问题块是短问句，问句本身不带文档指称（"为什么要循环洗井?"——哪口井哪份报告?），报告名是问题块唯一的文档锚；WeKnora `buildKnowledgeIndexContent` 原注释把边界说死："adds **only** the document title to searchable text. Custom metadata stays document-scoped: it is supplied once to the answer model and summary model, rather than repeated in every chunk embedding"——文档级信息一次供给，不在每个嵌入里重复，叠面包屑恰是把文档级信息重复进每个问题块的嵌入；摘要块自身就是文档级概括，再叠是重复叠加；文件名更是故意不进（主干二引用块原注释——不可靠信号+幻觉向量）。落定：主干三判②两员分治；设计稿 45 面包屑对正文子块照旧零触碰（产物块不经投影组装——它们自身就是加法产物，加法不再叠加法）。换边条件：问题块命中率评估显示"同报告多文档撞问句"成为主诉时，优先扩报告名锚（如报告名+日期），仍不上面包屑。
6. **两员共用库摘要模型别名——同一模型双温档（摘要 0.3 忠实/提问 0.7 发散），不设独立问题模型位。** 备选"问题生成独立模型别名"（提问要发散、用便宜大温度模型）：否决理由——卡 m22 依赖行只写"m2（摘要/问题生成走网关）"，独立别名是卡面没有的配置形状（伪代码红线：公开面零新增）；WeKnora 实测两员同源——摘要与问题生成共用 `kb.SummaryModelID`（`ProcessSummaryGeneration` :1400 与批路径 ：2114 同取 `GetChatModel(kb.SummaryModelID)`）。落定：主干二判⑤/主干四判③同别名调用；**双温对照**是这条取舍的设计要点——同一模型，摘要温度 0.3（忠实归纳，WeKnora :1099 实测）、问题生成温度 0.7+MaxTokens 512（发散提问+短输出，WeKnora :2312-2313 实测）：摘要是"把 100 页读成 1 页"的压缩任务（发散即幻觉），提问是"把陈述翻译成问法"的投影任务（太忠实只会复述原文问不出问题）。换边条件：评估显示提问质量受模型能力约束时，别名换挡是配置面的事（设计稿 07 网关模型清单既有面），管道零改动。
