### 主干一：to_otel_attrs——白名单映射出口，fail-closed（W-F29-1 的机器半边）

```text
伪代码 — app/observability/otel_map.py:to_otel_attrs（m12；签名=卡 m12 v3.2 注释逐字：
         to_otel_attrs(span_attrs) -> gen_ai.* 属性族）

# ── 第 0 步：映射表常量——白名单即合同（主干二两张表的机器可查形态，键名运行期零拼接）──
标准落位 = { "model_alias": ("gen_ai.request.model", 直传) }
    # 设计范围点名键逐行进此表（主干二映射表 B 标准落位段）；现状只有 model_alias 有袋内真源——
    #   usage/finish_reasons/system 三键登记在表注（落位形状在案、入袋空缺，取舍 2）
特有名册 = {"call_id", "cost", "agent", "thread_id", "verdict", "stage", "reason",
            "注记数", "error", "cost_breaker_tripped", "metric_ref", "SQL指纹", "审批档"}
    # 平台特有（OTel 无对应）显式名册——主干二映射表 B 特有段的键清单，逐键语义见该段

def to_otel_attrs(span_attrs) -> 属性族:
    # ★ 纯函数零副作用：不连网关、不读库、不回源 usage、不做单位换算——
    #   输入只有属性袋一物（"映射是出口不是新采集器"在签名上成立：单参数，无处接采集）
    标准出 = {}
    特有出 = {}
    for 键, 值 in span_attrs:
        if 键 in 标准落位:
            标准名, 变换 = 标准落位[键]
            标准出[标准名] = 变换(值)      # 主干判断① 白名单直传：标准键名只出自对照表
        else:
            特有出[键] = 值                # 主干判断② fail-closed：袋内未知键一律落平台特有——
                                           #   冒充标准键在结构上不可表达（捣乱输入的闸）
    return 属性族(标准=标准出, 平台特有=特有出)
    # 未落袋的设计范围点名键（usage 两键/finish_reasons/system）不进产物——空缺即缺省，
    #   不填 None 不填推算值（"不造"的运行期形态：宁空缺不造假，设计稿 06 宁缺毋假同款）
    # 异常去向：span_attrs 非映射袋形状 → 结构化上抛（出口对形状诚实）；映射零 IO，无业务错误路径
```

机制要点：
- **出口地位**：调用纪律=trace_run 落盘前对每 span 的 attrs 走一遍变形（设计演绎不接线）——采集接缝（start_span/end_span）、打点方（设计稿 19 接线）、落盘形状（trace_run）三者零改动，设计稿 06 取舍 3"日后要接平台只换 trace_run 的落盘出口"在本节落成第一块砖。
- **fail-closed 方向**：键的流向只有一个安全侧——表内键按表映射、表外键全落特有桶。出口永远不可能"顺手"发明一个标准键名：标准键空间在运行期是常量的值域（取舍 1）。
- **对账不切断**：平台特有桶不是垃圾桶——call_id 仍是与网关记账对账的锚（设计稿 19"树账分离"），出标准门后随平台特有标注同行，只是**不冒充** gen_ai.* 语义。

### Langfuse 演示说明（W-F29-3，文档段——设计演绎、不搭真实例）

> **声明**：本段只讲**形态**——不装 Langfuse、不建服务、不送真数据（设计范围框架红线；PRD F29"不做什么"行）。形态可复述的判据：读完能不看稿说出"同一 run 在视图里长什么样"。

**同一 run（run-t2s-1726877120）在观测平台视图中的三件形态**：

1. **trace 树**：一次问数 run 对应**一条 trace**——run_id 即 trace 身份（映射表 A 第一行的消费端兑现）；视图里整棵树与 `trace_run` 落盘树同构：运行根→意图澄清→选表→SQL 生成→安全校验→工具执行→结果校验，一次运行一屏可查（设计稿 06"体检表"类比的平台侧形态）。
2. **观察嵌套**：父子 span 映射为树状观察嵌套（"观察嵌套"沿走查断言用词）——"网关调用嵌在 SQL 生成之下"的嵌套关系原样可读，每个观察带起止耗时、标准属性族（如 gen_ai.request.model）与平台特有标注；错误观察（status=error 的 span）在树中可见——"哪一环慢、哪一环断"在平台上不再需要读日志行。
3. **评分挂接**：评估链裁决作为**评分记录**挂到对应 trace 上的形态——m18 结果比对 grader 三出口（pass/fail 带 diff/inconclusive）与稳定性"稳"标跑批结论，挂接在产生该结果的 run 的 trace 上，golden case 的对账结论可回指具体运行（"这条 trace 的结果与手算金标差多少"）——评估证据链（设计稿 23）与追踪树在观测平台的汇合形态，设计演绎推演、零实装。

**兼容性含义**（为什么值得标准化）：属性族一旦按约定出门，换观测平台=换出口形状、不换采集（设计稿 06 取舍 3"换 exporter 形状，start_span/end_span 采集接缝与全部打点方零改动"的具体化）；行业对照锚：官方 §5.3"Langfuse 等后端兼容该约定"、热词表行"span 树可映射标准属性，Langfuse 可视"；网关内置集成清单（docs/tech-stack/litellm.md，Langfuse/OTel 回调）是投递通道的行业形状——本节不接线，只讲出口；设计稿 06 锚（LangSmith 类平台异步批量采集）保证"追踪不拖慢主流程"的行业纪律在出口侧同样成立（本出口纯函数零 IO，天然满足）。

## 关键判断的取舍记录

1. **fail-closed 白名单出口——袋内未知键一律落平台特有，绝不拼标准键。** 备选一：开放式直传（键名逐字透传出门）——标准门被平台特有键污染，对面平台把 metric_ref 当通用属性解析（捣乱输入 t2）；备选二：未知键报错——出口对打点方加键太脆（设计稿 19 attrs 表每增一键出口就炸）。fail-closed 双向满足"不丢不造"：不丢（特有键全落标注桶，两路汇合 B-3 名册）、不造（标准键空间是常量值域，运行期零拼键）。换边条件：平台扩展键要升标准——那是 OTel 侧约定登记的语义（上游约定演进，官方锚），出口形状不变、只改常量表。
2. **空缺不造数、零补采零换算。** usage 两键/finish_reasons/system 落位形状在案、现状空缺，产物缺省不填值。备选一：出口回源网关收尾事件补采 usage——"映射是出口不是新采集器"失守（出口长出第二双眼睛，采集语义两处漂移；单参数签名也无处采——设计范围边界红线在签名上成立）；备选二：cost 按 token 单价反推 token 数——口径造假（捣乱输入 t3）。代价：W-F29-1 期望的属性族在现状树上是"部分产出+空缺在案"而非满键产出。接受：满键产出的前提是打点方把 usage 两整数入袋（设计稿 19 attrs 表增厚一行，备案）——那时出口零改动、表加一行直传；宁可交付诚实的部分产出，不交付好看的假满键（设计稿 06 宁缺毋假同款论证）。换边条件：打点方入袋（备案增厚）。
3. **键级清单宁可少列——gen_ai.* 键只列设计范围点名五键，工具调用/指标走主题级落位。** 备选：凭通识补全键级清单（工具名/调用标识类的 gen_ai.tool.* 之类键名）——取材锁失守：官方 §5.3 只给主题覆盖清单（agent spans/通用 GenAI spans/metrics/MCP 约定/provider 约定）不给键级清单，凭记忆写键名=发明规范文本，与本仓"gen_ai.* 键名以官方属性族为准、没列的键不发明"红线正面对撞。落点：主题级两行把落位主题挂实、键名从略，头部设计演绎声明与本条取舍双备案。代价：本表不能直接当接入手册用。接受：本节是设计稿不是接入手册——"哪天真接 SDK，先核对官方文本再扩表"是接入手册素材。换边条件：核对官方约定原文后扩表——行增加、白名单结构不变。
4. **平台特有桶随属性族同批出门，不就地丢弃。** 备选：标准出口只出标准键、特有键留平台侧——"不丢"字面满足，但跨平台排障时 call_id 对账锚断裂（树账分离的对账线被出口剪断）。落点：特有键带"平台特有（OTel 无对应）"标注随行（B-3 名册+特有桶），消费方按标注自取——标准段纯净（捣乱免疫）与对账链完整两头都占。代价：出门负载里混有平台语义，对面平台要理解"标注即免读"约定。换边条件：对面平台要求纯净负载——出口加特有桶开关（形状不变，参数一档）。
