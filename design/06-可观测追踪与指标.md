### 数据形状与口径（本节定形，后续设计稿沿用）

```text
伪代码 — app/observability/tracer.py:Span（数据形状——设计范围"运行号→父子层级→名称/耗时/属性"的落点）

class Span:
    span_id: int             # 运行内自增编号——树内寻址够用，不做跨进程全局唯一（无外部服务可发号）
    run_id: str              # 运行号：一次 Agent 运行的根编号；格式由接线设计稿（17/19）定，本节当不透明串
    parent_id: int | None    # 父环节编号——None 即根（"运行"级 span）；父子嵌套全靠它
    name: str                # 环节名："运行"/"意图澄清"/"选表"/"SQL 生成"/"网关调用"/"工具执行"
    start_ms: float          # 开始时刻——一律问时间源（第 0 步），不直接读墙钟
    end_ms: float | None     # 结束时刻；None = 未关账（孤儿信号，捣乱 A）
    duration_ms: float|None  # 耗时归集：关账时 end_ms − start_ms 一次算清
    attrs: dict              # 属性袋：call_id（网关调用号）/ model_alias / tool_name / cost / 错误摘要
    status: str              # "ok" | "error"（异常路径关账）| "unfinished"（落盘仍未关账）
    children: list[Span]     # 落盘组树时填充——内存平表不维护它，start/end 只碰平表与栈
```

### 第 0 步（主干三）：时间源注入点——Clock 真身与 FakeClock 替身

```text
伪代码 — app/observability/tracer.py:Clock（真身）与 FakeClock（替身，同文件同协议）

import time

class Clock:                          # 真身：可注入的时间源实现（设计稿 00 登记表 #13 的"真身"）
    def now(self) -> float:
        return time.monotonic() * 1000
        # 单调钟：只进不退。墙钟（time.time）会被 NTP 校正回跳——span 结束早于开始，
        # duration 算出负数（捣乱 B）；Tracer/Metrics 一切时刻只问它

class FakeClock(Clock):               # 替身：同协议子类——"替身保留供测试语义"（登记表明文）
    def __init__(self, start_ms=0.0):
        self._now = start_ms
    def now(self) -> float:
        return self._now              # 不自己走——只在 advance 被调时前进
    def advance(self, ms) -> float:
        self._now += ms               # 拨快协议：手动推时间——"喂固定耗时样本"的唯一入口
        return self._now
```

机制要点：
- 注入点=构造参数：`Tracer(clock=...)` / `Metrics(clock=...)` 默认 `Clock()`——生产路径零感知；离线走查 `Tracer(clock=FakeClock())` 指名替身。
- FakeClock 不走真实时间：t 是"拨"出来的，两次 advance 之间的断言恒定可复现——主干一/二的时序推演全站在这上面（设计范围"供后续设计稿走查耗时语义"即此用途）。
- 时间语义统一一个口：span 起止、TTFT/总延迟都由调用方用同一只钟算差值——同一次运行里 span 树的耗时与指标样本互为印证，可对账。

### 主干一：span 树——开始/结束配对、父子嵌套、耗时归集（W-F12-5 机制半程）

```text
伪代码 — app/observability/tracer.py:Tracer.start_span / end_span（采集接缝两函数——各模块在公开接口边界打点，内部零侵入）

class Tracer:
    def __init__(self, clock=Clock()):
        self._clock = clock
        self._runs = {}      # run_id → [Span,...] 内存平表（追加序）；卡面"内存 span 树"的存储形态
        self._stacks = {}    # run_id → [Span,...] 当前打开链——栈顶即新 span 的父
        self._seq = 0        # 运行内自增号源

    def start_span(self, run_id, name) -> Span:
        stack = self._stacks.setdefault(run_id, [])
        parent = stack[-1] if stack else None
        # 主干判断：栈空 = 根（"运行"级 span）；栈非空 = 挂在栈顶之下——父子嵌套在此一行成立
        self._seq += 1
        span = Span(span_id=self._seq, run_id=run_id,
                    parent_id=parent.span_id if parent else None,
                    name=name, start_ms=self._clock.now(),
                    end_ms=None, duration_ms=None, attrs={}, status="ok", children=[])
        self._runs.setdefault(run_id, []).append(span)   # 平表收账：start 只入表，不组树
        stack.append(span)                                # 入栈：此后 start 的环节都嵌在它下面
        return span

    def end_span(self, span, attrs=None) -> None:
        span.end_ms = self._clock.now()
        span.duration_ms = span.end_ms - span.start_ms    # 耗时归集：减法只在关账做一次
        if attrs:
            span.attrs.update(attrs)                      # 关账补属性：call_id/cost/工具名/结论
        stack = self._stacks.get(span.run_id, [])
        if span in stack:
            del stack[stack.index(span):]
            # 出栈弹到本 span 为止（含）：子层漏 end 时父层照常关账，栈错位不传染——
            #   被弹掉的未关账 span 由 trace_run 孤儿检测兜底（捣乱 A 第 2 道闸）
```

    def trace_run(self, run_id, spans=None) -> None:
        spans = spans or self._runs.get(run_id, [])
        # 卡面形状带 spans 参数：调用方可显式传入收集好的 span 列表（设计稿 19 接线用）；
        #   缺省则落本 Tracer 自己收的账——两条路都是"平表进、树出"
        now = self._clock.now()
        for s in spans:
            if s.end_ms is None:                     # 孤儿检测（捣乱 A 第 2 道闸）：
                s.status = "unfinished"              #   标脏——"这里断过"必须可见
                s.end_ms = now                       #   账面终点=落盘时刻，仅供树闭合
                s.duration_ms = None                 #   耗时置空——宁缺毋假，不伪造精确值
        for s in spans:                              # 数据变形：平表 → 嵌套树（按 parent_id 组 children）
            s.children = [c for c in spans if c.parent_id == s.span_id]
        record = {"run_id": run_id,                  # 落盘形状：一行 JSON，检索键即 run_id
                  "root": [r for r in spans if r.parent_id is None],
                  "span_count": len(spans),
                  "unfinished": sum(1 for s in spans if s.status == "unfinished")}
        _log.info("trace_run", extra={"trace": json.dumps(record, ensure_ascii=False)})
        # 结构化日志而非库表：卡面"内存 span 树 + 结构化日志、无外部服务依赖"——
        #   "按运行号可查"= 日志键值检索 run_id 等值查，不引入存储依赖（叶子纪律）

### 主干二：指标采集——TTFT/总延迟/成本三记录点与 p50/p95 聚合（W-F12-4 机制半程）

```text
伪代码 — app/observability/tracer.py:Metrics（三记录点 + 预算判据——判据无副作用）

class Metrics:
    WINDOW = 500                                # 每别名样本窗口（取舍 2：只看最近 N 个）

    def __init__(self, clock=Clock()):
        self._clock = clock                     # 钟注入备用——记账以调用方算好的 ms/cost 为准
        self._ttft = {}                         # model_alias → deque（maxlen=WINDOW）
        self._latency = {}                      # 同上
        self._cost_by_call = {}                 # call_id → cost（逐调用账，对账锚）
        self._cost_total = 0.0                  # 累计成本——判据的数据源

    def record_ttft(self, model_alias, ms) -> None:
        self._ttft.setdefault(model_alias, deque(maxlen=self.WINDOW)).append(float(ms))
        # 维度=model_alias：不同模型延迟分布不同，混桶会把 p95 搅成谁也解释不了的数

    def record_latency(self, model_alias, ms) -> None:
        # 本节定形（设计稿 00 登记表"待定形：设计稿 06 定形"）：形状对齐 record_ttft
        self._latency.setdefault(model_alias, deque(maxlen=self.WINDOW)).append(float(ms))

    def record_cost(self, call_id, cost) -> None:
        self._cost_by_call[call_id] = float(cost)
        self._cost_total += float(cost)         # 累计口径：本进程 record_cost 之和
        # 叶子纪律：m12 不 import m3/m4——不读 m4 的 spend 键计数（那是 m2 记账双写的账，
        #   设计稿 02 定形）、不读 m3 审计表；m12 的账自给自足，判据才不依赖任何外部件

    def over_budget(self, budget) -> bool:      # 卡面"over_budget?"谓词——形状去问号
        if budget is None:
            return False                        # 异常去向（设计范围明文）：无预算配置→恒不触发
        return self._cost_total > budget        # 主干判断：累计成本与预算比较→超限信号
        # True 只是信号：判据不切流、不复位、不自配预算——切降级模型组是设计稿 07 的接线；
        #   超限后累计怎么处置（沿用/按日换预算）也归设计稿 07 定形（半程边界）
```

```text
伪代码 — app/observability/tracer.py:_quantile（内部辅助——p50/p95 的算法口径，非公开接口）

def _quantile(samples, q) -> float | None:
    if not samples:
        return None
    xs = sorted(samples)                      # 窗口有界（≤500/别名），全量排序开销可忽略——
                                              #   不上 t-digest/直方图近似（取舍 2 的换边条件）
    rank = max(1, math.ceil(q * len(xs)))     # 最近秩法：p95 = 第 ⌈0.95·n⌉ 小样本
    return xs[rank - 1]                       # 读法："95% 的请求延迟不超过这个值"（锚 原书第七章）
```

```text
伪代码 — app/observability/tracer.py:Tracer.span（上下文管理器——异常路径的关账兜底闸）

from contextlib import contextmanager

    @contextmanager
    def span(self, run_id, name):
        s = self.start_span(run_id, name)
        try:
            yield s                              # 调用方主体在此执行；异常原样穿过去
        except Exception as e:
            s.status = "error"                   # 先定状态再关账——end_span 不碰 status，error 保留
            s.attrs["error"] = f"{type(e).__name__}: {e}"
            raise                                # 不吞异常：打点永远改变不了业务走向
        finally:
            if s.end_ms is None:                 # 兜底：正常/异常两条路都在此关账
                self.end_span(s)
        # 纯内存操作、无 await 点——同步 contextmanager 足够，m13 async 主循环里直接
        #   with 嵌入、不占事件循环；"接线一律用此形状"是设计稿 19 打点主干的调用纪律
```

## 关键判断的取舍记录

1. **机制指标与目标指标分家——古德哈特陷阱的预防性设计**。本节只造"机制指标"（如实记录 TTFT/延迟/成本并给出分位读数），不造"目标指标"：判据的预算由调用方传参进入（over_budget(budget)）、判据只出布尔信号不自行动手（切降级在设计稿 07）、聚合读数只做内部辅助不做公开接口（无"达标率"语义）。备选是让 Metrics 内置默认预算并在超限时直接抛异常拦调用——采集层长出业务牙齿后，一旦"p95<2s"这类目标写进采集件，系统就开始学会讨好指标（牺牲回答质量换首字快、把贵调用挪出计费路径），指标失真且无人察觉。换边条件：出现平台级统一预算治理需求时，按模块卡修订流程在卡上加预算配置接口，仍保持"采集/判据/执行"三段分离。
2. **p95 不用平均**（锚 原书第七章：均值会被大量快速请求拉低，掩盖少数用户遭遇的严重卡顿）。LLM 延迟天然长尾——上下文长度决定 prefill、思考 token 数跨模型差数倍：p50 保"典型用户的快"，p95 保"最不幸的 5%"，平均数两头都不保。算法取舍：窗口内全量排序取最近秩（≤500 样本/别名，排序开销可忽略）；近似算法（t-digest/HDR 直方图）是为"样本大到排序贵 + 多节点合并"准备的，本系统单进程用不上。换边条件：多实例部署需要跨节点合并分位数、或窗口需求上万样本时，换近似直方图或外部时序库——读数出口换形状，采集接缝与打点方零改动。
3. **内存 span 树+结构化日志，不上 OpenTelemetry/Langfuse 平台**（设计范围框架红线：无点名框架）。书里讲采集与分析解耦（OTEL 标准协议）、平台侧异步批量采集（锚点精要 3），好处真实存在；但本系统单进程规模、卡面明文"无外部服务依赖"、国产化离线交付（设计稿 03）——引一个追踪后端等于给离线环境加一个必须国产替代的新部件。自建形状刻意与标准模型同构：trace=一次运行（run_id）、span=执行单元（起止/属性/错误）、父子构成执行树——日后要接平台只换 trace_run 的落盘出口（换 exporter 形状），start_span/end_span 采集接缝与全部打点方零改动。换边条件：多服务拆分或需要第三方分析后端时。
4. **FakeClock 真身替身并存，不删替身**。其它 stub 的换身纪律是"真身上位、替身段留当离线退路"（设计稿 02/04/05 同款）；本 stub 登记表明文"替身保留供测试语义"——因为耗时语义的走查断言必须与时间无关：真时间源每次跑数字都不同，"根 span 耗时覆盖全部子环节""TTFT 恒 420"这类断言永远锁不死。设计成同协议子类（Clock/FakeClock 都答 now()，替身多一个 advance）后：生产默认真身零感知，走查指名替身，测试语义与生产语义不分裂。备选 monkey-patch time.monotonic 同效，但把"钟被换了"藏进测试框架暗处——注入点显式在构造参数上更可查。

## 锚点对照精要

**原书第七章 §选型的关键维度 · 吞吐量与延迟（TTFT/p95）**（卡 `m12` 锚点 K-J）
书：推理分 Prefill/Decode 两阶段，TTFT=排队时间+Prefill 时间，是用户感知的"反应快慢"，上下文越长 prefill 越慢、TTFT 越大；Decode 决定出字速度（tokens/秒）与思考时长。p95 尾部延迟比平均值更能反映真实用户体验——均值被大量快速请求拉低，掩盖少数用户的严重卡顿。落点：TTFT 与总延迟分开两个记录点（record_ttft/record_latency）——前者诊断"进来慢"（上下文长/排队）、后者诊断"出字慢"（解码/思考长），混成一个指标两头病因都查不了；聚合口径取 p50/p95 双分位。

**原书第七章 §Agent 系统的成本分析 · 成本监控与预算控制**（卡 `m12` 锚点 K-J）
书：生产环境应建立实时成本监控，按任务类型/模型/用户等维度追踪 token 消耗与 API 费用；同时给每个任务设成本上限——Agent 陷入循环或探索过深时自动终止，防单次任务异常高额费用。成本三层次：模型推理（上下文累积与思考 token 是两个放大因素）、工具调用（含工具结果注入上下文后逐轮反复计费的间接成本）、基础设施。落点：record_cost 按 call_id 逐调用入账对应"按维度追踪"，over_budget 判据对应"每任务成本上限"——上限的执行半边不在本节（切降级在设计稿 07、反思重试 3 次熔断转人工在设计稿 14），本节只出信号。

**原书第七章 §Agent 的可观测性 · Trace 与 span 树**（卡 `m12` 锚点 K-J）
书：可观测性的数据基础是追踪，数据结构沿用分布式系统的 span 树模型——一次任务执行一条 trace，每个 LLM 调用/工具调用/检索是一个 span（记输入输出、起止时间、token 消耗、错误信息），父子关系构成执行树；OpenTelemetry/OpenInference 提供标准协议，采集与分析解耦避免被单一平台锁定；LangSmith 类平台用异步批量采集确保追踪本身不影响响应延迟。落点：自建 span 树刻意同构该模型（取舍 3）；"追踪不拖慢主流程"在本系统以更朴素的方式成立——打点是纯内存操作（入表+入栈+一次减法），落盘只在运行结束一次（trace_run），运行中途零 IO。

**原书第二章 §KV Cache友好的上下文设计**（卡 `m12` 锚点 K-J）
书：无缓存时 prefill 的注意力计算量随上下文长度平方级增长；KV Cache 使每 token 的 K、V 只算一次，Prompt Cache 更把跨请求的相同前缀直接复用（缓存读价约为首次计算的十分之一）；前缀首个不同 token 之后的缓存全部失效——哪怕只差一个空格。落点：本节为这条机制提供"测量仪表"——TTFT 暴涨的第一排查方向就是前缀失稳（W-F12-2 反例"时间戳进前缀→缓存未命中→首字延迟暴涨"的对照数据就靠 record_ttft 采样）；测量（本节）与治理（设计稿 16 装配三铁律）分属两个设计稿。
