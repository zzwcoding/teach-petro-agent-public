### 第 0 步：六份分层 SQL 文本长什么样（交付物本体）

> 分层即目录：`models/staging|intermediate|marts/` 三目录六文件，文件在哪个目录=它对哪层契约负责。SQL 全文是本节交付物（设计演绎，不执行、不接调度）；每份文件头三行注释就是它的契约——进什么/出什么/防什么错，与主干一 `describe` 的答案逐字对得上。

```sql
-- 伪代码 — app/modeling/models/staging/stg_oil_production_daily.sql（交付物 1/6，文本不执行）
-- 层: staging（Clean，AE 原书 Ch6 §Clean：Deduplicate→Harmonize→Validate）
-- 进: oil_production_daily 裸表原样（设定书 §A.2）；出: 1:1 原粒度清洗模型（一井一日一行，去重不聚合）
-- 防: A/B 班次重复行（§A.2 脏特征）；吨方混写（§4 规则 3：折算后密度∈[0.82,0.98]）；停井日 open_days>0 矛盾（打标不篡改）

WITH 班次去重 AS (
    -- [去重] A/B 班次手抄汇总的同井同日两行是**同一事件的两次登记**——去重，绝不 SUM
    --（SUM = 当日产量翻倍，月完成率随之虚高一倍；AE 原书 Ch6 §Clean Deduplicate：de-duplicating early）
    SELECT raw.*,
           ROW_NUMBER() OVER (
               PARTITION BY well_raw, prod_date
               ORDER BY report_shift            -- 定序键固定：同一输入永远同一行幸存，重跑幂等（取舍 2）
           ) AS rn
    FROM oil_production_daily                   -- report_shift CHAR(1) A/B/C（设定书 §A.2）
)
SELECT
    w.well_std                AS well_id,       -- [统一] 规范井号取自 stg_well_info 归一字典——规则不写第二份
    p.prod_date,
    -- [统一] 吨方混写三档裁决（主干二）：净液估算 = liquid_output × (1 − water_cut/100)
    --   ① oil_output ≤ 净液估算 → 本来就是吨，原样保留（原油密度恒 <1，吨数必小于方数）
    --   ② 贴边超出（≤净液估算×1.02）→ 判为"误录成方"，按区块密度折算回吨（§2.2：渤南 0.86/渤中 0.89/渤西 0.91）
    --   ③ 超出更多 → 不折算，打 unit_unresolved 拦给人——宁可不修，不可错修（取舍 3）
    CASE
        WHEN p.oil_output <= p.liquid_output * (1 - p.water_cut / 100)
            THEN p.oil_output
        WHEN p.oil_output <= p.liquid_output * (1 - p.water_cut / 100) * 1.02
            THEN ROUND(p.oil_output * w.density_t_per_m3, 2)     -- 方 × 区块密度 → 吨
        ELSE p.oil_output                                        -- 原值保留，只打标
    END                       AS oil_output_t,
    p.liquid_output           AS liquid_output_m3,
    p.water_cut,                                -- 化验折算口径，与 fluid_test 打架（§A.2）——staging 不仲裁
    p.open_days,
    p.oil_pressure,
    p.plan_output             AS plan_output_t, -- 配产版本切换日双值行：本层不裁——谁消费谁裁（口径归指标层，主干三）
    -- [校验闸] 折算行与矛盾行打标随行走，不静默：下游看得见哪行动过、哪行存疑
    CASE
        WHEN p.oil_output >  p.liquid_output * (1 - p.water_cut / 100) * 1.02 THEN 'unit_unresolved'
        WHEN p.oil_output >  p.liquid_output * (1 - p.water_cut / 100)       THEN 'unit_converted'
        WHEN p.open_days > 0 AND 井在检修日历内(p.well_raw, p.prod_date)      THEN 'open_days_conflict'
        ELSE NULL
    END                        AS quality_flag  -- 矛盾标注不改数；修复与否归质量闭环（提取件二 §三 闭环机制）
FROM 班次去重 p
JOIN stg_well_info w ON w.well_raw = p.well_raw -- 层内引用 staging 同层模型（只许下层消费的例外：同层可见）
WHERE p.rn = 1                                  -- 每井每日恰一行——进入 intermediate 的准入形状
```

-- 伪代码 — app/modeling/models/staging/stg_well_info.sql（交付物 2/6，文本不执行）
-- 层: staging（Clean）
-- 进: well_info 裸表原样（设定书 §A.1）；出: 一井一行清洗模型，规范号 + 原始号双列（血缘不断）
-- 防: 井号写法并存（§4 规则 7：N2/N-2→N-02 归一化，归一表全命中）；状态滞后（§A.1：N-11 已停仍"生产中"——标注不自动改）

    归一化井号(well_id)       AS well_std,      -- "N2"→"N-02"；"N-2"→"N-02"
    well_id                   AS well_raw,      -- 原始写法保留：上游对不上号时可回溯（血缘半边）
    well_name,                                  -- 渤中28-1-N2（§A.1 样本）
    well_type,                                  -- EW 采油 / IW 注水（个别改型未留版本——本层不考证，原样透传）
    first_prod_date, platform,                  -- CEP-A/B
    block_name,                                 -- 渤南/渤中/渤西——下游密度折算字典的键（§2.2）
    field_name,                                 -- 渤海油田：行内冗余=反规范化样例（§A.1）——marts 层升格为有意为之
    current_status,                             -- 生产中·停产·检修·待弃置
    -- [校验闸] 状态滞后是**业务事实存疑**不是格式毛刺——staging 只打标交问题单闭环，
    -- 不替业务改状态（提取件二 §三：问题单 分发→认领→整改→复核→关闭）
    CASE WHEN 状态滞后(well_id, current_status) THEN 'status_stale' END AS quality_flag
FROM well_info                                  -- 一井一行（PK well_id，§A.1）

```sql
-- 伪代码 — app/modeling/models/intermediate/int_well_daily.sql（交付物 3/6，文本不执行）
-- 层: intermediate（Integrate，AE 原书 Ch6 §Integrate：Map→Simplify→Reconcile）
-- 进: staging 两模型（stg_oil_production_daily + stg_well_info）；出: 井×日统一视图（井侧属性已就位）
-- 防: join 键漂移（合法 join 裁决：oil_production_daily ⋈ well_info ✓，设定书 §5 白名单）；可复用计算散落（一处定义）

SELECT
    s.well_id,                                  -- 规范号：与 dim_well 主键同源
    s.prod_date,
    -- [Map] 主外键在此立约：well_id 引用井维度、prod_date 即日键——ERD 一句话：一井多日，每日一事实
    w.well_name, w.well_type, w.platform, w.block_name, w.field_name,   -- 井侧属性带在统一视图上
    s.oil_output_t, s.liquid_output_m3, s.water_cut, s.oil_pressure,
    -- [Simplify] 可复用计算在集成层算一次，下游不再各写各的（AE 原书 Ch6 §Integrate Simplify：
    -- "Calculations that can be reused downstream can be performed at this stage"）
    ROUND(s.liquid_output_m3 * s.water_cut / 100, 2)      AS water_output_m3,   -- 产水量=液×含水
    ROUND(s.liquid_output_m3 - s.oil_output_t / w.density_t_per_m3, 2)  AS 净液方_折算,  -- 吨↔方换算收口一处（§2.2）
    s.open_days, s.plan_output_t, s.quality_flag,          -- 质量旗标原样透传——下游可见，不静默洗白
    -- [Map 立约] 本视图是"井×日"唯一权威 join 路径：fluid_test 化验对齐须井号+取样日期双键+时间容差，
    -- 且**只许在本层做**（设定书 §5 白名单：直连 ✗，经 intermediate 视图 ✓）——本节不做，钩子留给后续设计稿
    NULL                            AS 化验对齐占位
FROM stg_oil_production_daily s
JOIN stg_well_info w ON w.well_std = s.well_id  -- 白名单内合法 join（设定书 §5 第一行 ✓）
```

### 主干一：LayerPlan 三层契约——三问可查可复述（W-F17-1 的本体）

```text
伪代码 — app/modeling/layers.py:LayerPlan（m20；签名=卡 m20；纯内存契约表，同步）

class LayerContract:            # 数据形状——一层的三问答案（进什么/出什么/防什么错）
    layer: str                  # "staging" | "intermediate" | "marts"
    step: str                   # 对应 AE 原书 Ch6 三步：Clean / Integrate / Enrich and summarize
    进什么: str                 # 本层唯一合法输入（上一层的输出；staging 的上一层=裸生产库）
    出什么: str                 # 本层产出承诺（粒度/形状/质量旗标）
    防什么错: [str]             # 本层闸清单——每条注源（设定书 §x / AE 原书 Ch6 §y / 提取件二 §三）
    消费谁: str                 # 谁有权读本层——管道内部层不外露，就绪层是唯一对外开放面

_CONTRACTS = { "staging": …, "intermediate": …, "marts": … }
# 契约即文件里的字面数据，不是推导结果——三问答案固定、可复述、可被设计稿 34 测试逐条对账。
# 三问全文见下表（与第 0 步六份 SQL 的文件头注释逐字同源：契约改了 SQL 头就改，反之亦然）。

class LayerPlan:
    def describe(self, layer) -> LayerContract:
        if layer not in _CONTRACTS:              # 🛡️ 主干判断：契约表没有的名字一律拒绝
            raise UnknownLayer(layer)            # describe("bronze") → 拒——medallion 是思想对照
                                                 # 不是别名（取舍 4）；错名字进来要当场死，不是返回 None
                                                 # 让调用方猜
        return _CONTRACTS[layer]                 # 纯读：契约查询零副作用，随时可讲可考
```

## 关键判断的取舍记录

1. **为什么三层而不是一层——分层的成本买"透明/可复用/可理解"**。备选是"清洗完直接出一张大宽表"（一层交付）。一层赢在初看简单，输在三处：清洗逻辑被复制进每个消费方，口径改一处要全库 grep（不透明）；产水量、吨方换算在多个看板各写一遍，漂移只是时间问题（不可复用）；新场景要读懂全库 SQL 才敢动手（不可理解）。AE 原书 Ch6 §Layering transformations 的原话是分层的判据——"transformations transparent, reusable, and easy to understand"。代价：六个文件+一份契约表的负担比一个文件重；换边条件：一次性看板、单人单场景——分层的维护成本收不回，一层无罪。分层的收益随消费方数量线性涨，本项目的消费方是问数、指标、看板三路，三层划算。
2. **去重用定序保留一行，不 SUM 也不合并**。备选一是对 A/B 两行数值求平均、备选二直接 SUM。两行是同一事件的两次登记（设定书 §A.2 班次手抄汇总），SUM=产量翻倍，平均=发明了一个不存在的第三值；正解是承认"这是一行"，ROW_NUMBER 定序保留一行。定序键（report_shift）固定保证重跑幂等——同一输入永远同一行幸存，今天跑和明天跑结果一致。换边条件：业务上真出现"两班各计量了一半"的双行语义——那是采集侧口径问题，归质量闭环问采集管理员（设定书 §1 角色卡），不是转换层替业务猜。
3. **单位混写三档裁决：修、贴边修、不修**。备选是"见吨方混写一律按密度折算"（一刀切自动修）。问题在判据可靠性：净液估算依赖 water_cut 与 liquid_output 都对——两个都脏时折算就是二次污染。三档裁决：正常带原样保留（零打扰）、贴边超出带（≤2%）判误录折算打标、超出更多原值保留打 unit_unresolved 拦给人——宁可不修，不可错修（与设计稿 15 只读闸 fail-closed 同哲学：不可确证的按最严处理）。换边条件：设计稿 34 转换测试用全量样本复核三档判据的误报率，误报高了收窄贴边带，漏报高了放宽——判据参数由测试数据说话，不拍脑袋。
4. **命名跟 AE 世界观（staging/intermediate/marts），不做 medallion 改名**。备选是把三层改叫 Bronze/Silver/Gold 以便"行业通用"。m20 的职责就是 AE 世界观载体（卡面原文），AE 原书 Ch6 §Layering transformations 明说两套划法"Regardless, all follow the same paradigm"——范式同构，划法边界不同（Silver 覆盖清洗+集成两层）。改名零收益：换来的只是术语换皮，丢掉的是与设计稿系列 AE 叙事的一致。medallion 的正确用法是**对照表可复述**（主干一）——实战里两套黑话都要能对上，但代码库里只留一套。换边条件：无（范式对照已覆盖可迁移性）。
5. **marts 反规范化是有意设计，不是偷懒**。field_name 在裸表里就是行内冗余（设定书 §A.1 明注"反规范化样例"），dim_well 把井→平台→区块→油田层级全部拍平进一行。AE 原书 Ch6 §Enrich Augment 的判据：查询要快、层级稳定（渤海油田的区块归属不会天天变）→ 反规范化划算；代价是层级变更要重算维度——本项目规模接受。规范化洁癖在这里是错的：让问数每答一句都四表 join 层级链，血亏。

## 锚点对照精要

**AE 原书 Ch6 §Layering transformations（分层与 medallion 对照）**：原文——dbt 主张把模型分 "Staging, Intermediate, and Marts layers"，Databricks 主张 medallion "Bronze, Silver, and Gold"，"Regardless, all follow the same paradigm: transforming your data should follow steps that make transformations transparent, reusable, and easy to understand"；三步为 "1. Clean … 2. Integrate … 3. Enrich and summarize"。落点：主干一三契约（step 字段逐字对三步）与 medallion 对照表。差异：dbt 的层由 ref() 依赖图与调度执行撑起，我们是 SQL 文本交付物+目录约定——执行与调度不在本卡（设计范围边界），分层纪律先靠契约表与文件头注释站住。

**AE 原书 Ch6 §Clean（清洗三任务与早拦原则）**：原文——"Data quality issues must be handled as early as possible, as they can ripple throughout your pipelines"；三任务 Deduplicate（"de-duplicating early is key to avoiding faulty joins"）/ Harmonize（units、types、categories 统一，缺失值一致处理）/ Validate（按预定义规则查完整性与一致性）。落点：staging 三闸（主干二两段推演+第 0 步交付物 1/2）与契约表 staging 行"防什么错"四条——四条逐一可映射回三任务加旗标纪律。差异：原书允许去重提前到 ingestion，我们的源头在采集侧（A/B 手抄行是班次报表，源头治理归设计稿 42 角色链），staging 是转换侧第一道也是最便宜的闸。

**AE 原书 Ch6 §Integrate（集成三步）**：原文——Map（enforce data model，定义 primary/foreign keys、documentation an ERD；可 regrain 重排粒度）/ Simplify（"Calculations that can be reused downstream can be performed at this stage"）/ Reconcile（跨源对账验证质量）。落点：int_well_daily（主外键立约+产水量/吨方换算收口）与 int_overhaul_days（区间事实 regrain 成井×日检修日历——§A.4 跨月切割一处算清）；Reconcile 留位给注采物质平衡（设定书 §4 规则 12，设计稿 38）。差异：原书的集成面向多源异构系统（电商订单线上线下合并），我们是"一数四源"的油田变体（设定书 §3 争议注记）——集成层同样承担"把口径打架的源挡在统一视图之下"的职责。

**AE 原书 Ch6 §Enrich and summarize（就绪层三任务）**：原文——Aggregate（按业务粒度聚合）/ Apply business rules（过滤、域约束、指标物化）/ Augment（"enriching data may also involve denormalization, that is, merging tables"，判据是访问速度与服务形态）。落点：marts 两模型——fct_daily_metering 的业务裁决（停井 open_days 按检修日历校正）对应 Apply business rules；dim_well 层级反规范化对应 Augment（取舍 5）。差异：原书提醒避免"一个看板一张表"的表爆炸——本项目 marts 只有维度+事实两件，聚合型 marts（月度区块汇总）等真实消费方出现再添，不预建。

**AE 原书 Ch6 §Design choices（转换放哪的四问）**：原文——四问：该转换下游还要用吗（要则下放）？这阶段存无用数据吗（早滤）？此时做与前后做的成本比？易理解易调试吗？以及 "primary metrics should be calculated in the transformation layer, and secondary metrics should be calculated in the serving layer"。落点：主干四末段（主指标在转换层算好，serving 只做呈现）与取舍 1（一层 vs 三层就是"易理解易调试"问的展开）。

**提取件二 §三（数据质量规则清单）**：来源论文的 6 大质量维度（规范性/完整性/准确性/一致性/时效性/唯一性）与 26 项通用规则（含"数据项组合唯一性校验""固定值域范围"）；三级质控"点、线、面"——"通过源头拦截进行数据采集质控，通过入口把关实施入湖质控，通过持续监控进行湖内常态化质检"；问题单闭环"分发→认领→整改→复核→关闭"。落点：staging 契约"防什么错"四条的维度归属（规则 3=准确性、规则 7/8=规范性、A/B 去重=唯一性）与"早拦便宜"的中文行业原型（staging=入湖把关）；状态滞后/单位矛盾等不可自动修项打标走问题单闭环——staging 不吞掉质量闭环的活（设计稿 34/38 消费）。

**设定书取材对账**（取材锁）：§2.2 单位换算表（密度 0.86/0.89/0.91 与吨↔方换算→staging 折算字典）；§4 规则 3/7/8（设计稿 32 的指定规则三条，§10 锚点行点名）；§5 合法 join 白名单（intermediate 集成立约）；附录 A 全部样本行与脏特征（N-02 A/B 重复行、N-11 12.40方、N2/N-2 并存、跨月检修 8-28→9-06、stop_reason_code 新旧编码、field_name 行内冗余、open_days 停井矛盾）；§10 取材锚点行（"设计稿 32：§2.2 附录 A 字典+单位换算表+§4 规则 3/7/8"）——本设计稿业务事实全部落在上述清单内，无凭空发明。
