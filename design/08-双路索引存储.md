### 主干一：向量半程——建集合、批量写入、带过滤近邻查询（W-F6-1/2 的向量半程）

```text
伪代码 — app/rag/vector_store.py:_get_collection（m14 私有装配；模块级惰性单例）

_client = None
_collection = None                        # 私有状态：Chroma 客户端与集合对象永不进公开签名/返回值

def _get_collection():
    # 输入形状：无——集合名/数据路径/服务地址全部来自环境配置（连接信息外置，同 m3 连接串纪律）
    global _client, _collection
    if _collection is not None:
        return _collection                # 重复装配直接复用：客户端与集合是进程级资源
    if 配置了 chroma 服务地址:              # compose 已声明 chroma 服务（设计稿 03 契约）→ 客户端/服务分离形态
        _client = chromadb.HttpClient(host="chroma", port=8000)   # 官方 HttpClient（client-server 模式）
    else:
        _client = chromadb.PersistentClient(path="数据目录")       # 官方 PersistentClient：库文件落盘、启动自装载
    _collection = _client.get_or_create_collection(
        name="report_chunks",             # 报告块集合；设计稿 14 的 schema 集合是同一封装下的另一 collection
        configuration={"hnsw": {"space": "l2"}},   # 官方参数：三值 l2/cosine/ip，默认 l2（平方 L2）——写明为凭据
        embedding_function=None,          # ★ 闸：本封装不内嵌任何嵌入函数——向量一律由调用方现成喂入
    )
    return _collection
    # 异常去向：服务不可达 / 路径不可写 → 装配期即抛，包装为结构化索引存储异常上抛——配置错误不拖到首笔查询
```

```text
伪代码 — app/rag/vector_store.py:VectorStore.upsert（m14；W-F6-1 向量半程·写入主干）

# 输入形状（设计稿 09 双写的一侧）：
#   ids        = ["volve-completion-01#p14#c3", ...]      # 块号规则=报告号#页码#块序；同号幂等覆盖
#   embeddings = [[1024 个 float], ...]                    # bge-m3 稠密向量——本节只存不算
#   documents  = ["……套管射孔完井，人工井底 2788 m……", ...]   # 块原文，检索命中后拼上下文用
#   metadatas  = [{"report_name": "Volve 完井报告", "page": 14}, ...]   # 元数据过滤与引用定位用
def upsert(ids, embeddings, documents, metadatas) -> None:
    # 主干判断：四数组等长——官方约束"所有数组同长、按下标一一对应"，不等长属调用方契约错
    if not (len(ids) == len(embeddings) == len(documents) == len(metadatas)):
        raise IndexStoreError("双写参数四数组长度不齐")      # 数据变形前先拦形状，不带病进库
    collection = _get_collection()
    try:
        collection.upsert(                                # 官方调用序列：同 id 更新、新 id 插入——
            ids=ids,                                      #   同一份报告重复索引天然幂等，不产生重复块
            embeddings=embeddings,                        #   集合维度以首笔写入固化（维度闸见捣乱 B）
            documents=documents,
            metadatas=metadatas,
        )
    except InvalidDimensionException as e:                # 异常去向①：维度与集合不符（捣乱 B 全程）
        raise IndexStoreError("向量维度与集合不符：维度以首笔写入固化", cause=e)
    # 异常去向②：服务不可达/超时 → HttpClient 断连同样包装为 IndexStoreError(下游不可用) 上抛，由调用方降级
    # 成功即返回 None——持久化由 Chroma 自管（PersistentClient 落盘 / 服务端落盘），
    #   调用方没有"落盘义务"：向量路的持久化不在六函数契约里（对照主干三 BM25 的义务，见该段）
```

```text
伪代码 — app/rag/vector_store.py:VectorStore.query（m14；W-F6-2 向量半程·查询主干）

# 输入形状：embedding = 查询向量（小李问题经 m2 嵌出的 1024 维 float 数组）；top_k = 5；
#           where = None，或 {"report_name": "Volve 完井报告"}（官方等值简写），
#           或 {"$and": [{"report_name": {"$eq": "Volve 完井报告"}}, {"page": {"$lte": 30}}]}（组合过滤）
def query(embedding, top_k, where=None) -> Hits:
    if 库内记录数为 0:                       # 空库闸（捣乱 A 之向量路）：官方查询不报错、有多少给多少，
        return []                           #   封装层把空组如实变形为空 Hits——不抛错、不造分
    res = _get_collection().query(
        query_embeddings=[embedding],       # ★ 只收现成向量——封装签名上没有 query_texts 这个口（见维度坑段）
        n_results=top_k,
        where=where,                        # 官方 where 语法：等值简写 / $eq,$ne,$gt,$gte,$lt,$lte,$in,$nin / $and,$or
        include=["documents", "metadatas", "distances"],   # 官方 include：要什么拿什么，不取回整库
    )
    # 数据变形：官方返回按查询分组的嵌套列表（本封装一次只查一条 → 取第 0 组）：
    #   res["ids"][0]       = ["volve-completion-01#p14#c3", ...]     近邻块号，近→远
    #   res["distances"][0] = [0.31, ...]                             l2 空间的平方 L2 距离，越小越近
    #   res["documents"]/res["metadatas"][0]                      块原文与元数据原样带回
    hits = [Hit(chunk_id=id, score=1 - dist, source="vector")
            for id, dist in zip(res["ids"][0], res["distances"][0])]   # score=1−distance：单调换算，仅供排序
    return hits
    # ★ score 口径注释（如实，不粉饰）：l2 空间下 1−distance 可为负（同向≈1、正交≈0、反向≈−3）——
    #   它不是余弦相似度、不是概率、没有"及格线"含义；优点只有一条：距离越小分越高，排序方向正确。
    #   跨查询、跨库都不可比；阈值判分归设计稿 10 精排与 m6 拒答闸，本层只保证排序真实
```

**维度坑：query_texts 与写入必须同一嵌入（本节在签名上收闸）**。官方 `query` 也接受 `query_texts`——但那意味着用**集合内嵌的嵌入函数**给查询文本现场算向量：本集合 `embedding_function=None`，`query_texts` 无函数可用即错用；即便允许内嵌（Chroma 默认嵌入模型是 384 维的另一套模型），与 bge-m3 1024 维写入**不同源不同维**——维度不符当场被拒（官方 `InvalidDimensionException`），维度凑巧相同则两套嵌入空间算出的"距离"是无意义数，比报错更危险。结论固化为两条：①写入与查询必须**同一嵌入模型、同一维**（设计稿 09 嵌入真身统一经 m2）；②本封装的 `query` 签名只收现成 `embedding`，不设 `query_texts` 入口——闸收在签名上，调用方想错都错不了。附带官方事实：集合维度由**首笔写入固化**，此后任何维度不符的写入都被拒——库内同维是集合不变量。

观察到的验收行为：一批 64 个块 `upsert` 成功；重复索引同一批（同 id）不产生重复，是原地覆盖；`query(小李问题向量, 5, where={"report_name": "Volve 完井报告"})` 返回 5 条 Hits，`metadatas` 里页码齐、`documents` 可直接拼上下文，`score` 按近→远单调递减。

### 主干二：关键词半程——进程内建索引与 Top-N 打分（W-F6-2 的 BM25 半程）

```text
伪代码 — app/rag/bm25_index.py:Bm25Index.build（m14；W-F6-2 关键词半程·建索引主干）

# 输入形状（设计稿 09 双写的另一侧）：
#   chunk_ids = ["volve-completion-01#p14#c3", ...]
#   tokens    = [["N-2","井","采用","套管","射孔","完井",...], ...]   # 已分词 token 序列——分词口径归调用方（设计稿 09），
#                                                                     #   本层只留官方 tokenizer 参数口，不锁分词器
def build(chunk_ids, tokens) -> None:
    # 主干判断：空语料闸——官方源码建构期 avgdl = num_doc/corpus_size，空语料即 0/0 除零；
    #   封装层拦下：空库保持"空索引"合法态，不把退化件建出来（捣乱 A 之关键词路的闸源）
    if not chunk_ids:
        return
    # 数据变形：token 序列对 → BM25Okapi 索引对象（官方默认 k1=1.5、b=0.75、epsilon=0.25）
    self._bm25 = BM25Okapi(tokens)          # 倒排统计建构期一次算好：每词的 df/idf、每篇的词频表与 doc_len
    self._chunk_ids = chunk_ids             # 语料顺序 = chunk_ids 顺序——打分按下标对回块号（对齐契约）
    self._corpus_tokens = tokens            # 留档：快照载荷与装载重建共用（主干三）
```

```text
伪代码 — app/rag/bm25_index.py:Bm25Index.search（m14；W-F6-2 关键词半程·查询主干）

# 输入形状：query_tokens = ["N-2","井","完井","方式"]（必须与建库同一分词口径——两套词表命中率恒为零，
#           这是 BM25 最常见的暗坑，口径唯一归口在设计稿 09 的分词件）；top_k = 5
def search(query_tokens, top_k) -> Hits:
    if self._bm25 is None:                  # 空库闸（捣乱 A 之关键词路）：空索引查询→空候选集，不抛错
        return []
    scores = self._bm25.get_scores(query_tokens)   # 官方调用：一次对全语料打分，numpy 数组按语料顺序排列
    # 官方口径注释：查询词不在语料词表（OOV）→ 官方源码 idf.get(q) or 0，该词对每篇贡献为 0，不报错
    #   （老版本曾有 KeyError 行为——本设计稿按当前官方源码口径书写）
    order = argsort(scores)[::-1][:top_k]   # 数据变形：按分降序取前 top_k 的语料下标（官方 get_top_n 同形状）
    hits = [Hit(chunk_id=self._chunk_ids[i], score=float(scores[i]), source="bm25")
            for i in order if scores[i] > 0]       # 本层策略：0 分 = 一个查询词都没命中，过滤不进融合候选
    return hits                             # 全体 0 分→空列表：空候选集如实返回（设计稿 10 拒答闸的原料）
```

观察到的验收行为：812 块建索引毫秒级完成；`search(["N-2","井","完井","方式"], 5)` 返回 5 条 Hits，含 "N-2" 字面的块排前（IDF 高权重词贡献大，BM25 机制的直接体现）；查询 `["定向","钻井","轨迹"]` 这类全文未出现的词组合返回空列表——不是错误，是"库里没有这个词的任何命中"的如实表达。

### 主干三：快照往返——进程内索引落库与启动装载（卡 `m14` save/load）

**为什么只有 BM25 有这条义务**：向量路的存储（Chroma）自带持久化——`PersistentClient` 库文件落盘、启动自装载，服务形态由服务端落盘；`upsert` 返回即持久。BM25 路（rank_bm25）是**纯进程内对象**，重启即蒸发——所以卡面给它的持久化义务是六函数里独一份的 `save_snapshot`/`load_snapshot`。

```text
伪代码 — app/rag/bm25_index.py:Bm25Index.save_snapshot（m14；快照落库）

def save_snapshot() -> None:
    if self._bm25 is None:
        return                              # 空索引不落快照：未建库就落空快照反而制造"伪版本"
    # 数据变形：序列化载荷 = pickle 容器装 dict（原料不是索引对象本体，理由见取舍 4）
    payload = pickle.dumps({
        "format_version": 1,                # 版本头：装载方先验头再解体，不裸 loads
        "chunk_ids": self._chunk_ids,
        "corpus_tokens": self._corpus_tokens,   # 存 token 序列（原料）：装载期重建索引，索引是可重建的派生物
    })
    # ★ 经 m3 公开面 save 语义落 bm25_snapshots 表（卡 m14 依赖行；实体占位=设计稿 04 models.py:Bm25Snapshot）
    await m3_repository.快照存取·save 语义(          # ← 形状未在卡面 Repository 九签名中：

    #   双写调用方（设计稿 09）感知"索引可查但快照未落"——重启后该批要重建，属可恢复降级，不静默吞
```

```text

def load_snapshot() -> None:
    row = await m3_repository.快照存取·get 语义(key="bm25:report_chunks")   # 形状待设计定形（同上）
    if row is None:
        return                              # 无快照 = 首次启动的合法态：保持空索引，查询返回空（不抛错、不建空库）
    try:
        data = pickle.loads(row.payload)    # 数据变形：二进制 → 载荷 dict
    except (UnpicklingError, KeyError) as e:            # 异常去向①：载荷损坏/头不认
        raise IndexStoreError("BM25 快照损坏，需离线重建索引", cause=e)   # 结构化上抛——重建是运维动作，不静默吞
    if data["format_version"] != 1:                     # 异常去向②：版本不符，同①结构化上抛
        raise IndexStoreError("快照格式版本不识别")
    # 装载 = 用存档原料重建索引对象（同 build 主干），先建后换引用——不出现半新半旧的中间态
    self._bm25 = BM25Okapi(data["corpus_tokens"])
    self._chunk_ids = data["chunk_ids"]
    self._corpus_tokens = data["corpus_tokens"]
    # 安全口径：pickle 反序列化不可用于不可信来源——本快照只来自自家 m3 表（国产库内），来源面收在自家仓库
```

快照往返全程（重启主角阿强）：`save_snapshot` 把索引原料落 m3 → `docker compose restart` 进程蒸发、进程内索引消失 → 装配侧（后续设计稿接线）启动时调 `load_snapshot` → 索引原位回位 → 关键词路查询恢复，**无需重跑设计稿 09 的整条离线索引**；同一时刻向量路零操作（Chroma 启动自装载）。这是 W-F6-1"重启后 `load_snapshot` 可装载"的存储半程（全程在设计稿 09 兑现）。

## 关键判断的取舍记录

1. **向量库选 Chroma 独立件，不选 pgvector**——卡 `m14` 选型记录点名官方件：Chroma 是嵌入式向量库的官方成熟件，`PersistentClient` 单机即用、compose 加一个 chroma 服务即成客户端/服务形态（两种构造都官方），本地开发环境 CPU 可跑、零额外运维面。生产替换路径一句话（卡面要求）：存储接缝收在 `upsert`/`query` 两函数，换 pgvector = 向量进 PG 列、检索 SQL 化，只重写 `vector_store.py` 内部，检索方与管道零改动。换边条件：报告元数据与向量需要随业务表同库同事务、备份运维要收敛进 PG 时，切 pgvector（回 00 号骨架登记只改 m14 卡落点，卡面接口不变）。
2. **BM25 用 rank_bm25 进程内 + 快照装载，不上 ES/OpenSearch**——报告库当前规模（万级块）下 BM25 毫秒级、零 JVM 运维面，与"官方件、CPU 可跑"的选型记录同源。代价是进程内索引重启即蒸发，快照往返因此升格为本设计稿一等公民（主干三）。换边条件：多实例要共享同一份索引、语料上亿、需要成熟中文分析器生态时，关键词路整体换 ES——`Hits` 形状不变、六函数接缝照旧，消费方零感知。
3. **快照走 m3 表（save/get 语义 + 契约待设计定形占位），不走 MinIO 桶**——两案都缺卡面签名，比差距：m3 路线差一处（Repository 无快照专属方法，但 `bm25_snapshots` 实体已在骨架与设计稿 04 占位、卡面依赖行只有 `m3`）；m5 路线差两处（m14 卡上没有 m5 依赖边 + 桶契约只有 reports/artifacts 两桶没有快照桶）。按"离卡面最近"取 m3，本节在伪代码中以"快照存取·save/get 语义"占位并注明**快照契约待设计定形**，不发明签名。换边条件：快照涨到百 MB 级或需要多版本/跨环境搬运时改走对象桶，届时回 00 号骨架登记一次扩卡（加依赖边 + 桶契约）。
4. **快照载荷存原料（token 序列），不 pickle 索引对象本体**——rank_bm25 官方没有持久化 API，直接 pickle `BM25Okapi` 实例依赖其私有属性布局（内部词频表/IDF 字典），跨版本脆弱且把派生物当真源。载荷改为 pickle dict 装 `chunk_ids + corpus_tokens`（原料），装载期用官方构造重建索引：`format_version` 头先验、重建走官方构造函数零私有依赖。付出：装载期一次 O(语料) 重建（当前规模毫秒级）。换边条件：语料大到重建耗时不可接受时，换原生支持持久化的倒排件（并入取舍 2 的换边）。

## 锚点对照精要

**RAG基础·稠密嵌入**（卡 `m14` 锚点 K-B 第一项）
要点：稠密嵌入把文本映进高维向量空间、语义相近则向量相近，常用余弦相似度度量"近"；BGE-M3 可同时输出稠密/稀疏/多向量三种表示，此处只用其稠密输出。落点：向量路存的就是这个稠密表示；我们集合用官方 l2 距离空间排序（经典叙述用余弦——距离与相似度单调等价但量纲不同，`score=1−distance` 的口径注释按 l2 如实写，不冒充余弦）。

**RAG基础·稀疏嵌入（TF-IDF→BM25）与倒排索引**（卡 `m14` 锚点 K-B 第一项）
要点：BM25 保留 IDF 对稀有词加权，加词频饱和与文档长度归一化（公式参数 k1、b；IDF=ln((N−df+0.5)/(df+0.5))）；倒排索引是"词→文档"的反向映射，稀疏检索强在关键词精确匹配、读不懂同义表达。落点：rank_bm25 官方默认 k1=1.5、b=0.75 与经典示例同参；倒排统计在 `BM25Okapi` 建构期一次算好；"读不懂同义词"正是主干四对照里关键词路的漏召面。

**RAG基础·混合检索三阶段**（卡 `m14` 锚点 K-B 第一项）
要点：典型混合检索流水线三阶段——并行检索（稠密/稀疏两引擎各召回）、结果融合（两路得分尺度与分布不同、不可直接比较，常用 RRF 只看排名，得分=Σ1/(k+rank)，k 常取 60）、神经重排序（跨编码器在融合候选池上精排）。落点：本节交付第一阶段的两只引擎与同形状 `Hits`；"得分不可直接比较"是主干四 `score` 口径注释的原文出处；融合（RRF）与精排归设计稿 10，本设计稿不写。

**docs/tech-stack/openai-embedding.md · bge-m3 稀疏表示与官方混合管线**（卡 `m14` 锚点第二项）
该文档：bge-m3 一次编码产 dense_vecs 与 lexical_weights（词项权重，类 BM25），官方给 `compute_lexical_matching_score` 算稀疏匹配分——与 BM25 的词项权重同构；官方推荐管线即 hybrid retrieval + re-ranking，工程落地点名 Vespa/Milvus。落点：我们用"bge-m3 稠密输出 + rank_bm25 分词倒排"实现同一管线形态（分词 BM25 与 lexical_weights 是两个稀疏口径，差异记为设计稿 09 素材，不进本层）；选型取 Chroma+rank_bm25 而非 Vespa/Milvus，按卡面"官方件、CPU 可跑"。

**Chroma/rank_bm25 选型事实（卡 `m14` 锚点第三句 + 依赖行）**
卡：向量库 Chroma（官方件，compose 增 chroma 服务），生产替换路径 pgvector 只讲不实现；Adapter 为 FakeIndex。落点：主干一两种客户端形态均为官方构造（`PersistentClient(path=...)` 落盘自装载 / `HttpClient(host, port)` 连 compose 服务）；rank_bm25 官方无持久化 API——快照义务由本层封装承担（取舍 4）；官方件两处已核对的硬事实：集合维度首笔固化 + `InvalidDimensionException`（捣乱 B）、`get_scores` 对 OOV 词贡献为零（主干二注释）。
