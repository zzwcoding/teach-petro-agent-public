> **红线声明**：本设计稿零真实可运行代码。全部代码块均为**伪代码**（块首标注"伪代码 — 文件:函数"或"伪代码（时序推演，非代码）"），公开签名取自模块卡 `m7` v3.1 扩容行（`TrustScore.rank(candidates, user) -> [scored]` 📊），函数体=输入输出契约+主干判断。
> **框架红线**（设计范围）：无点名框架——评分卡是**确定性加权**：权重写死在常量表、判据写死在判据表、三档打分，一个普通函数八次查表八次乘加一次排序，零模型调用、零训练、零分数回归（设计范围原话"确定性加权伪代码，不用 ML"）。八信号的方法论出处=演讲轮 2 场景 C（前沿升级方案报告 G4 行）；**权重数值是本项目的设计演绎**（演讲只给信号清单不给权重）——诚实声明逐信号在案（第 0 步表）。
> **接线边界**：本节活动范围只在 `m7` 新文件 `trust_score.py` + `retrieve_schema` 一处消费——`graph.py` 布线零改动（选表→生成仍是一条静态边）、State 字段名零改动（tables 格**内容**升级为带评分的候选，形状见主干三）；信号现算只经 `m20`/`m16`/`m3` 公开面（设计范围边界红线明文），三模块文件零触碰；评分卡是**排序器不是权限闸**——行列权限与新鲜度的拦人裁决仍归执行前校验链（设计稿 24），评分不代行任何闸的语义（取舍 5）。
> **stub 换真身声明**：无前稿替身——`TrustScore.rank` 为新增件本节即真身（纯内存现算）；卡面 Adapter **FakeText2SqlGraph** 照例登记，供后续设计稿走查指名注入固定候选轨迹，本设计稿不展开。
> **明确不讲的**（设计范围声明）：机器学习打分（按数据回归调权重——那是 m18 评估链出证据之后的事，设计范围明文不做）；信号落库（评分结果不建表不缓存，逐问现算——"不落库"是设计范围边界红线）；权限裁决与新鲜度**闸**（m17 已有：评分卡的策略/新鲜度是**排序信号**，只影响排序与标注，不做资格裁决）；水位登记与分层测试的动作本体（设计稿 34 已交付，本节只读其落库结果）；检索瀑布 S 级接线（设计稿 39/40——本节消费点在既有 `retrieve_schema`，瀑布升级时不回改本节，形状平移见后续衔接钩子）。

### 主干一：TrustScore.rank 本体——排序与 breakdown（W-F26-1 的调用路径本体）

```text
伪代码 — app/agents/text2sql/trust_score.py:TrustScore（m7；签名=卡 m7 v3.1 扩容行；纯内存现算，同步；零模型调用零落库）

_WEIGHTS = {有主:10, marts分层归属:25, Ontology归属域:20, 血缘:10,
            新鲜度:10, 策略:5, 使用热度:5, 质量体检:15}   # 和=100，写死不调参（取舍 1）
_FILTER_LINE = 60                     # 过滤线=就绪层基本盘 50 + 有主 10（第 0 步权重账）
_SIGNAL_ORDER = [S2, S3, S1, S4, S5, S8, S6, S7]   # 同分决胜序：重锚定信号优先——同输入永远同输出

class SignalScore:                    # 数据形状——单信号一行 breakdown（"得分+理由"是设计范围硬要求）
    信号: str                         # "marts 分层归属"
    权重: int                         # 25
    档位: 1 | 0.5 | 0                 # 三档——判据见第 0 步表，逐档可对账
    得分: float                       # 权重 × 档位
    理由: str                         # 一句话：判据事实 + 真源指针（"设计稿 36 井卡/计量点卡物理锚"）
    真源: str                         # "m16 resolve_entity 公开面" / "m20 models/marts 清单" / "m3 快照公开面"

class ScoredTable:                    # 数据形状——单表评分产物（装回 State.tables 的内容升级）
    table / ddl                       # 候选原样透传（生成节点消费的表结构不变）
    总分: float
    breakdown: [SignalScore]          # 八行——逐信号可查（W-F26-1"逐表八信号 breakdown 可查"）
    处置: "入列" | "降权标注" | "已过滤"
    处置理由: str                      # 过滤者必带（可解释含被过滤者，取舍 4）

class TrustScore:
    def rank(self, candidates, user) -> [scored]:
        # user 按卡面签名透传：本节只供策略信号读登记行比对，**不裁决权限**（权限闸在 m17，取舍 5）
        scored = [self._score_one(候选, user) for 候选 in candidates]      # 八信号逐个现算（主干二）
        # ── 硬边界先行：非就绪层剔除（S2=0 且判据"确证不在清单"）——不是低分是越界 ──
        #   （modules.md 边界规则表末行："问数消费非 marts 层表"禁止——评分卡是该边界的执行侧兑现）
        # ── 其余按总分降序稳定排序；同分按 _SIGNAL_ORDER 决胜序——同输入永远同输出（确定性）──
        # ── 低于 _FILTER_LINE 的就绪层表保留但 处置=降权标注（低可信警示随表结构进生成尾注）──
        # ── 全部被过滤 → 原样带回全列表并逐表附处置理由：宁可空手交代理由，不静默也不偷偷放行 ──
        # 异常去向（取舍 5）：单个信号源查询失败 → 该信号档位=0.5、理由="信号源不可达，按未知处理"
        #   ——降级不拦问：评分卡是排序器，信号源抖动最多退回次优顺序，不该打死问数主链；
        #   breakdown 理由如实写"不可达"，不静默不冒充（对照 m17 闸的 fail-closed：闸拒坏 SQL 不可执行）
        return 排序后的 [scored]

    def _score_one(self, 候选, user) -> ScoredTable:
        breakdown = [self._信号分(信号, 候选, user) for 信号 in _WEIGHTS]   # 八行，行行"得分+理由+真源"
        总分 = sum(行.得分 for 行 in breakdown)
        处置 = 判处置(总分, breakdown)          # 已过滤/降权标注/入列——判据见第 0 步权重账
        return ScoredTable(候选.table, 候选.ddl, 总分, breakdown, 处置, 处置理由)
```

**确定性在哪里、可解释在哪里**：权重是常量（改动=改代码走评审，不是调参）；档位判据是第 0 步表逐行写死的判据（每档对得上一个可查事实）；排序是纯比较（同分有决胜序）；breakdown 每行"得分+理由+真源"——任何一个排序结果都能被老王或审计员手工复算一遍。"排序可解释是底线"（设计范围原话）的兑现=**每张表的总分都能被第三者重算出来**。


## 关键判断的取舍记录

1. **权重写死不做 ML，排序可解释是底线**。备选：拿历史问数日志训练一个排序模型。否决理由：设计范围明文"不做 ML 打分"；更要害的是可解释性——权重回归出来的 0.137 讲不出"为什么"，老王问"为什么选这张表"就没有第二句话可答；确定性加权让每个总分可被第三者手工复算（主干一末段）。代价：权重是拍的（设计演绎，演讲只给清单不给权重）——换边条件：m18 评估链跑出真实分布数据后，按"评估失败案例里哪类信号漏报最多"的证据调权，调完写回常量表走评审——是**有证据地改常量**，不是上模型。
2. **marts 清单以常量登记+同步纪律，不给 m20 加"目录查询"新签名**。备选：给 m20 加 `MartsCatalog.list()` 公开接口让 rank 现查。否决理由：接口变更只能改卡（modules.md 头部纪律），且 m20 卡公开面已经够用——交付物清单（设计稿 32 第 0 步+设计稿 33 ModelSpec）就是真源；反手加接口是为消费方便宜改上游契约，边界纪律不许。代价：清单常量与交付物可能漂移——同步纪律随 m20 变更包走，漂移对账归设计稿 38 CI L2 引用一致收编（后续衔接钩子）。换边条件：模型物规模涨到手工同步出错——那时才是立目录接口的时机，带着 CI 对账数据去。
3. **归属域用"注记+公开面复核"两段式，不直读实体卡 YAML 也不碰内部锚索引**。备选一：m7 直读 ontology/*.yaml 的 physical_anchors；备选二：OntologyRegistry 内部 `_anchors` 倒排直接查。双双否决：m16 Seam 明文"m7 只认公开面，不读 YAML 细节"（modules.md 卡面原文），`_anchors` 是内部实现——两条都是边界规则表"m7 节点绕过 m16 公开面直连其内部实现"的禁止行。两段式的机制：归属注记随表结构文档离线装载（设计稿 14"离线一次性入库"同款占位），rank 持注记调 `resolve_entity` 公开签名复核 approved——"注记是线索、权威在域"（设计稿 39 回读权威源的同款哲学：显式锚定只给直达权不给免检权）。代价：注记与实体卡可能漂移——同归设计稿 38 CI L2 对账。换边条件：无（这是边界纪律的直接推论，不是偏好）。
4. **硬边界过滤而非纯排序，且被过滤者 breakdown 照出**。备选：八信号全加权、裸表低分排后面但保留——"让模型自己看着办"。否决理由：边界规则表末行"问数消费非 marts 层表"是**结构约束**不是偏好——staging/intermediate 是管道内部层（设计稿 32 主干四），把它们交进提示词本身就是违约，"排后面"是给违约留后门；而"宁可空手交代理由，不静默也不偷偷放行"的过滤纪律保证了可解释性覆盖被过滤者（走查推演 1 t2 裸表 breakdown 全文照出）。代价：全被过滤时这一问答不出——那是边界该有的样子（没有就绪层数据的问题本来就不该用裸表糊弄），空手时附逐表过滤理由交人工。换边条件：无（边界规则的执行侧没有换边）。
5. **评分卡是排序器不是闸：信号源异常降级不拦问，权限与新鲜度裁决一律不代行**。备选：把评分卡做成资格闸——低分表直接拒绝、缺过滤的表拒绝生成。否决理由：职责越位——资格裁决已有两道专职闸（只读/权限/新鲜度在 m17 五段，人工审批在设计稿 15），评分卡再加一道裁决就把"拦坏 SQL"与"排次优顺序"两种失败混在一个出口，容错语义打架：闸必须 fail-closed（不可执行的 SQL 宁可拦错），排序必须可降级（信号源抖动打死主链是自残）。本节的落法：信号异常 0.5 档+标注（走查推演 3），权限信号只读登记行影响排序、永不裁决（user 入参仅透传比对），S2 常量在内存保证硬边界判定恒可用。代价：低可信表仍会进提示词（带降权尾注）——那是排序器的本分，资格问题留给闸。换边条件：评估数据显示"低分表进提示词"本身成为主要错因——带着数据议评分卡升格，不是现在。
6. **使用热度只数成功快照、权重压到最低**。备选一：数全部历史查询频次（含失败）；备选二：干脆砍掉热度信号。否决：备选一正中演讲轮 2 的教训——"历史 SQL 频次高 ≠ 适合生产问数（高频常是底层明细大表）"，裸表 oil_production_daily 的热度第一恰是反例实录（走查推演 1）；备选二丢失真实信号面（v2 八信号逐条平移是设计范围要求）。落法：只数成功快照（失败查询不积热度）、权重 5 分垫底——热度为零丝毫无碍排序（fct 热度 0 分照样第一）。换边条件：就绪层模型物足够多、热度开始区分"就绪层内部谁更常用"时，权重可议升——仍走评审改常量。
